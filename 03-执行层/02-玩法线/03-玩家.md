# 玩家（SYS-PLAYER）

> 一句话：原站玩家从哪出生、长什么样、有什么动作状态、朝向和深度怎么算、沙滩怎么换装。本卡已定稿（`designed`），为 SYS-PLAYER 唯一正式主定义。

## 👀 先看这里（人话总结，给 Human）

下面全是给 AI 看的精确结论（FACT / UNKNOWN 那套术语）。你**不用啃术语**，看这段人话就够审了。

**这卡在说啥**：游戏里你操控的那个小人——他从哪来、长什么样、会做哪些动作。

**我查清的 6 件原站事实**（你审的就认这 6 条）：
1. **出生点**：(1088, 304)。
2. **深度是动态的**：`500 + y×0.1`——越往画面下方走，深度数字越大，被建筑遮挡得越正确（这是俯视角遮挡的标准手法）。
3. **外观**：48×48 的小人，一张精灵表切成 64 帧 = 8 个方向 × 每方向 8 帧走路动画，动画速度 10。
4. **空闲小动作**：30 秒不动就**坐下**（冒 Z 睡觉气泡）；8 秒不动就随机做小动作（吃饭 / 抓痒 / 系鞋带，三种里挑一个）。
5. **沙滩自动换装**：走到沙滩自动播"脱衣"动画（临时变成 64×64），换完变泳装；离开播"穿衣"换回来。换装过程中不能动。
6. **朝向**：默认朝南，平时记住最后走的方向；被怪物抓住时换成"被拎着"的贴图（64×64）。

**还有个澄清**：理解层卡写"8 方向动画（上/下/左/右）"，实际是**完整 8 方向**（含四个斜角），每个方向 8 帧。

## 1. 逆向结论（从 sample 读出来的事实）

### FACT（原站证实）

- 玩家类：`class extends Phaser.Physics.Arcade.Sprite`（压缩名 `$e`），双精灵结构——物理体 `sprite` 自身 `setVisible(false)` 不可见，显示由 `visualSprite`（`add.sprite`）负责。证据：`chunk-WMFY56ZM.js`（玩家类定义、构造）。
- 出生点：`createPlayer` 里 `new $e(this, 1088, 304)`，即 (1088, 304)。证据：`chunk-WMFY56ZM.js`（`createPlayer`）。
- 动态深度：`createPlayer` 里 `player.setDepth(500 + player.y * 0.1)`，深度随 y 变化；玩家类构造里的 `setDepth(600)` 只是初始值，会被此覆盖。证据：`chunk-WMFY56ZM.js`。
- 外观：spriteKey/texture = `player`，显示尺寸 48×48；精灵表 64 帧 = 8 方向 × 8 帧 walk，帧映射 east[0-7]/north-east[8-15]/north-west[16-23]/north[24-31]/south-east[32-39]/south-west[40-47]/south[48-55]/west[56-63]，idle 用第 48 帧（south 首帧）；`frameRate 10`（walk/idle 均默认 10）。证据：`chunk-WMFY56ZM.js`（`Ue`/`xe` 动画创建函数）。
- 动画状态机（字段与方法）：
  - 走路动画 `walk-{8方向}`（由 `updateMovement` 播放，见 SYS-MOVE）。
  - 空闲动画 3 种：`IDLE_ANIMATIONS = ["eating","scratching","tying-shoe"]`，随机选一个（排除上一个）。
  - 空闲触发阈值：`IDLE_TIME_FOR_SITTING = 30000ms`（30s）、`IDLE_TIME_FOR_EATING = 8000ms`（8s）。`preUpdate` 里按 `now - lastMovementTime` 判断：≥30s 坐下；≥8s 做吃饭/抓痒/系鞋带。证据：`chunk-WMFY56ZM.js`（`preUpdate`）。
  - 坐下：`playSittingAnimation`（`isSitting=true`，sleep 粒子 Z 跟随，`setPosition(x-12, y-5)`、`depth+1`）。站起：移动时 `standUp`（`pendingDirection` 记住待处理方向）。证据：`chunk-WMFY56ZM.js`。
- 朝向：`getFacingDirection()` 返回 `lastRequestedDirection || "south"`（默认朝南）；`_preserveFacingDirection`（保持朝向标志，可 get/set）。证据：`chunk-WMFY56ZM.js`。
- 换装（沙滩）：进沙滩 `setTexture("player-clothes-off")`、`setDisplaySize(64,64)`、播 `player-undressing` → `animationcomplete` → `setTexture("player-beach")`、`setDisplaySize(48,48)`、播 `player-beach-idle`；出沙滩反向播 `player-dressing` → `setTexture("player")`、播 `player-idle`。换装期间 `isChangingClothes=true` + `setVelocity(0,0)`（不能动），冷却 1s。尺寸常量 `originalDisplaySize={48,48}`、`clothesOffDisplaySize={64,64}`。证据：`chunk-WMFY56ZM.js`（沙滩换装触发块）。
- 被抓（怪物）：`setGrabbedByMonster(true)` → 停所有动画状态 + `visualSprite.setTexture("player-holding")` + `setDisplaySize(64,64)`；松开 → 恢复 `currentAnimPrefix`、48×48、播 idle。证据：`chunk-WMFY56ZM.js`（`setGrabbedByMonster`）。
- 控制启用：`setUseControls(e)` 设置 `useControls` + 注册键盘（cursors/wasdKeys），关闭时清理空闲气泡；`createPlayer` 初始 `setUseControls(false)`，开场火车动画完成（`isPlayerIntroComplete=true`）或传送完成才 `setUseControls(true)`。证据：`chunk-WMFY56ZM.js`（`setUseControls`、`createPlayer`、intro/teleport 回调）。

### INFERRED（推断）

- 双精灵（sprite 物理体 + visualSprite 显示）是为让"被抓/换装"时切换贴图而不动碰撞体。这是从结构推断，未做双设备实测。
- 玩家初始 `setUseControls(false)` 是为开场动画期间锁操作；开场结束才放行。推断自调用时序，未做帧级验证。

### UNKNOWN（还没弄清）

- 空闲对话（`idleTalkSequences`、`firstContactText`、`showIdleSpeechBubble`）完整内容与触发条件，归 SYS-INTERACT / SYS-ZONE，不在本卡。
- 怪物抓人的完整流程（`monsterEscapeHandler`、被抓挣脱）归 SYS-NPC / SYS-ENTITY，不在本卡。
- 传送特效粒子（理解层卡提到"传送时播粒子特效"）归 SYS-ZONE / SYS-FX，不在本卡。
- `_preserveFacingDirection` 的具体置位场景（哪些 tile / 事件要求保持朝向）未完全展开。

### DECISION（重构设计，非原站事实）

- 本卡已定稿为设计（`designed`）；完整玩家系统仍未授权。
- **当前重构深度决定**：玩家常态深度消费 SYS-LAYER 已接受的 `500 + (y + 24) * 0.1`；本卡上方 `500 + y*0.1` 继续保留为原站 FACT，不能把两者当成同一个口径。
- 实现 DECISION（`DEC-SYS-PLAYER-RUNTIME-001`，签字 `接受接受`，2026-08-21）：P1 只接入统一玩法控制门、8 秒随机 idle、30 秒 sitting、移动 stand-up、公开 idle/sitting 资源和安全降级；保留现有移动/碰撞/depth/摇杆。沙滩完整触发、怪物、传送、相机和内容线不在本项。

## 3. 怎么做

### 原站玩家流程（FACT，从 Bundle 读出）

```text
createPlayer（世界创建后）
  ├─ new 玩家类(1088, 304)     —— 出生点
  ├─ setUseControls(false)      —— 初始锁操作
  ├─ setDepth(500 + (y+24)*0.1) —— 重构常态深度（SYS-LAYER）
  └─ 注册 collider（SYS-MOVE 的 5 墙层）

开场火车动画完成 / 传送完成
  └─ setUseControls(true) + setJoystickVisible(true)  —— 放行

每帧 preUpdate
  ├─ updateMovement()           —— 走路 + 朝向（SYS-MOVE）
  └─ 空闲检测：
       ≥30s 不动 → 坐下（冒 Z）
       ≥8s 不动 → 吃饭/抓痒/系鞋带（三选一）

沙滩进出
  ├─ 进沙滩 → 脱衣动画（64×64）→ 泳装
  └─ 出沙滩 → 穿衣动画 → 恢复

被怪抓
  ├─ 抓 → holding 贴图（64×64）+ 停一切动画
  └─ 松 → 恢复 + idle
```

- 走路/朝向/碰撞细节见 SYS-MOVE；输入见 SYS-INPUT；本卡只管玩家的外观、状态机、出生与换装。

## 4. 失败怎么办

- 纹理缺失（动画创建前检查）：`if(!textures.exists(t)) console.warn(...)`，跳过该动画创建，不崩溃。证据：`chunk-WMFY56ZM.js`（`xe`/`Fi`/`Ue`）。
- 玩家无碰撞体：`console.warn("Player nemá inicializované telo fyziky.")` 并跳过碰撞体设置（见 SYS-MOVE）。证据：`chunk-WMFY56ZM.js`。
- 换装动画缺失：`once("animationcomplete")` 依赖动画存在；若动画未创建则该回调不触发、换装状态卡住——原站未显式兜底。证据：`chunk-WMFY56ZM.js`（换装块）。
- 无重试 / 降级；外观失败不阻断游戏启动。

## 5. 接口接口

- 入 ← SYS-INPUT：方向（键盘/摇杆）由 `updateMovement` 消费（见 SYS-INPUT/SYS-MOVE）。
- 入 ← SYS-MOVE：`body.blocked` 卡墙反馈，`walk-{方向}` 动画选择（见 SYS-MOVE）。
- 出 → SYS-MOVE / SYS-CAMERA：玩家位置 (x, y) 供碰撞与相机跟随。
- 出 → SYS-LAYER：重构常态深度 `500 + (y+24)*0.1` 参与遮挡排序；原站 FACT `500+y*0.1` 只作为行为证据保存。
- 与 SYS-MOVE / SYS-INPUT 重叠：玩家类同体持有 cursors/wasdKeys/joystickActive 并直接消费输入、执行移动，三者边界已在本卡与 SYS-MOVE/SYS-INPUT 分别登记，未拆独立模块。
- **DECISION（`DEC-MAP-GAMEPLAY-PARALLEL-DESIGN-001`）**：并行实施冻结“玩家位置快照”和“玩法控制门”两条语义接口。位置输出只提供只读世界坐标，不转移 Sprite/Body 所有权；控制禁用时必须立即停速、屏蔽并 reset 键盘/摇杆，恢复时才重新接受设备输入。真实 TypeScript 签名在 P1 实现授权时确定。
- **并行所有权**：玩法窗口只实现 `src/player/`、有界 Phaser 玩家适配器和对应测试；`CampusScene` 最终接线、共享 Smoke 与权威状态由 Main 在 integration 分支完成。

## 6. 怎样算做对

原站事实基准（来源：`chunk-WMFY56ZM.js`）：

- BASE-PLAYER-001：出生点 (1088, 304)、动态深度 `500 + y*0.1`，可复现。
- BASE-PLAYER-002：精灵表 64 帧（8 方向 × 8 帧）、frameRate 10、48×48，可复现。
- BASE-PLAYER-003：动画状态机（walk / 空闲 3 种 / 坐下 / 站起 / 换装 / 被抓）及阈值 30s/8s，可复现。
- BASE-PLAYER-004：控制启用时机（初始锁、开场介绍完成 / 传送完成才放行），可复现。

重构设计验收（本次不写码，仅作设计候选验收口径）：

1. 出生点和精灵表帧映射与上表一致；原站深度 FACT 与重构 SYS-LAYER 决定分别可追溯，不混成一个公式；
2. 状态机（走路/空闲/坐下/站起/换装/被抓）的状态与切换条件无遗漏、无歧义；
3. 换装、被抓的尺寸切换（48×48 ↔ 64×64）与冷却显式记录；
4. 失败路径显式记录（纹理缺失跳过、换装动画缺失无兜底），不静默吞错。

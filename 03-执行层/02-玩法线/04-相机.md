# 相机（SYS-CAMERA）

> 一句话：原站镜头怎么跟着玩家、看得见多大范围、缩不缩放，以及公开六点序列具有什么能力。六点序列与正常入口的触发关系尚未证明。

## 👀 先看这里（人话总结，给 Human）

下面全是给 AI 看的精确结论（FACT / UNKNOWN 那套术语）。你**不用啃术语**，看这段人话就够审了。

**这卡在说啥**：游戏镜头平时怎么跟着玩家，以及Bundle中六点相机序列的数据和能力边界。

**我查清的 5 件原站事实**（你审的就认这 5 条）：
1. **镜头紧贴玩家**：玩家一停镜头就停、一走镜头就贴住——**没有"慢慢追"的平滑**，是瞬间跟上（代码里 lerp=1 就是"硬贴"）。理解层卡之前写的"平滑跟随"是错的，要改。
2. **画面范围**：整张地图 2240×2240 像素（140 格 × 每格 16 像素），镜头不缩放（缩放=1），画面永远 1:1 不放大缩小。
3. **画面像素对齐**：开了 `roundPixels`（像素取整），防止画面抖动/模糊；物理模拟固定 30 帧/秒。
4. **六点相机序列**：Bundle存在6个预设点、总时长约111秒、沿途预加载和3秒回玩家能力；但当前证据没有证明普通Loading/Play入口必然完整播放它，真实触发链保持UNKNOWN。
5. **清晰度自适应**：有个 `nativeScale`（设备像素比，比如普通屏 1、高清屏 2），用来算模糊强度和分块渲染尺寸——**它是运行时设备值，不是写死的相机参数**。

**当前状态**：完整系统仍为`designed`；六点序列能力`19ac98b`和入口修复`798eda6`已完成有界技术验证，普通入口立即跟随、控制可用，仅test-hooks启动序列。
**仍未完成**：Loading/Play→Scene的真实短过渡、最终视觉构图和六点序列原站触发链。`DEC-THREE-BOARD-VISIBLE-WAVE-001`明确禁止把111秒序列接入正常入口。

## 1. 逆向结论（从 sample 读出来的事实）

### FACT（原站证实）

- 边界：`cameras.main.setBounds(0, 0, 2240, 2240)`，其中 2240 = 140 格 × 16px（`u=mapWidth*16`、`f=mapHeight*16`）；`physics.world.setBounds(0,0,2240,2240)` 同边界。证据：`chunk-WMFY56ZM.js`（`create` 相机块 @364238）。
- 缩放：`setZoom(1)`——全程无缩放（1:1）。证据：`chunk-WMFY56ZM.js`（@364398 开场、@415992 航拍结束回玩家）。
- 跟随：`startFollow(player, true, 1, 1)`——第 3/4 参 lerpX=lerpY=**1**，即**硬跟随（无平滑，逐帧瞬时贴住）**；`setFollowOffset(0,0)`（不偏移）、`setDeadzone(0,0)`（无死区）。证据：`chunk-WMFY56ZM.js`（@369624 主 gameplay、@397275 传送、@415935 航拍结束、@557606 怪物抓人）。
- 像素对齐：`roundPixels=true` + `setRoundPixels(true)`。证据：`chunk-WMFY56ZM.js`（@364230 附近）。
- 物理帧率：`physics.world.setFPS(30)` + `fixedDelta=true`（固定步长）。证据：`chunk-WMFY56ZM.js`（@364276）。
- 公开六点相机序列数据（`cameraSequence` 6 个点，`currentCameraSequenceIndex` 从 0 开始；用途/入口触发 UNKNOWN）：
  ```js
  cameraSequence = [
    {x:16*59,  y:16*58,  duration:0,     stayDuration:7000},   // (944, 928)  立即，停 7s
    {x:16*97,  y:16*76,  duration:15000, stayDuration:7000},   // (1552,1216) 飞 15s，停 7s
    {x:16*57,  y:16*71,  duration:15000, stayDuration:5000},   // (912, 1136) 飞 15s，停 5s
    {x:16*76,  y:16*41,  duration:15000, stayDuration:5000},   // (1216, 656) 飞 15s，停 5s
    {x:16*128, y:16*128, duration:15000, stayDuration:7000},   // (2048,2048) 飞 15s，停 7s
    {x:16*59,  y:16*58,  duration:15000, stayDuration:5000}    // (944, 928)  飞 15s，停 5s
  ]
  ```
  总时长 ≈ 111 秒（7+22+20+20+22+20）。证据：`chunk-WMFY56ZM.js`（@333500 字段声明）。
- 序列方法行为：`startCameraSequence()`里`stopFollow()`、隐藏摇杆、延迟100ms预载沿途chunk并创建lighting manager。该方法存在是FACT；谁在正常产品流程调用它仍UNKNOWN。证据：`chunk-WMFY56ZM.js`（@409312）。
- 航拍结束回玩家：`tweens.add({targets:cameras.main, scrollX, scrollY, duration:3000, ease:"Power2", onUpdate:loadChunksForCamera, onComplete:...})`，onComplete 里 `startFollow(player,true,1,1)` + `setFollowOffset(0,0)` + `setZoom(1)` + `setDeadzone(0,0)` + 装后处理管线（HeatHaze/Fire/Morph，strength 初始 0）。证据：`chunk-WMFY56ZM.js`（@415700–416050）。
- nativeScale：设备像素比（Angular 注入进 GameScene 构造 `nativeScale=e`），用于 `blur = 16*nativeScale`（后处理模糊）、`scaleFactor = 1/nativeScale`（摇杆/渲染缩放）、chunk 渲染分块尺寸 `Math.ceil(10*nativeScale)`。证据：`chunk-WMFY56ZM.js`（@335353 构造、@364638 blur、@377322 摇杆、@417109 分块、`updateNativeScale` @486416）。

### INFERRED（推断）

- 硬跟随（lerp=1）在 30 FPS 固定物理步长 + roundPixels 下，画面不会"抖"——是"逐帧贴住"而非平滑，手感靠像素取整兜底。这是从代码结构推断，未做双设备实测。
- `nativeScale` 的值来自运行时设备（DPR），并非相机卡需要写死的常量；重构时作为外部注入即可。这是从注入结构推断，未做多分辨率实测。

### UNKNOWN（还没弄清）

- 航拍 6 点之间的"飞"是 tween 还是逐帧 scrollX 移动，压缩代码未逐帧验证（仅确认了序列数据与结束 tween）；具体推进机制待实现前再核。
- `nativeScale` 的注入来源与取值（Angular provider 具体值）在本游戏 chunk 之外，未追。
- 传送时的相机过渡（@397275 后 333ms 的 tween 细节）归 SYS-ZONE / SYS-ENTITY，不在本卡展开。

### DECISION（重构设计，非原站事实）

- 本卡已定稿为设计（`designed`）。
- 实现 DECISION（`DEC-SYS-CAMERA-RUNTIME-001`，2026-08-21）：有界实现六点序列、控制锁、viewport预载、3秒回玩家、硬跟随恢复和降级，仅证明能力可运行。
- 入口 DECISION（`DEC-CAMERA-ENTRY-FLOW-FIX-001`，2026-08-21）：当前可玩场景不自动播放六点序列，立即硬跟随并允许控制。
- 证据纠正 DECISION（`DEC-THREE-BOARD-VISIBLE-WAVE-001`，2026-08-22）：不得把六点约111秒序列称为或接成正常入口；P1重新调查Loading/Play→Scene真实触发链和秒级过渡。

## 2. 数据与约定

### 相机基本参数

| 项 | 值 |
|---|---|
| 边界 setBounds | (0, 0, 2240, 2240) |
| 缩放 setZoom | 1（无缩放） |
| 跟随 startFollow | (player, true, 1, 1) —— lerp=1 硬跟随 |
| 跟随偏移 setFollowOffset | (0, 0) |
| 死区 setDeadzone | (0, 0) |
| roundPixels | true |
| 物理帧率 | 30 FPS（fixedDelta） |

### 六点相机序列数据（用途/入口触发 UNKNOWN）

| 点 | 目标 (x, y) | 飞过去耗时 | 停留 |
|---|---|---|---|
| 0 | (944, 928) | 0 ms | 7000 ms |
| 1 | (1552, 1216) | 15000 ms | 7000 ms |
| 2 | (912, 1136) | 15000 ms | 5000 ms |
| 3 | (1216, 656) | 15000 ms | 5000 ms |
| 4 | (2048, 2048) | 15000 ms | 7000 ms |
| 5 | (944, 928) | 15000 ms | 5000 ms |

总时长 ≈ 111 秒。坐标 = `16 * 格坐标`（16px/tile）。

### nativeScale（设备像素比）

| 项 | 用途 |
|---|---|
| blur 后处理 | `blur = 16 * nativeScale` |
| 摇杆/渲染缩放 | `scaleFactor = 1 / nativeScale` |
| chunk 渲染分块 | `Math.ceil(10 * nativeScale)` |

> nativeScale 是运行时注入的设备值，非相机写死参数。

  └─ 页面/Loading/Play通过什么真实条件调用该方法，以及正常入口是否使用其他短过渡

- 相机范围 → 分块加载链路见 SYS-CHUNK（Q-MAP-003 已关）；本卡只管镜头本身。

## 4. 失败怎么办

- 后处理管线（HeatHaze/Fire/Morph）安装失败：`try/catch` + `console.warn("... nedostupný:")`，strength 置 0 或置空，不影响游戏。证据：`chunk-WMFY56ZM.js`（@415950 附近）。
- 无重试 / 降级；相机初始化失败不单独兜底（依赖 Phaser 默认）。

## 5. 接口接口

- 入 ← SYS-PLAYER：玩家位置 (x, y) 供跟随（`startFollow(this.player, ...)`）。
- 出 → SYS-CHUNK：相机可见范围决定该加载哪几块（`preloadChunksForCameraSequence` / `loadChunksForCamera`，见 SYS-CHUNK）。
- 出 → SYS-INPUT：航拍期间 `toggleJoystick(false)` 隐藏摇杆、锁输入（见 SYS-INPUT）。
- 出 → SYS-LAYER / SYS-FX：后处理管线（HeatHaze/Fire/Morph）与灯光管理，具体实现归对应系统。
- **DECISION（`DEC-MAP-GAMEPLAY-PARALLEL-DESIGN-001`）**：相机只消费玩家只读位置、调用统一玩法控制门，并向 SYS-CHUNK 提交 viewport；目标集合公式、cache、请求和 Tilemap 生命周期仍归 SYS-CHUNK/SYS-WORLD。相机不得直接操作 chunk cache、renderer layer 或玩家键盘对象。
- **历史能力Gate**：M1/P1 integration和`impl/gameplay-serial`已验证六点默认数据可运行；当前production正常入口禁止触发该序列，只由显式test-hooks验证。

## 6. 怎样算做对

原站事实基准（来源：`chunk-WMFY56ZM.js`）：

- BASE-CAMERA-001：边界 setBounds(0,0,2240,2240)、setZoom(1) 无缩放，可复现。
- BASE-CAMERA-002：硬跟随 startFollow(player,true,1,1)（lerp=1）、offset(0,0)、deadzone(0,0)，可复现。
- BASE-CAMERA-003：roundPixels=true + 物理 30 FPS fixedDelta，可复现。
- BASE-CAMERA-004：六点序列数据与结束3秒回玩家能力可复现；它是否属于正常入口不在该基准中断言。

重构设计验收（本次不写码，仅作设计验收口径）：

1. 边界、缩放、跟随三参数与上表一致，不另立命名；
2. 跟随语义显式记录为"硬跟随 lerp=1"，不写成"平滑跟随"（纠正理解层卡）；
3. 航拍 6 点序列（坐标×耗时×停留）无遗漏、无歧义；
4. 失败路径显式记录（后处理 try/catch 降级），不静默吞错。

第二波 Main integration 预览（2026-08-21）：

- gameplay 结果 `19ac98b` 提供6点111秒状态机、3000ms Power2 返回、控制门、viewport、nativeScale、降级和 shutdown；Main 在 dynamic World ready 后接线，test-hooks 才显式缩时。
- viewport 只覆盖单一 pending 快照，由既有500ms目标循环消费；chunk Smoke 确认航拍预载24块、定位左下后仅新增 chunk20，异常/失败请求为0。
- 大范围装卸暴露 renderer 既有双重 `removeLayer`；依据 Phaser 3.90 vendor 默认 `destroy(true)` 修为先 remove 后 `destroy(false)`，回归测试及全部浏览器门禁 PASS。
- production 未等待完整114秒自然结束；默认时长由自动测试固定，最终硬件性能与真实后处理仍未验证。
- 后续 Human 产品验收否决了“进入可玩场景后自动航拍”；修复 `798eda6` 将默认入口改为直接跟随玩家，并把航拍限制到显式 test-hooks。typecheck、36文件/192测试、两种build、diff与Human实时预览通过。

# 输入（SYS-INPUT）

> 一句话：原站怎样把键盘（方向键 + WASD）和手机虚拟摇杆，统一翻译成「往哪个方向走」；速度多少；键盘和摇杆谁优先。本卡已定稿（`designed`），为 SYS-INPUT 唯一正式主定义。

## 👀 先看这里（人话总结，给 Human）

下面全是给 AI 看的精确结论（FACT / UNKNOWN 那套术语）。你**不用啃术语**，看这段人话就够审了。

**这卡在说啥**：原站怎么「听懂」你的操作——键盘（方向键 + WASD）和手机摇杆，都翻译成「往哪个方向走、走多快」。

**我查清的 4 件原站事实**（你审的就认这 4 条）：
1. **键盘两套键**：方向键和 WASD 是**同一套逻辑**，按哪个都行，直接合并（`左键 || A 键`）。
2. **手机摇杆**：用第三方插件 rexVirtualJoystick；参数是半径 15、底座直径 60、摇杆头直径 30、固定摇杆、放在屏幕右下角。
3. **速度统一**：不管键盘还是摇杆，走路速度都是 **150**；斜着走是 150×0.707 ≈ **106**。
4. **谁优先**：摇杆一动，键盘就失效；摇杆松开，键盘恢复。摇杆只在手机/平板生效，桌面隐藏。

**还有个纠正**：我之前理解层写「手机多指跟踪（touch.identifier）」，查下来**原站实际是「只认第一个手指」**，第二个手指被忽略。这条已改正。

**还有没彻底搞清（标 UNKNOWN，不是错）**：
- 摇杆灵敏度阈值（0.3 / 0.5）的精确单位还没 100% 定死。
- 键盘按住不松的「连发」行为，还没做行为验证。

**当前状态**：已定稿（📐 画好图纸，2026-08-15 Human 签字「通过」）。
**下一步**：写正式代码要你**另外单独授权**（实现授权 ≠ 这次设计定稿）。

## 1. 逆向结论（从 sample 读出来的事实）

### FACT（原站证实）

- 键盘映射：方向键（`createCursorKeys()` 的 up/down/left/right）与 WASD（`addKey(KeyCodes.W/A/S/D)`）两套键并存，合并成同一逻辑：`cursors.left.isDown || wasdKeys.A.isDown`（四个方向同理）。证据：`chunk-WMFY56ZM.js`（`setUseControls`、`updateMovement`）。
- 键盘归一化：8 方向判定，优先级 上 > 下 > 左 > 右（if/else if 链）；单轴速度 150、对角 150×0.707≈106；方向字符串 north/north-east/east/south-east/south/south-west/west/north-west 用于选择 `walk-{方向}` 动画。证据：`chunk-WMFY56ZM.js`（`updateMovement`）。
- 摇杆插件：rexVirtualJoystick 以全局插件注册（`plugins.global [{key:"rexVirtualJoystick", start:true}]`）；实现为 VirtualJoyStick 容器 + TouchCursor 指针跟踪，`forceX = end.x - start.x`（手指相对摇杆中心的像素偏移）、`force = 距离(start,end)`。证据：`main-RV3Z53H4.js`、`chunk-VANY4YOC.js`。
- 摇杆参数（`createJoystick`）：`radius` tablet 12 / 其他 15；base 直径 tablet 48 / 其他 60；thumb 直径 tablet 24 / 其他 30；`fixed:true`（固定摇杆不跟随手指）；插件默认 `forceMin=16`（距离死区）。位置：桌面居中底部（`width/2, height-50`），tablet/mobile 右下角（`width-50, height-50`）。证据：`chunk-WMFY56ZM.js`（`createJoystick`）、`chunk-VANY4YOC.js`（TouchCursor `forceMin`）。
- 摇杆归一化（`setJoystickControls`）：只在非桌面（`device.os.desktop` 为假）处理。主轴判定 `|fx|/|fy| > 1.5`（或反之）→ 单轴方向；单轴阈值 0.3、对角阈值 0.5；量化成 8 方向 (dx,dy)∈{-1,0,1}²；速度 150、对角 106。证据：`chunk-WMFY56ZM.js`（`setJoystickControls`）。
- 摇杆/键盘优先级：`updateMovement` 首行 `if(!this.cursors || this.joystickActive) return`——摇杆激活时键盘移动被跳过；`joystickActive` 在摇杆触发移动时置 true、摇杆无输入（回到中心/松手）时置 false 并 `setVelocity(0,0)`。证据：`chunk-WMFY56ZM.js`。
- 摇杆创建时机：无条件 `createJoystick()` + `player.setJoystickControls(joystick)`，随后桌面设备 `toggleJoystick(false)` 隐藏摇杆；`setJoystickControls` 内部桌面设备直接 `return` 不处理。证据：`chunk-WMFY56ZM.js`（`playerCreated` 事件处理、`setJoystickControls`）。
- 单指跟踪（非多指）：TouchCursor 用 `this.pointer === t` 锁定第一个 pointer 对象；`onKeyDownStart` 在 `this.pointer !== void 0` 时忽略后续 pointer，即第二个手指不接管摇杆。证据：`chunk-VANY4YOC.js`（`onKeyDownStart`/`onKeyDown`）。
- 失败/占位：插件加载失败只 `console.error("⚠ rexVirtualJoystick plugin sa nepodarilo načítať alebo neobsahuje metódu add!")` 并 return；`joystick-base`/`joystick-thumb` 纹理缺失时 `console.warn` 并用 `add.circle` 圆形占位。证据：`chunk-WMFY56ZM.js`（`createJoystick`）。

### INFERRED（推断）

- 键盘在移动端同样注册（`setUseControls` 无条件 `createCursorKeys`），但移动端用户以摇杆为主，二者并存时摇杆优先（由 `joystickActive` 标志保证）。这是从代码结构推断，未做双设备实测。
- 摇杆阈值 0.3/0.5 直接作用在 `forceX/forceY` 像素值上，相对 radius=15 极灵敏（手指微动即触发），属原站实际行为；「为何设这么低」为推断。

### UNKNOWN（还没弄清）

- 摇杆阈值单位：`forceMin=16`（像素死区）与归一化阈值 0.3/0.5（`|forceX|` 直接比较）量级差异大，两者关系未完全理清——`forceX` 是否在某处被归一化、`radius`/`forceMin`/阈值三者的精确配合，需对照 rexVirtualJoystick 原版或做行为采样确认。
- 键盘长按的连发/重复行为（Phaser `isDown` 每帧持续为真，但具体「按下→移动→松开停」的帧级时序）未做行为验证。
- 特殊输入（`monsterEscapeHandler` 被怪物抓住时按方向键挣脱、菜单点击传送）是否归 SYS-INPUT 范围，本次未展开。

### DECISION（重构设计，非原站事实）

- 本卡已定稿为设计（`designed`），暂未提出实现 DECISION；写正式 `src/` 时需独立授权并补实现 DECISION。

## 2. 数据与约定

### 键位 → 方向

| 键位 | 合并逻辑 | 方向 |
|---|---|---|
| 左 ← / A | `cursors.left.isDown \|\| wasdKeys.A.isDown` | west |
| 右 → / D | `cursors.right.isDown \|\| wasdKeys.D.isDown` | east |
| 上 ↑ / W | `cursors.up.isDown \|\| wasdKeys.W.isDown` | north |
| 下 ↓ / S | `cursors.down.isDown \|\| wasdKeys.S.isDown` | south |

### 摇杆参数（createJoystick）

| 项 | tablet | 其他 |
|---|---|---|
| radius | 12 | 15 |
| base 直径 | 48 | 60 |
| thumb 直径 | 24 | 30 |
| fixed | true | true |
| forceMin（插件默认） | 16 | 16 |
| 位置 | 右下角 (width-50, height-50) | 桌面居中底部 (width/2, height-50)，移动端右下角 |

### 速度与方向

- 单轴速度 150；对角速度 150×0.707≈106（8 方向向量模长归一）。
- 8 方向字符串：north / north-east / east / south-east / south / south-west / west / north-west，对应 `walk-{方向}` 动画。

## 3. 怎么做

### 原站输入流程（FACT，从 Bundle 读出）

```text
玩家创建（playerCreated）
  ├─ createJoystick()：无条件创建 rexVirtualJoystick（radius 15 / 固定 / 右下角）
  ├─ player.setJoystickControls(joystick)：每帧 update 读摇杆 forceX/forceY
  └─ 桌面设备 → toggleJoystick(false) 隐藏摇杆

每帧移动（两类，二选一）：
  A. 键盘 updateMovement()（摇杆未激活 joystickActive=false 时）
       读 cursors + wasdKeys → 8 方向 → setVelocity(150 / 106)
  B. 摇杆 setJoystickControls 回调（非桌面设备）
       读 forceX/forceY → 主轴判定(1.5) + 阈值(0.3/0.5) → 8 方向 → setVelocity(150 / 106)
       joystickActive 置 true（键盘让位）；摇杆回中 → joystickActive 置 false + 停
```

- 键盘与摇杆共享同一套「8 方向 → 速度 → walk 动画」的尾段，只在上游「读输入」处不同。
- 输入只产出方向（north/east/... 与 dx/dy），不直接碰碰撞；碰撞由 SYS-MOVE 的 `body.blocked` 反馈（walk 动画选择时读取 blocked 判断是否卡墙）。

## 4. 失败怎么办

- 摇杆插件加载失败：`console.error` 斯洛伐克语提示 + `return`（不创建摇杆，游戏继续，仅无触屏摇杆）。证据：`chunk-WMFY56ZM.js`。
- 摇杆纹理缺失：`console.warn` + 用圆形 `add.circle` 占位，不中断。证据：`chunk-WMFY56ZM.js`。
- 无重试 / 降级 / 默认输入替代；桌面设备不依赖摇杆（走键盘）。
- 输入接口：键盘 / 摇杆归一成方向（原站事实已定稿，见 §1；重构约定留待实现授权时再定 DECISION）。

## 5. 接口接口

- 出 → SYS-MOVE：方向向量（dx, dy）+ 方向字符串（north/east/...），移动系统据此 `setVelocity`；精确格式待定稿。
- 入 ← 硬件事件（键盘 `keydown` / 触摸 pointer）；摇杆插件 rexVirtualJoystick。
- 与 SYS-PLAYER 重叠：玩家类同时持有 cursors/wasdKeys/joystickActive 并直接消费输入，输入与玩家边界待定稿时明确（原站未拆独立输入模块）。
- 输入 → 移动的接口在 `02-接口层/API契约表.md` 中当前未单列；本卡已定稿原站事实，重构约定留待实现授权。

## 6. 怎样算做对

原站事实基准（来源：`chunk-WMFY56ZM.js`、`chunk-VANY4YOC.js`、`main-RV3Z53H4.js`）：

- BASE-INPUT-001：键盘映射可复现——方向键 + WASD 合并成同一 8 方向逻辑。
- BASE-INPUT-002：摇杆可复现——rexVirtualJoystick，radius 15 / base 60 / thumb 30 / fixed，移动端右下角，单指跟踪。
- BASE-INPUT-003：归一化可复现——8 方向量化，速度 150 / 对角 106，主轴判定 1.5，阈值 0.3 / 0.5。
- BASE-INPUT-004：优先级可复现——摇杆激活时键盘失效，摇杆只在非桌面处理。

重构设计验收（本次不写码，仅作设计候选验收口径，待定稿后细化）：

1. 键位与摇杆参数与上表一致，不另立命名；
2. 归一化逻辑能从键位/force 推导出唯一 8 方向与速度，无遗漏或歧义；
3. 失败路径显式记录且不静默吞错（原站插件失败只打日志，重构是否加降级属 DECISION，待 Human 定）；
4. 阈值单位未证实项标 UNKNOWN，不把「0.3/0.5 像素」夸大为已确认语义。

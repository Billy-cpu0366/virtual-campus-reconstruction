# 移动与碰撞（SYS-MOVE）

> 一句话：原站玩家怎么走路、撞墙怎么停、碰撞数据藏哪。本卡已定稿（`designed`），为 SYS-MOVE 唯一正式主定义。

## 👀 先看这里（人话总结，给 Human）

下面全是给 AI 看的精确结论（FACT / UNKNOWN 那套术语）。你**不用啃术语**，看这段人话就够审了。

**这卡在说啥**：玩家接到输入给的方向后，怎么"走起来"，撞到墙怎么停下。

**我查清的 5 件原站事实**（你审的就认这 5 条）：
1. **速度**：走路速度 150，斜着走 106（上一张输入卡已经查过，这里直接沿用）。
2. **玩家的"身体"很小**：屏幕上玩家是 48×48 的图，但真正撞墙的"碰撞块"只有 **20×8 的一个小扁条**，贴在脚底。所以头能跟墙、屋檐重叠，只有脚被挡住——俯视角 RPG 的经典做法。
3. **墙是隐形的**：玩家撞的墙层其实看不见（`setVisible(false)`），你看到的墙是另一套"视觉层"画的。碰撞墙层分 5 个：1 个主墙层 + 4 个桥的上下墙层。
4. **撞墙就"定住"**：脚被挡住时，走路动画停住、换成第一帧的静止贴图，不会原地踏步。
5. **分轴不是手写的**：斜着走不卡墙缝，靠的是 Phaser 物理引擎自带的"先挪横再挪竖"分轴碰撞，原站没自己写这段。

**还有个纠正**：之前理解层写"碰撞数据离线预提取成 walls-layer.json（0/1 矩阵）"，查下来**这个 walls-layer.json 不是给玩家撞墙用的**，而是给 **NPC 寻路**用的离线网格（0=能走、1=墙）。玩家撞墙用的是 tilemap 里的 walls 层（存的是贴图编号，不是 0/1）。

**当前状态**：设计已定稿；确定性 CORE 已实现并通过测试；Human 已于 2026-08-20 授权 `WI-SYS-MOVE-WORLD-COLLISION-001` 进行墙体/桥真实碰撞集成。
**本次范围**：玩家 Arcade Body、walls 与四个 bridge wall 碰撞层、`body.blocked` 撞墙反馈和 chunk 装卸后的碰撞清理；桥状态来源不足时保持 UNKNOWN。
**下一步**：先完成桥状态来源调查，再实现和验证；不扩展手机摇杆、NPC、完整13层或其他玩法。

## 1. 逆向结论（从 sample 读出来的事实）

### FACT（原站证实）

- 移动速度：单轴 150、对角 150×0.707≈106（`setVelocityX/Y`）。与 SYS-INPUT 一致，这里只引用不重复定义。证据：`chunk-WMFY56ZM.js`（`updateMovement`）。
- 移动由 `updateMovement()` 每帧调用（`preUpdate` 里 `this.updateMovement()`）：先 `setVelocity(0,0)` 归零，再按方向 `setVelocityX/Y`。只产出速度，不手写碰撞。证据：`chunk-WMFY56ZM.js`（`preUpdate`、`updateMovement`）。
- 玩家碰撞体（脚部小扁块）：`setCollideWorldBounds(true)`；`this.body.setSize(20, 8)`、`this.body.setOffset((48-20)/2=14, 48-8-4=36)`；`setDrag(300,300)`、`setMaxVelocity(200,200)`；`setDisplaySize(48,48)`。碰撞体 20×8 贴精灵底部（脚），头部可重叠。证据：`chunk-WMFY56ZM.js`（玩家构造）。
- 碰撞墙层（5 个）：`this.wallLayer = tilemap.createBlankLayer("walls", collisionsTileset)`，`setVisible(false)`（隐形）、depth 550；`bridge1_down_wall`/`bridge1_up_wall`/`bridge2_down_wall`/`bridge2_up_wall` 四层，`setAlpha(0)`、depth 3500。证据：`chunk-WMFY56ZM.js`（`createBlankLayer` 块）。
- 碰撞注册：`this.physics.add.collider(this.player, this.wallLayer)` + 四个桥墙层各自 `collider(player, bridgeXxxWallLayer)`。碰撞交给 Phaser Arcade 引擎。证据：`chunk-WMFY56ZM.js`（`playerCreated` 前）。
- 分轴碰撞：原站**无手写分轴**代码；`collider` 内部由 Arcade 物理引擎先处理 x 轴再 y 轴（引擎内置分轴，天然避免斜着卡墙）。证据：`chunk-WMFY56ZM.js` 全文无逐轴位移/逐轴碰撞判定。
- 撞墙反馈：`updateMovement` 里读 `this.body?.blocked`，按方向 switch 判断卡墙（north→up、south→down、east→right、west→left，对角→两个方向与）；卡墙则 `anims.stop()` + 显示该方向 walk 动画第一帧静态贴图，不卡则播放 walk 动画。证据：`chunk-WMFY56ZM.js`（`updateMovement` 尾部）。
- NPC 寻路碰撞数据：`walls-layer.json` = `{width:140, height:140, grid:140×140}`，grid 为 0/1 矩阵（0=可走 12121 格、1=墙 7479 格），16px 一格，行优先 `grid[y][x]`。消费方是 NPC 寻路（NpcGhost、Rats 用 `cache.json.get("walls-layer")` 后 `grid[y][x]===0` 判可走），不是玩家碰撞。证据：`assets/maps/walls-layer.json`、`chunk-WMFY56ZM.js`（`NpcGhost`、`Rats.isWalkable/isTileWalkable`）。

### INFERRED（推断）

- `walls-layer.json` 是从 tilemap `walls` 层（25 个 chunk 拼接 140×140）预提取出的 0/1 简化网格，供 NPC 寻路快速查表、避免每帧遍历 tilemap。这是从「walls 层存 GID、walls-layer.json 存 0/1、二者尺寸同为 140×140」推出的关系，未直接看到生成代码。
- `setMaxVelocity(200,200)` 大于实际速度 150，属上限兜底而非主动限速；drag 300 用于松手后减速。这是从数值关系推断，未做行为采样。

### UNKNOWN（还没弄清）

- 桥墙层（bridge1/2 up/down）的碰撞切换完整逻辑归 SYS-LAYER（`setCollisionByExclusion([-1], true/false)`），SYS-MOVE 只登记「玩家 collide 这 4 层」，切换时序不在本卡。
- 玩家出生点、初始位置、朝向归 SYS-PLAYER，不在本卡。
- 撞墙时的精确停靠位置（碰撞体贴墙的像素级行为）未做帧级采样。

### DECISION（重构设计，非原站事实）

- 本卡设计授权仍为 `DEC-SYS-MOVE-CORE-001`；运行时集成另由 `DEC-SYS-MOVE-WORLD-COLLISION-001` 授权，主责 SYS-MOVE，碰撞层和世界生命周期分别依赖 SYS-LAYER/SYS-WORLD/SYS-CHUNK。

## 3. 怎么做

### 原站移动/碰撞流程（FACT，从 Bundle 读出）

```text
每帧 preUpdate
  └─ updateMovement()
       ├─ 无输入/被怪抓/换装/介绍未完 → setVelocity(0,0) return
       ├─ 读方向 → setVelocityX/Y(±150 或 ±106)
       └─ 选动画：读 body.blocked
             ├─ 没卡墙 → play("walk-{方向}")
             └─ 卡墙 → anims.stop() + 显示 walk 第一帧静态贴图

碰撞（每帧，Arcade 物理引擎）
  └─ collider(player, wallLayer + 4 桥墙层)
       └─ 引擎内置分轴：先 x 后 y，逐轴检测并回推
             └─ 撞墙 → body.blocked.{up/down/left/right} = true
```

- 移动只产出速度；碰撞完全交给 `physics.add.collider`（Arcade 引擎）。
- `body.blocked` 是引擎每帧碰撞后更新的标志，供动画选择读。

## 4. 失败怎么办

- 玩家无碰撞体（`body` 为空）：`console.warn("Player nemá inicializované telo fyziky.")`（斯洛伐克语「玩家没有初始化物理身体」），跳过碰撞体设置。证据：`chunk-WMFY56ZM.js`。
- walls 层缺失（`collisionsTileset` 为空）：`if(this.collisionsTileset){...}` 整个墙层创建块跳过，玩家无墙可撞（可自由移动）。证据：`chunk-WMFY56ZM.js`。
- `walls-layer.json` 未加载：`cache.json.get("walls-layer")` 返回空时，NpcGhost 打 `console.warn("[NpcGhost] walls-layer not found in cache!")`，Rats 静默跳过网格（`isWalkable` 返回 true 全部可走）。证据：`chunk-WMFY56ZM.js`。
- 无重试/降级；碰撞失败不阻断游戏启动。

## 5. 接口接口

- 入 ← SYS-INPUT：方向字符串（north/east/...）由 `updateMovement` 消费，产出 `setVelocity`。
- 碰撞 → SYS-LAYER / SYS-CHUNK：`wallLayer`（walls 层）、4 桥墙层由地图/图层系统创建并交给本卡 collide；本卡只登记 collide 关系，不拥有墙层数据。
- NPC 寻路 → 地图：`walls-layer.json` 的 `grid[y][x]` 是「这格能走吗」的**真正消费方**（`0=可走`），见 `02-接口层/API契约表.md` 已定死接口「移动→地图：这格能走吗 (x,y)→true/false」。
- 出 → SYS-PLAYER：`body.blocked`、`lastRequestedDirection` 供动画/朝向使用（玩家类与移动同体，边界待 SYS-PLAYER 定稿时明确）。

## 6. 怎样算做对

原站事实基准（来源：`chunk-WMFY56ZM.js`、`assets/maps/walls-layer.json`、`assets/maps/chunks/chunk0.json`）：

- BASE-COLLISION-001：玩家碰撞体 20×8、offset(14,36) 贴脚底，可复现。
- BASE-COLLISION-002：玩家 collide wallLayer（隐形 walls 层）+ 4 桥墙层，可复现。
- BASE-COLLISION-003：walls-layer.json 为 140×140 的 0/1 网格、0=可走、供 NPC 寻路，可复现。
- BASE-COLLISION-004：分轴靠 Arcade collider（非手写），卡墙 `body.blocked` 停动画，可复现。

重构设计验收与本次集成口径：

1. 碰撞体尺寸/偏移、墙层清单与上表一致，不另立命名；
2. 「玩家物理碰撞」与「NPC 寻路查表」两条路径分清，不把 walls-layer.json 误当玩家碰撞数据；
3. 分轴明确为引擎行为，不手写重复的逐轴碰撞；
4. 失败路径显式记录（墙层缺失/碰撞体缺失），不静默吞错。

# 游戏 UI（SYS-GAME-UI）

> 一句话：把内容作为 DOM overlay 显示在 Phaser canvas 上方，负责可见性、pointer、滚动、移动端尺寸和 DOM 清理，但不拥有 marker/visited/manual-close 业务状态。本卡是 Main 复核后的正式设计主定义。

## 👀 先看这里（人话总结）

- 原站游戏画面在 canvas，弹窗/backdrop/HUD 在同一 game container 的 DOM 子树里，不是 Phaser display object。
- Game UI 只负责“怎么显示”和“用户点了关闭”；何时打开、关闭后何时能再开归 SYS-INTERACT。
- 当前重构采用一个可复用 DOM modal shell；普通内容不显示全局 backdrop，memo 内容显示 backdrop。这个结构是重构 DECISION，不冒充原站11个预置 modal 的源码结构。
- 键盘 Escape、focus trap、图片失败和原站完整 teardown 仍为 UNKNOWN；第一版不宣称这些 parity 已完成。

**当前状态**：设计已在 `DEC-CONTENT-FOUNDATION-DESIGN-001` 预授权范围内由 Main 定稿；P4 B窗口只实现独立 UI core/adapter，入口和 scene 接线归 Main。

## 1. 逆向结论（从 sample 读出来的事实）

### FACT

- `main#main-content.game-container` 内包含 Phaser canvas 所在 wrapper 子树、modal backdrop 和多个 modal 子树；它们属于同一容器下的兄弟子树，不是 canvas 与 modal 必然直接兄弟。
- Phaser config 的 `parent` 指向 game container；Angular template/handlers 拥有 modal、close button、backdrop 和 HUD DOM，Phaser scene 通过 `window.showModalWithBackdrop` / `hideModalWithBackdrop` / `closeMarker` bridge 访问。
- backdrop 默认不可见且不接收 pointer，visible 时 `z-index:9998`；modal visible 时 `z-index:9999`、`pointer-events:auto`、`overflow:auto`。根 `html/body` 禁止页面滚动，内容在 modal 内滚动。
- `showModal(id)` 首次 hidden→visible 时把 `scrollTop` 归零；重复 show 已可见 modal 时不归零。close button/backdrop 有 Angular click handler。
- 移动端使用 CSS `100dvh` 及 fallback；resize、orientationchange、visualViewport resize 和 `innerHeight` 变化会更新可见 modal/backdrop 高度。
- 原站 modal 显示时隐藏 speech bubble、content marker 和 joystick；这不是“完整玩家控制已锁”的直接证据。

证据：`index.html` lines 310–327、1337–1499；`styles-DVTBSD34.css` byte 1720–3783、60142、79920；`main-RV3Z53H4.js` byte 116635–117605、118833–119700、123282–125034、155784、170534–170672；`chunk-WMFY56ZM.js` byte 88787–89511、408830–409190。

### INFERRED

- 最小重构边界应保留 DOM adapter 与 Phaser scene 分离，不把作品内容重画成 Phaser text/shape。
- CSS 相同 z-index 不足以单独证明 mobile quick action 与 modal 的最终遮挡，必须由 DOM/browser 检查。

### UNKNOWN

- 原站 Escape 关闭、初始 focus、focus trap/return、Tab 顺序。
- 图片失败、空 payload、多个 modal 的正式产品语义。
- resize polling/listener、window bridge 和 modal DOM 在 Angular/scene shutdown 时的完整清理。
- 普通 modal、memo modal、big-map local backdrop 的所有分支细节；本卡只冻结本轮11个 Zone 内容策略。

### DECISION

- 当前重构使用一个 generic DOM modal shell，而不是复制11个静态 modal；内容 resolver 决定 payload，B 不从 menuId 猜正文。
- 普通 `about/cv/projects/contact/tech` 使用 `backdrop:none`；`memo1`–`memo6` 使用 `backdrop:global`。`big-map`/`under-hood` 不在本次接口。
- 第一版保留 close button/backdrop pointer 行为；不实现或宣称 Escape/focus-trap parity。close button 保留 `aria-label`，后续可独立改善 accessibility。

## 2. 数据与约定

### GameUiContentPayload

| 字段 | 语义 |
|---|---|
| `menuId` | 11个 `ContentMenuId` 之一 |
| `residenceId` | Interact传入的当前驻留身份；UI原样保留并回传，不解释业务语义 |
| `title` | 证据支持的显示标题 |
| `body` | 只读文本段落数组；本轮不支持任意 HTML |
| `presentation.backdrop` | `none` 或 `global` |

Interact 把 payload 当 opaque 数据；内容文案来源归 `04-内容层/` 和 Main resolver。

### 结果

- `show`：`shown | already-visible | missing-target | invalid-payload | destroyed`。
- `hide`：`hidden | already-hidden | target-mismatch | destroyed`。
- `UserCloseEvent`：`menuId` + `residenceId` + `source: close-button | backdrop`。

### DOM 约定

- Main 在 `index.html` 提供唯一 `#game-ui-root`；B runtime 在该 root 内拥有 backdrop、modal、title、body 和 close button。
- B 不拥有 canvas、Phaser scene、marker、玩家或控制门。
- modal 全局层级高于 backdrop；hidden 时不接收 pointer；visible 时 modal 自己滚动。

## 3. 怎么做

1. `DomGameUiRuntime` 构造时绑定 root、close、backdrop、resize/orientation/visualViewport listener；构造失败返回受控错误，不污染 canvas。
2. `show(request)` 先验证 payload、residenceId 和目标 root；验证失败保持当前 modal 不变。
3. hidden→visible 时写安全 text content、设置 backdrop policy、归零 scrollTop；相同 `menuId+residenceId` 已 visible 返回 already-visible 且保留 scrollTop。
4. 不同 identity show 采用原子替换：所有新数据验证完毕后一次更新 DOM；失败保留旧内容。
5. close button/backdrop 从当前 DOM state 读取 `menuId+residenceId`，只发一次 `UserCloseEvent`；不直接决定 manual-close、visited 或控制门。Interact 核对仍为active后调用 programmatic `hide`。
6. `hide` 只改变呈现，不发 user-close；清 visible/backdrop/当前 menu 和 payload 引用。
7. resize 只更新 active UI 的 viewport height，不改变 Phaser world/camera；连续更新可取消/合并。
8. `destroy()` 先阻止新事件，再解绑所有 listener/timer，隐藏并清 DOM 引用；幂等。

## 4. 失败怎么办

- 未知 menuId、空 title、非法 body：返回 `invalid-payload`，不替换当前 UI，不发 close。
- root/target 缺失：返回 `missing-target`；不动态猜 DOM 结构，不 acquire 控制门。
- 图片不在本轮 payload；不请求私有资源、不实现无证据 retry。
- resize/destroy 竞态：destroyed guard 阻止晚到回写。
- listener 移除失败：继续其他清理并保留首个诊断；不得生成业务 close。
- CSS/DOM 失败不能让 A 假定 show 成功；所有结果必须同步可观察。

## 5. 接口接口

### SYS-INTERACT → SYS-GAME-UI

```text
show({ menuId, residenceId, payload, presentation }) -> ShowResult
hide({ menuId, residenceId, reason }) -> HideResult
destroy()
```

- Caller 明确是 SYS-INTERACT；SYS-ZONE 不直连 UI。
- `show` 原子替换；`hide` 是 programmatic 命令，不发用户事件。

### SYS-GAME-UI → SYS-INTERACT

```text
UserCloseEvent { menuId, residenceId, source: close-button | backdrop }
subscribeUserClose(handler) -> unsubscribe
```

- B 只报告动作和原样 identity；A 核对 `menuId+residenceId` 后决定 manual-close、hide、lease release 和再进入。stale event 必须忽略。

### Main-owned 接线

- Main 提供 root、同步内容 resolver、shared contract、control lease provider 与 scene shutdown 调用。
- Main-owned adapter 固定为 `game/CampusContentResolver.ts` 和 `game/GameplayControlLeaseRuntime.ts`；B不修改。
- B 不修改 `game/CampusScene.ts`、`game/main.ts`、`index.html`、`package.json` 或 browser smoke。

精确语义索引见 [`02-接口层/API契约表.md`](../../02-接口层/API契约表.md)。

## 6. 怎样算做对

1. DOM 检查证明 canvas wrapper 与 UI 是同容器兄弟子树，UI 不进入 Phaser display list。
2. hidden/visible、pointer、9998/9999层级和 modal 内滚动符合设计；根页面不滚动。
3. 首次 show 归零 scroll；相同 menu 重复 show 保留 scroll。
4. 不同 menu 原子替换；非法 payload/root 缺失保留旧 UI。
5. standard 无 global backdrop；memo 有 global backdrop；backdrop 只在可见时接收 pointer。
6. close button/backdrop 各只发一次带当前 residenceId 的 UserCloseEvent；programmatic hide 不发；stale close不影响新modal。
7. resize/orientation/visualViewport 多次触发不累积 listener；destroy twice 安全。
8. shutdown 后无 listener/timer/global bridge/DOM payload 引用回调。
9. 桌面、≤1000px、≤500px 至少有结构/行为 Smoke；console/pageerror/network error 为0。
10. Escape/focus trap/图片失败仍明确标 UNKNOWN，不误报 parity PASS。

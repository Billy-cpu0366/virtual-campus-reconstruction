> 本卡完整工程状态仍为`undesign`；既有入口安全不代表Loading/Play/Retry已设计。新三板块并行波已授权P1调查页面→Loading→Play→Phaser真实状态链。

## 1. 逆向结论（从 sample 读出来的事实）

还没逆向，sample 里有原料。

## 2. 数据与约定

- **DECISION（有界重构入口）**：普通 production build 不安装可见运行时诊断监听器，也不暴露 `__campusDebug` / `__campusCollisionTest`；碰撞 Smoke 只使用显式 `test-hooks` build。
- **DECISION（入口资源）**：使用 inline favicon，避免浏览器默认请求未提供的 `/favicon.ico`。

## 3. 怎么做

- **DECISION（本次有界实现）**：`game/main.ts` 在创建 Phaser Game 前安装开发专用诊断；`CampusScene` 对初始化和 renderer 销毁 rejected 显式收敛，并在 shutdown 清理测试 hooks。
- P1由04独立件worktree调查完整页面、真实加载进度、Play、错误UI和Retry；Main产品入口线调查与相机/Phaser的接线。P2 Human Gate前不写正式功能代码。

## 4. 失败怎么办

- **DECISION（本次范围）**：开发诊断最多保留 50 行，使用 `textContent`，不在 production DOM 中写入内部错误；初始化或销毁 rejected 由场景捕获并记录，不形成未处理 Promise rejection。
- 完整应用错误恢复、页面级 fallback 和用户可见错误交互仍为 UNKNOWN。

## 5. 接口接口

- `game/main.ts` → `installRuntimeDiagnostics()`：仅开发环境安装诊断监听。
- `CampusScene` → Phaser Scene shutdown：停止移动、销毁 coordinator/scheduler、异步销毁 renderer、移除 DOM/键盘监听和测试 hooks。

## 6. 怎样算做对

- 普通 production build：诊断面板保持 hidden 且为空，`__campusDebug` 与 `__campusCollisionTest` 不存在，favicon/资源/页面无失败请求和运行时异常。
- 显式 `test-hooks` build：碰撞/桥 Smoke 仍可观察 Body、blocked、bridge 状态和 chunk 清理；该 build 不作为普通 production 产物。
- 本次结果：普通安全 Smoke、普通 browser Smoke、跨块 Smoke和 test-hooks 碰撞/桥 Smoke均通过；完整 SYS-APP 仍未实现。

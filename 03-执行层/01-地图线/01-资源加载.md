# 资源加载（SYS-ASSET）

> 一句话：原站怎样把图片、地图 JSON、瓦片集和分块数据拉进来；失败了怎么办；有没有缓存。本卡已定稿（`designed`），为 SYS-ASSET 唯一正式主定义。

## 👀 先看这里（人话总结，给 Human）

下面全是给 AI 看的精确结论（FACT / UNKNOWN 那套术语）。你**不用啃术语**，看这段人话就够审了。

**这卡在说啥**：原站靠什么、按什么顺序，把「图片、地图、切块数据」拉进浏览器；拉失败了会怎样；有没有缓存。

**我查清的 4 件原站事实**（你审的就认这 4 条）：
1. **家底**：原站公开资源 265 个文件、18.5 MB，webp 图片占大头（197 个）；一次完整运行 396 次请求**全部成功、零失败**。
2. **两条路拉货**：图片和地图走 Phaser 加载器，分块数据走 Angular 的 http；两条路各管各的、互不依赖。
3. **切块是「读」出来的**：先读小地图 JSON，从里面发现 16 个切块再逐个拉，不是写死在代码里。
4. **失败 / 缓存**：加载失败只往控制台打日志（不重试、不降级、不放占位图）；不把资源存进浏览器缓存。

**还有 2 件没彻底搞清**（标了 UNKNOWN，正常，不是错）：
- 到底靠不靠浏览器自带的 HTTP 缓存（得看响应头才能定）。
- 切块纹理啥时候创建、啥时候释放。

**当前状态**：完整系统仍为 `designed`；确定性 CORE 已验证，M1 粒子运行资源已在第一波 integration `f2fe106` 接入并通过资源、构建和浏览器门禁。
**仍未完成**：原站两套 Loader 的完整时序、HTTP cache/失败画面、纹理释放与严格内存边界；有界 M1 不等于完整 SYS-ASSET implemented。

## 1. 逆向结论（从 sample 读出来的事实）

### FACT（原站证实）

- 资源全景：manifest 记录 265 个公开文件、约 18.5 MB，其中 image/webp 197、application/json 31、image/png 23、js 8、css 1、svg 1、gif 1、字体 1、图标 1。一次完整运行捕获 396 次请求**全部 HTTP 200、零失败**，其中 image/webp 336（占 85%）。来源：`sample/original-public-build/manifest.json`、`sample/analysis/runtime-network.json`。
- 两套加载机制并存：Phaser Loader（`this.load.xxx`）加载地图 JSON 与瓦片集 webp；Angular HttpClient（`this.http.get`）加载分块数据 `master.json` 与 `chunk0-24.json`。证据：`chunk-WMFY56ZM.js`、`chunk-RA2FASQA.js`。
- 切块瓦片动态发现：`USE_OPTIMIZED_TILESETS` 开关为真时，先显式加载 `final-map-small`（`/assets/maps/final_map_small.json`）、`final-map-original`（`/assets/maps/final_map.json`）和 `exterior`（`/assets/maps/exterior-small.webp`）；再监听 `filecomplete-json-final-map-small` 事件，从该 JSON 的 `tilesets` 数组过滤名字含 `exterior-small` 的瓦片集，对每个（除 `exterior-small` 自身）拆后缀构造加载 key `exterior-{n}` 与 URL `/assets/maps/{tileset.image}`，逐个 `this.load.image`。即切块集合由 JSON 元数据驱动，不硬编码 16 个切块。证据：`chunk-WMFY56ZM.js`。
- 失败处理：GameScene 只注册 `fileerror` 和 `loaderror` 两个事件，均 `console.error` 打印日志（斯洛伐克语）；`collisions` 瓦片集失败额外打印「严重错误」。**未定位到重试、降级或占位图逻辑**。证据：`chunk-WMFY56ZM.js`。
- 缓存：`localStorage` 只存 UI 状态（`debug` 开关、`hasTiltedCard` 标记），**不缓存资源**；未定位 Service Worker Cache API（`caches.`）；运行时捕获全部 `fromDiskCache:false` 且 `fromServiceWorker:false`。证据：`main-RV3Z53H4.js`、`runtime-network.json`。
- 分块请求：chunk manager 用 `http.get` 请求 `assets/maps/chunks/master.json` 与 `assets/maps/chunks/chunk{index}.json`，成功以 `x_y` 缓存，非法坐标 / master 未就绪 / HTTP 异常返回 `null`。证据：`chunk-RA2FASQA.js`（与 SYS-CHUNK 的请求能力重叠，这里只记资源侧事实）。

### INFERRED（推断）

- 切块瓦片按「先加载小 JSON 元数据、再据此发现切块」的次序加载，但精确加载时机（何时加载哪几块、何时释放纹理）未量化；`runtime-network.json` 的 `timestamp` 字段基准/单位异常（跨度仅 14 ms 且全部落在同一秒桶），不能用于时序证明。证据：`runtime-network.json`。
- `USE_OPTIMIZED_TILESETS` 开关暗示存在「非优化」分支（可能直接渲染整图 `final_map`），但该分支的完整行为未在本次定位。

### UNKNOWN（还没弄清）

- 缓存策略：原站是否依赖浏览器 HTTP 缓存（`Cache-Control` 响应头）？采集时全 fresh 是冷启动还是资源本就无缓存头？需看响应头或重复访问实验。
- 失败后的实际玩家体验：`collisions` 瓦片集缺失时游戏是否继续、是否缺碰撞或白屏，未做行为验证。
- 切块纹理的生命周期：webp 纹理何时创建、何时释放、内存上限未量化。

### DECISION（重构设计，非原站事实）

- 本卡完整系统保持 `designed`；已接受的 CORE 与 M1 是有界实现 DECISION，不自动覆盖完整 Loader、缓存和失败体验。
- 实现 DECISION（`DEC-SYS-ASSET-CORE-001`，签字 `A`；`开工`，2026-08-16）：确定性纯逻辑 CORE，覆盖资源 URL 约定（§2）、切块瓦片发现与加载 key 构造（§3）。失败处理**照抄原站**——只 `console.error`，不重试、不降级、不占位图。落点 `src/asset/` + `tests/asset/`。不含 Phaser/Vite、网络请求、缓存、渲染、旧项目修改。
- 实现 DECISION（`DEC-MAP-RUNTIME-COMPLETION-001`，签字 `接受接受`，2026-08-21）：M1 只新增公开 `tileset-particles` 的运行资源生成/校验及失败边界；保留当前完整 exterior atlas + sanitized chunk 合同，不切换为 16 张 exterior-small，不复刻完整原站 Loader 时序，不修改 `sample/`。

## 2. 数据与约定

### 原站资源 URL 约定

| 类别 | 路径 | 说明 |
|---|---|---|
| 地图 JSON | `/assets/maps/final_map.json` | 整图 1.6 MB |
| 地图元数据 | `/assets/maps/final_map_small.json` | 5.3 MB，含 `tilesets` 元数据（切块发现的来源） |
| 独立图层 | `/assets/maps/walls-layer.json`、`footsteps-layer.json`、`particle-trajectories.json` | 各约 40 KB |
| 分块 | `/assets/maps/chunks/master.json`、`chunk0.json`…`chunk24.json` | 每块约 219 KB |
| 切块瓦片 | `/assets/maps/exterior-small.webp`、`exterior-small-2~16.webp`、`exterior-final.webp` | `final` 约 517 KB |
| sprite | `/assets/sprites/*.png`（如 `sunburn.png`、`vortex.png`） | 游戏内精灵 |
| UI 图片 | `/assets/images/`（`logos/`、`cards/`、`ui/`、`portfolio/`） | 作品集卡牌、Logo 等 |
| 第三方库 | `/assets/js/phaser.min.js`、`hover-tilt.min.js` | Phaser 3 与悬停倾斜 |
| 外部字体 | Google Fonts `Press Start 2P` | woff2，外链加载 |

### 加载 key 约定（Phaser Loader）

- `final-map-small`、`final-map-original`、`exterior`、`exterior-{n}`（n = 切块后缀 2…16）。

### 采集工具探测到的不可用路径（非运行时事实）

- `unavailable.json` 记录的 `exterior.png`、`cards/card5_foil.webp`、`ui/cables3.png` 均 404，但在 Bundle 中零引用，属采集工具猜测的路径，**不是原站运行时请求失败**。证据：`sample/original-public-build/network/unavailable.json`。

## 3. 怎么做

### 原站加载流程（FACT，从 Bundle 读出）

```text
游戏场景 preload
  ├─ 优化瓦片集开关为真：
  │    this.load.json(final-map-small / final-map-original)
  │    this.load.image(exterior = exterior-small.webp)
  │    filecomplete-json-final-map-small 触发后：
  │        遍历 tilesets 中名字含 exterior-small 的项
  │        → 对每个非基础项，按后缀构造 exterior-{n}，load.image
  └─ 分块数据（另一条线，不经过 Phaser Loader）：
       chunkManager.http.get(chunks/master.json)
       → 按 index=y*5+x 逐个 http.get(chunks/chunk{index}.json)
```

- 两套机制互不依赖：Phaser Loader 管「渲染所需的图像与地图 JSON」，HttpClient 管「分块数据」，后者成功结果以 `x_y` 存入 manager 缓存供场景读取。
- 加载进度：`this.load.on("progress", …)` 回调把 0–1 进度换算成百分比，供 UI 展示。

## 4. 失败怎么办

- 原站已定位行为：`fileerror` 与 `loaderror` 两个事件均只 `console.error`；`collisions` 失败额外打印「严重错误」。**无重试、无降级、无占位图**。证据：`chunk-WMFY56ZM.js`。
- 分块请求失败返回 `null`（非法坐标、master 未就绪或 HTTP 异常）。证据：`chunk-RA2FASQA.js`。
- 异步清理：`this.load.once("filecomplete-…")`、`this.load.on("fileerror"/"loaderror"/"progress")` 均为 Phaser 事件监听，随场景销毁回收；本次未定位额外的显式 shutdown 清理路径（与 SYS-CHUNK 的销毁 UNKNOWN 一致）。
- 资源加载的重构约定留待实现授权：原站事实（两套加载机制）已定稿，我们怎么写（是否加重试/降级）在写代码时再定 DECISION。

## 5. 接口接口

- 出 → SYS-WORLD / SYS-LAYER：提供渲染所需的地图 JSON、瓦片集 webp 与 sprite。
- 出 → SYS-CHUNK：提供分块数据请求能力（master 与 chunk JSON），但**不在此定义通用 Loader**（与 SYS-CHUNK 卡 §5 呼应）。
- 入 ← 原站 URL / `sample/` 公开证据。
- 资源 → 各系统的接口（图片怎么加载、失败怎么办、要不要缓存）：原站事实已定稿（见 §1）；重构约定（是否加重试/降级/缓存）留待实现授权。

## 6. 怎样算做对

原站事实基准（来源：`manifest.json`、`runtime-network.json`、Bundle）：

- BASE-ASSET-001：完整资源清单可复现——265 文件 / 18.5 MB，webp 占绝对多数；运行时 396 请求全 200、零失败。
- BASE-ASSET-002：两套加载机制并存——Phaser Loader 拉地图 JSON 与瓦片集 webp，HttpClient 拉 master 与 chunk JSON。
- BASE-ASSET-003：切块瓦片由 `final_map_small.json` 的 `tilesets` 元数据驱动发现，不硬编码切块清单。
- BASE-ASSET-004：失败只 `console.error`，无重试 / 降级 / 占位图；`collisions` 失败打印严重错误。

重构设计验收（本次不写码，仅作设计验收口径）：

1. 资源清单、路径与加载 key 与上表一致，不另立命名；
2. 切块发现逻辑能从元数据推导出全部切块 URL，无遗漏或重复；
3. 失败路径显式记录且不静默吞错（原站只打日志，重构是否加有限重试/降级属 DECISION，待 Human 定）；
4. 缓存结论不把「运行时全 fresh」夸大成「原站一定无缓存」，未证实项标 UNKNOWN。

M1 有界验收（第一波 integration `f2fe106`，2026-08-21）：

- `prepare:runtime` 从只读公开证据生成 `tileset-particles.png`，sanitizer 为 27 份运行地图内联受限 tileset metadata；`check:runtime` 验证 PNG `112×16`、firstgid `69355`、无 external tileset 和 raw GID 白名单。
- `CampusScene` preload 粒子 texture 并注册第三 tileset；production Smoke 25 个资源响应 200，无异常、失败请求或坏响应。
- typecheck、35 个测试文件/184 项、production/test-hooks build 及完整第一波浏览器门禁 PASS；不证明原站 HTTP cache、真实故障画面或完整纹理释放。

# 执行层（操作手册）

> 给执行 AI 照做。这里是 16 张系统卡 + 1 份总账 + 操作规则的唯一当前家。

## 六条规矩（先背下来，每轮照做）

1. **四色标记**（FACT/INFERRED/DECISION/UNKNOWN），推断不冒充事实
2. **两条状态线分开记**（理解 ≠ 做出）
3. **唯一事实源**：一件事一个家，别处只链接
4. **结论落地 = git 提交 + 完整同步《定稿落地清单》**，否则不算做完
5. **签字才写码**，签字写清"这次只授权哪块"
6. **sample 只读不抓**；遇异步/监听器/计时器必须写超时+清理

## 最小 6 步循环（每张卡一个循环）

```text
选卡/查证据 → 填7格和未知 → Human签字定范围 → 实现对应src/tests
→ 按标准验证差距 → git提交并回写总账
```

1. **选卡/查证据**：从[总账](00-总账.md)挑一张卡，只读对应 `sample/` 证据；
2. **填 7 格和未知**：把逆向结论填进卡的一至七格（四色标记），没弄清的上[总账](00-总账.md)未知队列；
3. **Human 签字定范围**：书面写明"这次只授权哪块"，没签字不写码；
4. **实现对应 src/tests**：按卡的七格（尤其 §4 失败与清理、§7 代码位置）写代码和测试；
5. **按标准验证差距**：对照卡的 §6（原站基准 + 设计验收 + 旧版差距）逐条验证；
6. **git 提交并同步《定稿落地清单》**：小步独立提交，并逐项同步下方《定稿落地清单》10 处，否则不算做完。

## 多人协作与 PR 补充（`DEC-GIT-PR-WORKFLOW-001`）

第二位协作者加入或 Human 明确要求正式 PR 时，除上面六步外增加以下边界：

1. 开始前核对正式仓库、canonical `origin`、当前分支和工作树；已有未提交修改必须保留，不得擅自 `reset`、`clean`、覆盖、`pull` 或切换覆盖。
2. 正式协作使用独立分支或 worktree；禁止在 `main` 上开始新的协作修改、commit 或 push。
3. commit 前检查实际 diff 和允许文件范围，完成匹配工作项的验证，并把结果回写 `task_plan.md` 和必要权威文档。
4. commit、push 或创建 PR 前先展示变更摘要、验证结果和未解决风险；Human 明确接受后才进入对应 Git 步骤。
5. 创建或更新 PR 后停止 PR 流程；不自动合并，不把 Draft PR 当作已进入 `main`。
6. `task_plan.md` 仍是动态状态唯一权威；`task-todos/` 只记录有界工作，不覆盖当前状态或决策台账。

## API 协作规范审查补充（`DEC-API-COLLABORATION-001`）

外部 API 规范采用“输入 → 对照 → Human API Gate → 权威落盘”的流程：

1. **输入**：登记原始文档、最终交付物、来源、路径和 SHA-256；缺少源文件或哈希时保持 `UNKNOWN`，不把收据当事实。
2. **对照**：以 `02-接口层/API契约表.md` 和对应系统卡为项目契约权威，再核对代码/测试状态及 `task_plan.md`；外部规范只能提出候选结论。
3. **分层**：接口契约用 `Draft / Frozen / Changed`；工程状态用 `Not Started / Core Ready / Integrated / Verified`，两条状态线不能互相替代。
4. **冲突**：Caller/Provider、路径、参数和运行时集成未有证据时标为 `UNKNOWN`，不得为了协作方便直接冻结。
5. **Human Gate**：展示来源、实际 diff、冲突、验证结果和未解决项；Human 接受后，才同步 API 契约表、系统卡、决策记录和 `task_plan.md`。
6. **交付**：外部文档不进仓库时，项目侧提交可复核收据和已接受结论；不可复核的“已整理”不能作为完成证明。

## 定稿落地清单（一张卡 Human 签字「通过」后，逐项照做）

> 签字「通过」只代表「这卡内容对了」，**不算做完**。做完 = 下面 10 处全部同步并提交，缺一处不算落地。
> 以后每个系统照这份清单打勾，不靠记性；`scripts/check-state-consistency.py` 会兜底核对第 1/2/4/5 步的字段，第 6/7/8 步是内容级同步、脚本抓不到，更要自己照做。

1. **执行卡**：`status` → `designed`；补上 `## 👀 先看这里` 人话块（这卡在说啥 + 你审的就认这几条 + 下一步要单独授权）
2. **总账**（`00-总账.md`）：该系统行「工程状态」→ `designed`，备注写清已定稿结论摘要
3. **总账「未知队列」**：本系统查清的 `Q-` 从 open 挪到 closed（只留摘要 + 主定义链接 + 残余未知）
4. **进度总览**（`01-理解层/00-进度总览.md`）：该系统行图标 → 📐，顶头「全局一句话」计数同步
5. **理解卡**（`01-理解层/`对应路径）：标题下「📌 进度」行图标 → 📐，清掉底部滞留的旧 TBD / "待签字"话术
6. **系统地图**（`01-理解层/00-系统地图.md`）：若本系统动了「桥」（跨线接口），桥的状态同步成「已定死」
7. **API 契约表**（`02-接口层/API契约表.md`）：本系统入/出接口汇进「一、已定死」，删掉「二、还没定死」里已查清的老 TBD
8. **决策记录**（`决策记录.md`）：加一条 `DEC-SYS-XXX-DESIGN-001`；同系统 INVESTIGATION 那条「当前效力」列补"查证与填卡已完成"结果
9. **task_plan.md**：frontmatter `current-work-item` → `none`、顶部状态块同步、工作项写进「已关闭工作项索引」（含 `result-commit`）
10. **兜底闸门**：跑 `python scripts/check-state-consistency.py` 确认 0 漂移 → `git` 小步提交

## 动态权威

根 [task_plan.md](../task_plan.md) 是当前工作项、阶段、Gate 和下一步的唯一权威；总账只维护 16 系统状态，不复制动态状态。

## 代码 Gate

正式代码只在第 3 步签字且范围明确后进入 `src/` 和 `tests/`；`sample/`、旧项目和证据一个字节不碰；小步独立提交，禁止一次大提交。

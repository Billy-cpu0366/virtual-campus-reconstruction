# 区域触发（SYS-ZONE）

> Human 已于 2026-08-20 通过原设计；`DEC-CONTENT-FOUNDATION-DESIGN-001` 在一条龙预授权内进一步冻结 residence 边沿接口和访问收据。正式实现现由 P3/P4 有界包授权，尚未开始。

## 👀 先看这里（人话总结，给 Human）

**这卡在说啥**：地图上的 11 个内容 marker 怎么判断玩家靠近，并把对应内容交给弹窗系统。

**你审的就认这几条**：marker 来自公开 Bundle 静态配置，不来自地图 object layer；触发是每 100ms 检查 marker 中心与玩家的严格 `<30px` 距离；`visited` 统计与手动关闭抑制分开；离开区域后才允许再次触发；`menuId` 是 SYS-ZONE 到 SYS-INTERACT 的内容标识。

**当前状态**：设计已接受并完成跨线接口修订；弹窗 DOM、完整双语内容和原站失败/销毁事实仍未知。

**下一步**：一条龙 P3 创建 immutable baseline 和实现包后，由窗口A实现 `src/zone/**`；Main 最后接 SYS-INTERACT，不把 CORE 当作完整内容系统。

## 1. 逆向结论（从 sample 读出来的事实）

### FACT（公开证据已确认）

- marker 配置直接硬编码在 `sample/original-public-build/mirror/chunk-WMFY56ZM.js` 的 `markers` 数组（约 byte 334450），不是地图 JSON 的 object layer；公开地图 JSON 没有 `objects`、`sunburn` 或 `vortex` marker 数据。
- 当前公开配置有 11 个 marker：sunburn 5 个（about、cv、projects、contact、tech）和 vortex 6 个（memo1–memo6）。精确 id、名称、`menuId` 和像素坐标以 [`04-内容层/作品集内容.md`](../../04-内容层/作品集内容.md) 的 marker 索引为准。
- `addContentMarker` 给每个 marker 传入固定 `interactionDistance = 30`；玩家与 marker 中心距离严格 `< 30px` 时触发，等于 30px 不触发。
- 场景以 `CONTENT_MARKERS_CHECK_INTERVAL = 100` 每 100ms 检查当前相机范围外扩 100px 内的 active marker，然后调用 marker 的 `handlePlayerOverlap()`。
- 进入范围时，marker 先登记 visited，再通过 `menuId` 调用 `window.showModalWithBackdrop(menuId)`；离开范围时隐藏对应内容并将 `wasManuallyClosed` 重置为 false。
- `visited` 只用于访问统计，不阻止再次访问；手动关闭后，只要玩家没有离开区域，marker 不会再次打开，离开后才允许下一次触发。
- marker 的 `pointerdown` handler 对应 `handleClick()`，而该方法为空；当前公开 Bundle 中没有 marker 使用 `JustDown` 的证据。

证据位置：`chunk-WMFY56ZM.js` marker 类（约 byte 85500–89600）、marker 创建（约 byte 369827、484050）、场景轮询（约 byte 402981–403268）；Angular 桥接在 `main-RV3Z53H4.js` 的 `window.showModalWithBackdrop`；英语 modal 容器在 `sample/original-public-build/mirror/index.html`。

### DECISION（重构设计；Human 已通过 2026-08-20）

- SYS-ZONE 可建模为“静态 marker 配置 + 定时距离检查 + outside/inside 驻留边沿 + 访问统计”，而不是 Tiled object layer 或墙体碰撞。
- `type`/`menuId` 负责把区域触发结果交给 SYS-INTERACT；SYS-ZONE 不拥有弹窗 DOM、文案、语言内容、控制锁或手动关闭业务状态。
- 每次 outside→inside 生成唯一 `residenceId`，只发一次 enter；inside→outside 只发一次对应 leave。100ms轮询不直接变成重复 open。
- 原站在调用 show 前记录 visited；当前重构改为收到 Interact 的成功 visit receipt 后记录，避免 UI 失败仍产生虚假访问。该差异是明确 DECISION。

### UNKNOWN（本轮不补猜）

- 是否存在当前镜像之外的动态 marker 或运行时追加来源。
- `/sk/` 页面完整内容及每个 modal 的 Slovak 文案映射；当前只能确认首页 alternate 链接和 Bundle 内 `en`/`sk` 翻译表。
- modal 缺失、场景销毁、异步失败和多个内容请求同时发生时的完整清理/恢复策略。

## 2. 数据与约定

- marker 最小字段候选：`id`、`type`、`name`、`menuId`、`x`、`y`；可选 `fixedDepth` 仅作为显示层数据，不改变区域触发规则。
- 11 项内容索引、坐标和 `menuId` 维护在 `04-内容层/作品集内容.md`；本卡维护区域行为和系统边界，不复制整张内容表。
- FACT：当前公开 marker 使用固定 30px 交互距离；不是 Tiled 矩形/多边形区域。视口外扩 100px 是检查优化范围，不是触发半径。
- FACT：`memo4` 的可见固定 depth 为 999995，`memo5` 的可见固定 depth 为 1650；这两个字段不应被误作区域边界。

## 3. 怎么做

### DECISION（已由一条龙 P2 冻结）

1. 从静态 marker 配置建立可查询集合；
2. 每个检查周期只处理当前视口外扩 100px 内的 active marker；
3. 以玩家位置和固定 `<30px` 距离规则维护每个 marker 的 outside/inside；
4. outside→inside 生成 `residenceId` 并发一次 enter；持续 inside 不重复发；
5. inside→outside 发对应 leave，随后结束该 residence；
6. Interact UI show 成功后回 visit receipt，Zone 再记录 visited；
7. SYS-ZONE 只输出驻留状态和内容标识，manual-close、控制、DOM、文案、语言和关闭按钮归下游。

## 4. 失败怎么办

### FACT

- 公开 Bundle 只有在 `document.getElementById(menuId)` 找到目标时才显示内容；目标缺失时当前路径不显示，也没有证据表明 SYS-ZONE 自动创建内容。
- 公开 Bundle 没有为 marker 记录独立网络请求或重试策略。

### UNKNOWN / 后续边界

- 目标/payload 缺失由 SYS-INTERACT / GAME-UI 返回受控失败；Zone 不记 visited，也不创建 fallback。
- 场景销毁时必须停止轮询、阻断晚到 tick、清 marker residence/visited引用；原站完整 teardown 仍 UNKNOWN。

## 5. 接口接口

### Frozen

- **输入**：玩家世界位置；静态 marker 配置；场景 active/销毁状态。
- **输出**：`ZoneResidenceEvent { markerId, menuId, residenceId, phase: enter|leave }`。
- **回执**：Interact show 成功后返回 `InteractionVisitReceipt`，Zone 才记录 visited。
- **下游边界**：manual-close、single-active、DOM 与控制恢复不归 Zone。
- **索引**：精确语义见 [`02-接口层/API契约表.md`](../../02-接口层/API契约表.md)。P3共享 contract 由Main冻结，窗口A不得单方面改。

## 6. 怎样算做对

### 设计验收标准

1. 11 个 marker 的 id、type、名称、`menuId` 和坐标与公开 Bundle 逐项一致；
2. marker 不从地图 JSON object layer 推导；
3. 距离 29.999px 触发，距离 30px 不触发；
4. outside→inside 只发一次带唯一 residenceId 的 enter；持续inside不重复发；
5. inside→outside 只发一次匹配 leave；再次进入生成新 residenceId；
6. show成功receipt才记录 visited；visited 与 manual-close/是否允许再次触发分开；
7. marker `pointerdown` 不被误实现为额外打开路径；
8. `/sk/` 完整内容映射保持 UNKNOWN，不能用英语 DOM 冒充双语已验证。

本节已作为 SYS-ZONE 设计验收标准冻结；P4窗口A必须逐条测试并由Main回写结果。

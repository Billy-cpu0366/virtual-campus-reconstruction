# 世界交互·弹窗（SYS-INTERACT）

> 一句话：把 SYS-ZONE 的一次驻留进入/离开变成可关闭、可再次进入、不会泄漏控制锁的内容弹窗状态。本卡是 Main 复核三窗口报告后的正式设计主定义。

## 👀 先看这里（人话总结）

- 玩家进入内容 marker 后，Interact 根据 `menuId` 请求 Game UI 显示内容；离开后关闭。
- 用户手动关闭后，只在这次驻留里保持关闭；真正离开并再次进入后才重新打开。
- 同时只允许一个内容弹窗；新内容成功显示后替换旧内容。替换不是“手动关闭”，不会污染旧 marker 状态。
- 弹窗显示期间通过统一玩法控制门锁住玩家；关闭、离开、失败或 shutdown 都必须成对释放。
- 原站控制锁、完整 teardown、`/sk/` 内容仍缺直接证据；当前控制 lease 和失败收敛是重构 DECISION，不冒充原站 FACT。

**当前状态**：设计已在 `DEC-CONTENT-FOUNDATION-DESIGN-001` 的预授权范围内由 Main 复核定稿；实现由一条龙 P3/P4 自动派工，尚未开始。

## 1. 逆向结论（从 sample 读出来的事实）

### FACT

- 11 个 Zone 内容 `menuId` 为 `about`、`cv`、`projects`、`contact`、`tech`、`memo1`–`memo6`；marker 中心严格 `<30px` 时进入，每 100ms 检查，离开重置手动关闭抑制。主定义见 [SYS-ZONE](01-区域触发.md)。
- 原站按 `document.getElementById(menuId)` 查找预置 modal；目标存在且 marker 未手动关闭时，先记录 visited，再调用 `window.showModalWithBackdrop(menuId)`。目标缺失时静默跳过，不记录 visited，也没有 modal 网络请求/重试证据。
- close button 经 Angular handler 调用 scene `closeMarker(menuId)`；marker `manuallyClose()` 将 `wasManuallyClosed=true` 并隐藏 modal。离开半径后隐藏 modal、重置该 flag，再进入可重新打开。
- backdrop click 会遍历可见 modal，隐藏并调用对应 `closeMarker`。原站存在多个 visible modal 的技术可能，但没有产品语义证明。
- 原站 marker 周期检查可能重复调用 show；已可见 modal 通常保持可见且不重新归零 scroll。

证据：`sample/original-public-build/mirror/chunk-WMFY56ZM.js` byte 334450、403011–403268、481963–485100、88609–89698；`main-RV3Z53H4.js` byte 116875–117900、121663–125010、170672–172820；`index.html` 的11个 modal/close button。

### INFERRED

- marker 负责驻留和内容标识，Angular modal manager 负责 DOM 可见性；二者是显式 bridge，不是同一对象。
- 周期重复 show 在视觉上近似幂等，但若重构直接重复 acquire 控制门，会造成锁泄漏，因此必须在 Interact 状态机去重。

### UNKNOWN

- 原站 modal 打开时是否完整暂停键盘、玩家、相机或 Phaser scene；目前只直接看到 speech bubble、marker 和 joystick 可见性变化。
- 原站 modal/global bridge/resize listener/timer 在 scene 或 Angular destroy 时的完整清理。
- 多 modal 同时打开的正式产品规则、异步 provider 失败、缺失 payload fallback、完整 `/sk/` 内容。

### DECISION

- 当前重构采用 single-active modal，不复刻多 modal 技术可能。
- 控制锁使用 token/lease 语义；这是为相机和内容交互并存提供的重构安全合同。
- visited 在 UI `show` 返回 `shown` 或 `already-visible` 后才提交 receipt；正常路径与原站结果一致，失败时不产生虚假 visited。该时序是重构 DECISION，区别于原站“调用 show 前记录”。

## 2. 数据与约定

### 内容 ID

`ContentMenuId` 固定为11个值；`big-map`、`under-hood` 不属于本轮 Zone→Interact 输入。

### ZoneResidenceEvent

| 字段 | 语义 |
|---|---|
| `markerId` | marker 唯一 id |
| `menuId` | 11个内容 ID 之一 |
| `residenceId` | 每次 outside→inside 新生成的驻留代号；同一驻留的重复检查不变 |
| `phase` | `enter` 或 `leave` |

### InteractState

```text
closed
open(active marker/menu/residence, control lease)
manually-closed-until-leave(suppressed residence)
destroyed
```

- 当前只允许一个 `active` modal。
- 手动关闭抑制按 `residenceId` 记录，不按 `menuId` 全局记录。
- `replace` 不把旧 residence 标为 manually closed；旧 residence 后续 leave 只清自己的记录，不关闭新 modal。
- `destroyed` 是幂等终态，拒绝后续事件。

## 3. 怎么做

### 进入

1. 校验事件、`menuId`、scene 状态和 `residenceId`；重复 enter 幂等忽略。
2. 当前 residence 已手动关闭时不显示。
3. 通过 Main-owned `ContentResolverPort.resolve(menuId)` 同步取得 evidence-backed payload；missing/invalid 时不申请 lease、不显示、不 visited。本轮不支持网络/异步 resolver。
4. 没有 active modal 时申请 control lease；`acquire` 返回 `{ok, token|reason}`，失败则不显示、不 visited。
5. 调用 `GameUiPort.show({menuId,residenceId,payload,presentation})`。show 必须原子：目标无效时保留旧 UI，不产生半切换。
6. 返回 `shown` / `already-visible` 后更新 active，并向 Zone 发送 visit receipt。
7. 初次 show 失败时释放刚申请的 lease；replace 失败时保留旧 active 和旧 lease。

### 替换

- 新 residence enter 且已有 active 时，复用现有 lease；UI 原子切换成功后才把 active 改成新 marker。
- 旧 residence 不进入 manual-close；由于 Zone 只发边沿事件，周期检查不会把旧 modal 抢回。

### 用户关闭

- B 只发 `UserCloseEvent(menuId, residenceId, source)`，不自行改业务状态。
- A 必须同时核对 menuId 和 residenceId 仍对应 active；stale close 直接忽略。匹配后调用 UI `hide({menuId,residenceId,reason})`，记录该 residenceId 为手动关闭，清 active，释放 lease。
- close button 和 backdrop 语义等价，但保留 source 供诊断。

### 离开

- 清除该 `residenceId` 的手动关闭抑制。
- 只有 leave 对应当前 active 时才 hide、清 active 和 release；被替换的旧 marker leave 不影响新 modal。

### Shutdown

1. 标记 destroyed，先取消 Zone 和 UI close 订阅；
2. hide 当前 UI；
3. 调用 UI destroy；
4. 在 `finally` 释放 Interact 持有的全部 control lease；
5. 清 active、suppression、generation 和 payload 引用。重复调用不得抛错。

Main 只在 Interact/Camera 等消费者 shutdown 后调用 `GameplayControlLeaseProvider.shutdown()`；provider shutdown 拒绝新 acquire、使剩余 token 失效，并保持scene shutdown所需的禁用状态。它不替代消费者各自 release。

## 4. 失败怎么办

- 非法 menuId / 缺内容 payload：返回受控失败，状态不变，不 visited、不 acquire。
- UI `missing-target` / `invalid-payload`：初次打开回滚 lease；replace 保留旧 active。
- lease acquire 失败：不得调用 show；记录受控诊断。
- hide 失败：仍清业务 active，并在 finally 释放 lease；保留首个错误用于诊断，不能让玩家永久锁死。
- stale residence / shutdown 后回调：no-op；不得复活旧 modal。
- 本轮不新增网络 retry，不请求私有/未公开内容，不用英语内容冒充双语完成。

## 5. 接口接口

### SYS-ZONE → SYS-INTERACT

- `ZoneResidenceEvent`：`markerId / menuId / residenceId / phase`。
- Zone 只负责边沿事件和驻留身份；不拥有 DOM、控制锁和手动关闭业务状态。

### SYS-INTERACT → SYS-ZONE

- `InteractionVisitReceipt`：只在 UI 确认显示后发送 `markerId / residenceId / menuId`；Zone 维护访问统计。

### Main ContentResolver → SYS-INTERACT

- Main-owned `ContentResolverPort.resolve(menuId)` 同步返回 `resolved(payload)` 或 `missing/invalid`。
- Resolver 的权威来源是 `04-内容层/`；Interact不解析文案，B不猜内容。本轮不引入网络、Promise或retry。

### SYS-INTERACT ↔ SYS-GAME-UI

- A 调用带 `menuId + residenceId` 的 `show(request)`、`hide(request)`、`destroy()`；B 发带同一 identity 的 `UserCloseEvent`。
- programmatic hide 不得伪造 user-close；stale residence close 不得关闭当前UI。
- 精确结果和 backdrop policy 见 [SYS-GAME-UI](../../04-独立件/02-游戏UI.md)。

### SYS-INTERACT → 玩法控制门

- `acquire("modal-open") -> {ok:true,token}|{ok:false,reason}`；`release(token)`。
- token 是 opaque、由成功 acquire 的 Interact active state 独占；重复/未知/失效 token 安全忽略并诊断。
- Interact 只释放自己的 token，不直接操作 keyboard、joystick、camera 或玩家 Sprite；provider shutdown 只由Main在消费者之后调用。

精确语义索引见 [`02-接口层/API契约表.md`](../../02-接口层/API契约表.md)。P3 由 Main 创建共享冻结 contract 后，A/B 从同一 immutable baseline 实现。

## 6. 怎样算做对

1. 11个 menuId 一一识别；非法 id 不改状态。
2. Zone outside→inside 只生成一次 residence enter；距离30px不进入。
3. 同 residence 重复 enter 不重复 resolve、show、visited 或 acquire。
4. resolver missing/acquire失败/show失败均无虚假访问和锁泄漏；失败结果可测试。
5. close button/backdrop 都进入本次 residence 的 manual-close；未离开不重开。
6. leave 清 suppression；re-enter 新 residence 可再次打开。
7. replace 成功才切 active；旧 leave 不关闭新 modal；replace 失败保留旧 UI。
8. initial/replace/hide/acquire 失败均有单测；任何路径最多一个 Interact lease。
9. shutdown/destroy 幂等，之后无 listener/timer/Promise 回调、UI、payload 或 token 残留。
10. 浏览器 Smoke 覆盖接近 marker→打开→控制暂停→关闭→恢复→离开→再次进入。

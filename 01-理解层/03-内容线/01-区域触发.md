# 区域触发（SYS-ZONE）

> 📌 进度：📐 已设计＋有界CORE已验证 —— 11个marker、`<30px`、100ms、residence/receipt已在`8ae7692b`接入浏览器；完整系统仍未完成

## 它是什么

地图上散落的"标记点"（marker），玩家走近就触发（弹出提示 / 打开内容）。

## 它管哪些事

- 检测玩家是否进入某个标记区域
- 防重复触发（走近只触发一次，不狂弹）
- 11 个 marker（sunburn×5 + vortex×6）

## 走一遍

玩家进入 marker 中心 30px 内 → 场景每 100ms 的距离检查发现进入 → 通过 `menuId` 自动打开对应内容 → 玩家离开 30px 区域 → 内容隐藏并重置本次驻留的手动关闭状态 → 再次进入可重新触发。

## 为什么这么设计

交互点散落在地图各处，不能靠"碰撞"（那是墙），要靠 marker 中心距离检查。原站公开 Bundle 使用 100ms 轮询和 `wasManuallyClosed` 驻留状态；没有发现 marker 使用 `JustDown` 的证据。

## 跟谁接口

- 出 → 世界交互（弹窗）：触发打开对应内容
- 入 ← 玩家：位置

> 精确约定见 `../../02-接口层/API契约表.md`

## 容易踩的坑

- **防重复驻留**：`visited` 只做统计；手动关闭后，玩家未离开区域前不能重复打开，离开后才重置。
- **区域边界**：严格按 marker 中心 `<30px` 判定；视口外扩 100px 只是轮询优化范围，不是触发半径。
- marker 坐标以 `04-内容层/作品集内容.md` 的公开 Bundle 索引为准。

## 我要学什么

"**触发器**"模式——地图上的标记点 + 就近检测 + 防重复。这是 RPG 交互点的通用做法。

# 世界交互·弹窗（SYS-INTERACT）

> 📌 进度：📐 已设计＋有界CORE已验证 —— 打开/关闭/替换/再次进入和控制lease已在`8ae7692b`通过真实浏览器纵切片

## 它是什么

玩家走进地图内容点后，负责把 `menuId` 变成一个可关闭的作品集弹窗，并协调玩家控制暂停与恢复。

## 它管哪些事

- 同时只显示一个内容弹窗
- 关闭按钮 / memo backdrop 的用户关闭动作
- 手动关闭后，本次驻留不重开；离开再进入才重开
- 弹窗显示成功后才记录访问
- 弹窗期间控制锁，关闭/失败/shutdown 必须释放

## 走一遍

玩家进入 marker → UI 成功显示 → 记录访问并暂停控制 → 用户关闭 → 本次驻留不再弹 → 玩家离开 → 再次进入可重新显示。

## 为什么这么设计

原站靠 marker 和 DOM modal 连接游戏与作品集。当前重构把“什么时候开”与“怎么显示”分开：Interact 管业务状态，Game UI 管 DOM。这样快速进入/离开、切换内容或销毁场景时不会重复弹窗或泄漏控制锁。

## 跟谁接口

- 入 ← SYS-ZONE：`markerId/menuId/residenceId/enter|leave`
- 出 → SYS-GAME-UI：显示/隐藏内容；接收用户关闭事件
- 出 → SYS-ZONE：UI成功后的访问收据
- 出 → 玩法控制门：持有并释放自己的控制 token

> 精确约定见 `../../02-接口层/API契约表.md`

## 容易踩的坑

- 旧弹窗的关闭事件不能关闭后来替换的新弹窗，所以事件必须带 `residenceId`
- programmatic hide 不能伪造用户手动关闭
- UI显示失败不能记录访问，也不能把玩家永久锁住
- 原站 Escape、focus 和完整 teardown 仍未证实，不能误报已复刻

## 我要学什么

“**游戏状态与网页弹窗解耦**”：地图只报驻留，Interact 管状态，DOM UI 管呈现，Main 管最终接线和销毁顺序。

# 移动与碰撞（SYS-MOVE）

> 📌 进度：🟡 懂一半 —— "能走吗"暗号已定死，可拿假地图开工

## 它是什么

角色走路 + 撞墙停下。走之前先问一句"前面这格能走吗"。

## 它管哪些事

- 应用移动向量（把方向变成实际位移）
- 碰撞检测（问地图"这格能走吗"）
- 分轴移动（先走 x 再走 y，分开判断碰撞）

## 走一遍

输入系统给了方向"上" → 移动系统问地图"上面那格能走吗？" → 能走，就移过去；不能走（是墙），就停下 → 逐轴判断，避免"斜着卡墙"。

## 为什么这么设计

原站的碰撞数据**不是运行时算的**，而是离线预提取成一份 `walls-layer.json`（140×140 的 0/1 矩阵，40KB）。运行时只要查表"这格是 0 还是 1"，比实时计算快得多。

## 跟谁接头

- 出 → 地图：问"这格能走吗"（输入坐标 → 输出 true/false）
- 入 ← 输入：方向
- 入 ← 玩家：当前位置

> 精确约定见 `../../02-暗号层/接头暗号表.md`

## 容易踩的坑

- **分轴移动 vs 预提取网格**：碰撞数据是离线静态文件，不是 tilemap API 现算
- **斜着卡墙**：如果 x、y 一起判断，斜着走会卡在墙缝里；要分轴

## 我要学什么

"**碰撞数据离线化**"——把碰撞算成静态数据，运行时只查表。这是性能优化的经典手法。

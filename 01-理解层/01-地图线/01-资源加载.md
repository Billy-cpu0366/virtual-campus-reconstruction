# 资源加载（SYS-ASSET）

> 📌 进度：📐 画好图纸 —— 失败/缓存已定稿；浏览器 HTTP 缓存仍 UNKNOWN

## 它是什么

图片、地图 JSON、瓦片集怎么加载进来，加载失败怎么办，要不要缓存避免重复下载。

## 它管哪些事

- 加载图片 / JSON / 瓦片集
- 失败处理（原站只打日志，不重试、不放占位图）
- 缓存（原站不缓存资源，每次进都重新下载）

## 走一遍

进游戏 → 资源系统按需加载瓦片集、精灵表、地图数据 → 某张图加载失败 → 只往控制台打日志，不重试也不放占位图 → 资源不缓存，反复进出会重复下载。

## 为什么这么设计

原站的瓦片集（exterior，6.9 万个 gid）被**切块成多个 webp** 动态加载，不是一张整图。所以加载策略复杂：得知道"什么时候加载哪几块瓦片"。而且资源不缓存，玩家反复进出会重复下载。

## 跟谁接口

- 出 → 世界 / 分块：提供它们要的数据
- 入 ← 原站 URL / sample 证据

> 精确约定见 `../../02-接口层/API契约表.md`

## 容易踩的坑

- **瓦片集不完整**：exterior 完整有 6.9 万 gid，只拿到 3.4KB，要反推缺哪些
- **失败降级**：网络断了 / 图没了，原站只打日志，不重试、不降级
- **切块加载**：一张大瓦片集被切成多个 webp，加载策略比"整图"复杂

## 我要学什么

"**加载 / 失败 / 缓存**"三件事分离，是资源管线的通用骨架。将来平台要加载多校园素材，也是这套。

> ✅ 已确认（SYS-ASSET）：失败只往控制台打日志，不重试、不降级、不放占位图；应用层不缓存资源。剩两处 UNKNOWN：浏览器 HTTP 缓存是否生效、切块纹理创建/释放时机。精确结论见 `../../03-执行层/01-地图线/01-资源加载.md`。

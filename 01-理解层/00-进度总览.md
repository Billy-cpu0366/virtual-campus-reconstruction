## 先看结论

- **原站理解**：1 个 confirmed、10 个 partial、5 个 discovered。
- **详细设计**：8 / 16，已完成资源、世界、图层、分块、输入、移动、玩家、相机。

## 两条基础状态线

| 线 | 状态 | 意思 |
|---|---|---|
| 原站理解 | `discovered` → `partial` → `confirmed` | 刚发现 → 懂一半 → 证据足够确认 |
| 完整工程 | `undesign` → `designed` → `implemented` → `verified` | 没设计 → 图纸定稿 → 完整代码 → 完整验证 |

## 三条工作线

```text
地图线：资源 → 世界 → 图层 → 分块
玩法线：输入 → 移动 → 玩家 → 相机
内容线：区域触发 → 世界交互
```

- 地图线和玩法线可以在接口定死后并行。
- 内容线依赖区域触发，旁支依赖世界基础。
- 独立件可以单独推进，但仍要通过当前工作项和Human授权。

## 怎么看“完成”

- `✅ 有 CORE`：只代表纯逻辑代码和测试存在。
- `designed`：代表完整系统的设计和验收标准已定稿，不代表代码完成。
- `implemented`：代表完整系统代码已实现。
- `verified`：代表完整系统已按原站基准、设计标准和浏览器/行为要求验证。

# 游戏 UI（SYS-GAME-UI）

> 📌 进度：📐 已设计 —— 内容 modal 的 DOM/Canvas 边界、层级、移动端尺寸和关闭接口已定稿；完整网站外壳仍归 SYS-APP

## 它是什么

显示在 Phaser canvas 上方的网页 UI。当前设计范围是游戏内内容 modal、backdrop、关闭按钮、滚动和移动端尺寸，不把 Loading/Play/Retry 全部塞进本系统。

## 它管哪些事

- DOM modal 的显示、隐藏和原子内容替换
- backdrop、close button、z-index 和 pointer
- modal 内滚动、移动端高度与 resize
- 把 close-button/backdrop 用户动作报告给 Interact
- shutdown 时清理 DOM listener、timer 和引用

## 走一遍

Interact 提交内容 payload → Game UI 在 DOM modal 显示 → 玩家滚动阅读 → 点关闭按钮或 memo backdrop → UI 报告用户动作 → Interact 决定关闭与恢复控制。

## 为什么这么设计

原站把 Phaser canvas 和 Angular modal 放在同一个 game container 的不同 DOM 子树中。重构保留“DOM UI + Canvas 游戏画面”的边界，但用一个通用 modal shell，避免复制11套静态结构。

## 跟谁接口

- 入 ← SYS-INTERACT：带 `menuId/residenceId/payload/backdrop` 的 show/hide
- 出 → SYS-INTERACT：带相同 residence 的 close-button/backdrop 事件
- 入 ← Main：modal root、内容 resolver、viewport 和 shutdown

> 精确约定见 `../../02-接口层/API契约表.md`

## 容易踩的坑

- canvas wrapper 与 modal 是同一容器的兄弟子树，不应把 modal 画进 Phaser
- old close 事件必须带 residence，不能误关新内容
- hidden UI 不应接收 pointer；modal 要高于 backdrop，并自己滚动
- Escape、focus trap、图片失败和原站完整 teardown 仍是 UNKNOWN

## 我要学什么

“**DOM 呈现端口**”：UI 只显示和报告动作，不接管 marker、visited、manual-close 或玩家控制业务。

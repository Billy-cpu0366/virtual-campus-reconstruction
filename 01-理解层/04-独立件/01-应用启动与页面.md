# 应用启动与页面（SYS-APP）

> 📌 进度：📐 已设计 —— Loading/Play主链已查清，ERROR/Retry是重构决定

## 它是什么

网站外壳：从打开网页到点 Play 的整个入口。页面状态机。

## 它管哪些事

- 4 层 DOM 结构（init-load 临时 Loading / Angular 壳 / game-container Canvas / landscape-overlay 横屏提示）
- 预加载流程
- Play 按钮 → 初始化游戏
- 页面状态管理

## 走一遍

打开网页后先创建Phaser并显示真实文件队列进度 → Scene ready后出现Play → 点Play → 3秒镜头落玩家、火车5秒进场 → 开放控制。失败时进入本重构设计的ERROR/Retry。

## 为什么这么设计

应用外壳（Angular）和游戏画布（Canvas）分两层。原站用 Angular 19 做壳，但 Angular 只负责"承载 Canvas + 渲染模态 DOM"，所以复刻版可以用原生 JS 替代，视觉和交互一样（这是 PRD 里的一个关键 DECISION）。

## 跟谁接口

- 出 → 游戏 UI：提供入口 / 状态
- 入 ← 浏览器事件

> 精确约定见 `../../02-接口层/API契约表.md`

## 容易踩的坑

- **SPA 壳与 Canvas 的 z-index**：叠错了层，游戏画面或按钮会互相挡住
- **Angular vs 原生 JS**：复刻版决定用原生 JS 替代 Angular，减少构建依赖（见决策记录）

## 我要学什么

"**应用壳 + 游戏画布分层**"，以及"用更轻的技术替代重框架、效果不变"的取舍判断。

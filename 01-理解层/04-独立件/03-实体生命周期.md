# 实体生命周期（SYS-ENTITY）

> 📌 进度：🔍 刚发现 —— 还没拆

## 它是什么

每个实体（玩家 / NPC / 车辆）从"生"到"死"的统一管理：创建、活跃、销毁、清理。避免内存泄漏。

## 它管哪些事

- 实体创建（出生）
- 实体活跃（更新、移动）
- 实体销毁（离场）
- 失败回滚与清理（出错也能清干净）

## 走一遍

一个 NPC 出现（创建）→ 在地图上活跃 → 走出范围被销毁 → 销毁时把它的监听器、计时器、引用全清掉，不留垃圾。

## 为什么这么设计

游戏里实体很多、反复出现消失。如果没有统一的生命周期管理，每个实体"怎么生、怎么死、死前清什么"各写各的，很容易漏清理，导致内存泄漏、越玩越卡。

## 跟谁接头

- 出 → 各系统：提供"生 / 死 / 清理"的统一规矩
- 入 ← 触发条件（进入范围创建、离开范围销毁）

> 精确约定见 `../../02-暗号层/接头暗号表.md`

## 容易踩的坑

- **漏清理**：销毁时没移除监听器 / 计时器，就会泄漏
- 这个系统的细节还没查清（Q-ENTITY-001 开着）

## 我要学什么

“**生命周期管理**”——创建/销毁/回滚，是所有有“对象”的系统都要面对的共同问题。精确工程区把它单列，是因为它横跨所有实体，值得独立说明。

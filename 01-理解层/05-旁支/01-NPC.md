# NPC 与环境实体（SYS-NPC）

> 📌 进度：📐 已设计 —— 本轮先做四个喷洒者NPC

## 它是什么

地图上会动的"非玩家"角色：行人、鬼魂、舞者、怪物、人群。

## 它管哪些事

- NPC 生成与状态
- 沿路径移动
- 视锥裁剪（超出相机范围就销毁，回来重建）
- 寻路（EasyStar.js，跑在 Web Worker 里）

## 走一遍

玩家接近row25的四个喷洒者 → 最近者先逃跑 → 其余按距离每300ms开始 → 沿公开路线跑完并销毁。视口外普通idle实例回收，逃跑实例保持自己的路线生命周期。

## 为什么这么设计

- **视锥裁剪**：地图上可能有很多 NPC，全留着浪费性能，只留"看得见的"
- **后台寻路**：寻路计算重，放 Web Worker 里跑，主线程专心渲染，不卡顿

## 跟谁接口

- 出 → 世界：提供 NPC 实体
- 入 ← 相机：裁剪范围（决定销毁/重建）
- 入 ← 地图：路径数据

> 精确约定见 `../../02-接口层/API契约表.md`

## 容易踩的坑

- **Worker BlobURL 创建 + 跨线程数据同步**（有主线程 fallback）
- **销毁重建 vs setVisible**：简单版先 setVisible 切换，别急着销毁重建

## 我要学什么

"**视锥裁剪 + 后台寻路**"两大优化，是 NPC 系统的通用难点。原站还有怪物章鱼抓玩家（复杂相机状态机，P2 后补）。

## 三、执行层卡的 7 格模板

每张卡统一 7 个格子。frontmatter 保持极简：

```markdown
---
tags: [虚拟校园, 执行层, 系统卡]
system: SYS-XXX
status: 空槽 | designed | implemented | verified
updated: 2026-08-15
---

# 系统名（SYS-XXX）

## 1. 逆向结论（从 sample 读出来的事实）
每句标来源和颜色：`FACT`（原站证实）/ `INFERRED`（推断）/ `UNKNOWN`（还没弄清）

## 2. 数据与约定
精确的数据结构、格式、坐标、命名约定

## 3. 怎么做
精确的算法、流程、每帧做什么

## 4. 失败怎么办
超时、失败、越界、资源缺失时的兜底；遇异步/监听器/计时器必须写清理路径

## 5. 接头暗号
跟谁握手、精确形式；没定死的标【TBD】

## 6. 怎样算做对
验证标准、测试点

## 7. 代码位置
src/ 哪个目录 + tests/ 哪个文件（没写的标"未写"）
```

**空槽卡**：7 个格子都留空，只在 §1 写一句"还没逆向，sample 里有原料"。status = 空槽。

## 五、执行步骤（每步一次提交）

**第 0 步 · 安全网**：确认 `git status` 干净，记下 HEAD（`1fabc8a`）。

**第 1 步 · 建 16 张卡**：按 §二 建 `03-执行层/` 完整目录；3 张有肉的按 §四① 抽内容填好；13 张按空槽模板填。提交。

**第 2 步 · 建总账和操作手册**：按 §四② 写 `00-总账.md`；写 `03-执行层/README.md`，第一页放 6 条规矩：
1. 四色标记（FACT/INFERRED/DECISION/UNKNOWN），推断不冒充事实
2. 两条状态线分开记（理解 ≠ 做出）
3. 唯一事实源：一件事一个家，别处只链接
4. 结论落地 = git 提交 + 回写总账，否则不算做完
5. 签字才写码，签字写清"这次只授权哪块"
6. sample 只读不抓；遇异步/监听器/计时器必须写超时+清理
提交。

**第 3 步 · 归位顶层**：按 §四② 写 `决策记录.md`（从"谁确认过什么"抽）、更新根 `README.md` 的 Phase 1 边界。提交。

**第 4 步 · 归档壳**：按 §四③ 把壳挪进 `migration-history/doc-v0.1/`，保留结构。提交。

**第 5 步 · 留个壳指针**：让 `doc/v0.1/` 只留 ①当前工作项任务卡 ②一个 README 说"精确文档已搬到 03-执行层，历史在 migration-history/"。提交。

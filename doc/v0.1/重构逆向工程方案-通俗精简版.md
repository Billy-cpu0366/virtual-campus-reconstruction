# 重构逆向工程方案：通俗精简版

> [!summary]
> 当前先研究 Peter Oravec 原站，把它拆成一个个能看懂、能验证的系统；文档写清楚以后，才重新编写正式代码。

配套结构图：[[重构逆向工程方案-思维导图]]

## 一、我们现在在做什么

现在仍处于**原站逆向和复刻阶段**，还不是直接开发最终虚拟校园。

当前目标有两个：

1. 弄清楚原站由哪些系统组成、每个系统怎样工作；
2. 将这些结论写成正式文档，为后面的代码重构提供依据。

研究范围覆盖原站完整公开前端，但优先研究 Phaser 虚拟世界。

## 二、三个目录分别负责什么

```text
sample/    原站证据：公开文件、地图、资源、运行记录和采集工具
doc/v0.1/  工程知识：当前版本已经研究清楚并确认的结论
src/       正式代码：以后按照确认后的文档重新实现
```

简单理解：

```text
sample 是原材料
    ↓
doc/v0.1 是当前设计图纸
    ↓
src 是正式建筑
```

## 三、原站先分成哪几部分

### 1. 网站部分

包括页面启动、页面结构、作品展示、卡牌、弹窗、外部链接和设备适配。

### 2. 虚拟世界部分

包括：

- 游戏启动和资源加载；
- 地图、地图分块、图层和遮挡；
- 玩家、输入、移动、碰撞和相机；
- NPC、环境实体、车辆和路线；
- 区域触发、互动、游戏 UI 和动效。

### 3. 公共支撑部分

包括内容配置、资源路径、状态与事件通信、错误处理、兼容和调试。

这些最初都只是**候选系统**。必须找到原站证据后，才能确认。

## 四、怎样继续拆系统

拆分目标不是制造大量文件，而是把原站的职责、对象、事件、数据和行为边界研究清楚。

例如火车不是一个系统，它是一个对象。火车运行可能涉及：

```text
路线数据
位置推进
速度控制
朝向计算
动画表现
循环与重置
```

这些内容当前先留在车辆与路线系统中研究。只有实际实现、修改或第二个独立场景显示出真实重复，才能登记复用观察；多个场景的稳定部分和变化部分清楚后，才允许提出独立提取方案。

建立独立详细文档至少需要：

- 只负责一件清楚的事情；
- 输入和输出能够说清楚；
- 可以单独验证；
- 有原站证据和当前研究价值；
- 独立文档确实比继续留在所属系统更清楚。

不要为了显得专业，把每个函数、图片或 Phaser 类都包装成系统，也不要根据未来设想提前创建通用能力。

## 五、怎样区分事实和我们的设计

每项结论必须说明属于哪一种：

| 标记 | 说人话解释 |
|---|---|
| `FACT` | 原站文件或浏览器运行已经直接证明 |
| `INFERRED` | 有证据支持，但仍然包含推断 |
| `DECISION` | 我们重构时主动采用的设计 |
| `UNKNOWN` | 还没有弄清楚，需要继续研究 |

例如：

```text
FACT：原站使用 master 和 25 个地图分块，并按玩家邻域与相机范围动态装卸。
INFERRED：公开 Bundle 只能证明发布后机制，不能自动证明原始源码边界。
UNKNOWN：玩家阶段具体装卸时序和性能指标仍需量化。
DECISION：对应详细设计和 Human Gate 通过后，才决定正式源码怎样组织。
```

## 六、文档先怎么组织

先保留一个精简框架：

```text
doc/
└─ v0.1/
   ├─ README.md
   ├─ 01-需求分析/    原站有什么、复刻什么
   ├─ 02-概要设计/    有哪些系统、对象和事件
   ├─ 03-详细设计/    某个系统具体怎样工作
   ├─ 04-验证/        证据在哪里、复刻是否一致
   └─ 05-逆向计划/    还有哪些问题没有弄清楚
```

第一步不用建立几十份空文档。先完成系统思维导图和节点清单；某个节点真正开始研究时，再建立它的详细文档。

## 七、一个节点怎样逐步成熟

节点会经历两条不同的进度线。

### 我们对原站理解到什么程度

```text
只发现名称 → 部分理解 → 已确认
```

### 我们自己的重构做到什么程度

```text
未设计 → 已设计 → 已实现 → 已验证
```

两者不能混在一起。例如，我们可能已经确认原站使用地图分块，但还没有确定自己的正式代码如何实现。

## 八、什么时候建立正式 src

不需要等整个原站全部研究完，也不能没有文档就直接写代码。

正确方法是按一个个可以运行的闭环推进：

```text
先研究并写清这一圈
→ 确认系统边界和验收方式
→ 编写这一圈代码
→ 与原站对比验证
→ 修正文档
→ 再进入下一圈
```

建议第一圈是：

```text
启动
→ 资源加载
→ 地图和分块
→ 图层
→ 玩家生成
→ 输入
→ 移动与碰撞
→ 相机跟随
```

这条流程跑通后，就得到第一个可以操作、可以比较的虚拟世界基础版本。

## 九、当前任务从哪里看

当前阶段、当前 Human Gate、允许/禁止操作和下一步只维护在项目根 [`task_plan.md`](../../task_plan.md)。本文只解释稳定流程，不复制动态进度。

每一圈仍遵循：精确映射证据，写清事实、推断、未知项、边界和验收方式；对应 Human Gate 通过后，才能进入设计或实现。

> [!important]
> 文档先行不是先写完所有文档，而是每一圈代码开始前，先把这一圈要实现的内容写清楚。

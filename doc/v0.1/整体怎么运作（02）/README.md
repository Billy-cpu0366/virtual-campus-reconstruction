# 整体怎么运作（02）

> **说人话：把游戏当作一张总地图，看清地图、玩家、相机、图层等部分各管什么、怎样配合。**
>
> 想知道“现在做到哪一个功能”或“为什么先做地图分块”，看这里。

本目录回答：原站可能由哪些系统、对象和事件组成，它们之间如何协作。

概要设计只定义概念、边界和关系，不展开具体算法。

## 文档

- [[游戏整体由什么组成（系统全景）]]
- [[功能总目录（节点清单）]]
- [[游戏里有哪些东西和事情（对象与事件）]]
- [[各部分怎样配合（系统依赖）]]
- [[旧版本现在做到什么（现有实现盘点）]]：记录旧 Phaser 工程的集成基线、模块边界和明确缺失，不代表原站源码结构或新工程状态。
- [[先做什么（P0系统对照与顺序）]]：比较原站P0系统与旧实现，记录调查优先级和首个系统建议。

## 重要规则

这里的系统结构是逆向建模结果，不等于原作者源码目录。每个结论必须标注 `FACT / INFERRED / DECISION / UNKNOWN`。

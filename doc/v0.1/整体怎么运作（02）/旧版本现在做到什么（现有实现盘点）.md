## 3. 当前组合关系

```text
index.html + src/main.ts
├─ DOM UI Controller
│  └─ Loading → Ready → Starting → Playing / Error
└─ GameHandle
   └─ Runtime
      └─ CampusScene（唯一生产组合点）
         ├─ World
         ├─ Keyboard Input
         ├─ Player
         ├─ Walls Collider
         └─ Camera
```

这是当前旧代码的结构，不等于原站内部类结构，也不直接决定新仓库源码目录。

## 5. 地图与图层现状

### 已实现（现有代码 FACT）

- 运行时加载 `final_map_phaser.json`；
- 地图为 140×140 tile、16px tile，即 2240×2240px；
- 预加载16个 `exterior-small` tileset、`collisions-objects.webp` 和玩家精灵；
- 创建 `layer1` 至 `layer10`；
- 创建隐藏 `walls`，仅 GID `69345` 作为玩家实体墙；
- 创建前清除不属于嵌入 tileset 范围的残留 GID，防止 Phaser 解析失败。

### 未实现或未接入（现有代码 FACT）

- 没有读取 `master.json`；
- 没有读取 `chunk0.json` 至 `chunk24.json`；
- 没有地图分块加载、卸载或流式管理；
- 没有创建 `cars`、4个 roof、4个 bridge wall、3个 particles 和 `footsteps` 共13层；
- 3373个粒子占位格会被清零，不等于实现了粒子系统；
- 没有接入 `particle-trajectories.json` 和粒子纹理行为。

这些缺失只说明旧复刻现状；是否以及怎样实现，必须继续依据原站证据决定。

## 7. 生命周期与错误处理

### 已有边界

- Runtime在创建新Game前等待旧Game销毁；
- resize listener会在销毁时移除；
- Scene和Sandbox清理相机、collider、玩家、输入、地图图层与Tilemap；
- 加载文件失败会进入应用Error状态；
- UI与Scene通过显式生命周期接口通信，UI不直接修改Scene内部状态。

### 已知风险

- Retry目前执行整页刷新，不是游戏内重建；
- `getUiElements()` 在创建Game前失败时不会进入既有Error UI；
- Loader事件使用 `.on`，没有显式解绑，是否完全随Scene释放仍需专项验证；
- sanitizer原地修改Tilemap缓存，同一Game内重启Scene时不会恢复被清零的GID；
- HUD导航、地图和菜单按钮只显示，没有完成游戏交互。

- NPC及环境实体；
- 车辆、火车与路线；
- 区域触发、标记和世界交互；
- 动态粒子和脚步；
- 游戏内弹窗连接；
- 移动端虚拟摇杆、触摸或手势输入；
- 完整Retry和失败恢复；
- 地图分块运行机制。

## 9. 工程与部署风险

- 构建主JS约1495.54kB，gzip约344.82kB，Vite报告大于500kB Chunk；
- `base: "/"` 和绝对资源路径假定部署在站点根；
- `sourcemap: true` 会生成生产source map；
- `index.html` 仍含Google Fonts、Peter原站SEO信息和外链；
- Sandbox开发页会请求缺失的 `/favicon.ico`，当前得到HTTP 404；
- CI没有运行M3地图合约或浏览器/Sandbox验证；
- 多个旧B14/B15/Rust脚本已过时，不能作为当前Phaser验收入口。

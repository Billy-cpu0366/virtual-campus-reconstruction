# 重构逆向工程：工作流程速查

> [!summary]
> 先研究原站并写清楚，再根据文档重写代码；实现后与原站比较，结果继续补回文档。

相关文档：[[重构逆向工程方案-通俗精简版]]｜[[重构逆向工程方案-思维导图]]

## 整体流程

```text
1. 建立原站系统全景
   ↓
2. 选择一个要研究的系统
   ↓
3. 从 `sample/`、Bundle、Network、浏览器和现有代码中找证据
   ↓
4. 写清原站事实、合理推断、未知项和必要的重构决定
   ↓
5. 拆清系统职责、对象、事件、数据和行为边界
   ↓
6. 确认系统边界、实现方案和验收标准
   ↓
7. Human 确认后按文档编写对应正式 src
   ↓
8. 与原站运行效果进行对比验证
   ↓
9. 检查是否出现真实重复，并更新复用观察
   ↓
10. 将发现的问题补回文档，再研究下一个系统
```

## 一句话版本

```text
搭框架 → 找证据 → 填文档 → 拆边界 → 定方案
→ Human确认 → 写代码 → 做对比 → 观察重复 → 改文档 → 下一圈
```

## 每一圈必须留下什么

| 阶段 | 最少产物 |
|---|---|
| 找证据 | 可定位的文件、请求或浏览器行为 |
| 填文档 | `FACT`、`INFERRED`、`DECISION`、`UNKNOWN` |
| 拆边界 | 系统职责、子能力、对象、事件和数据 |
| 定方案 | 边界、依赖、验收标准和 Human 确认 |
| 写代码 | 与本圈文档对应的正式实现 |
| 做验证 | 原站与复刻的差异结果 |
| 观察重复 | 真实重复场景或“未发现”的记录 |

## 当前所在位置

```text
公开资源采集            ✅ 已完成
运行时首轮采集          ✅ 已完成
系统全景与文档框架      🔄 正在确认
逐系统逆向填充          ⏳ 下一步

```

> [!important]
> “文档先行”不是一次写完整个项目，而是每一圈写代码之前，先把这一圈研究和设计清楚。

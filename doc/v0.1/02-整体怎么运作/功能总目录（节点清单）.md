## 候选关注点去向

本表处理已经进入权威输入、但当前不应机械晋升为独立节点的内容。它不是第二套节点状态线。

| 候选关注点 | 当前去向 | 处置 | 理由或触发条件 |
|---|---|---|---|
| 页面结构、导航、作品、卡牌、弹窗和设备适配 | SYS-APP | 归入现有节点 | 当前由应用系统统一研究；出现独立边界和近期任务后再登记节点 |
| 游戏生命周期 | GRP-GAME-LIFECYCLE、EVT-PLAY | 保留分组 | 当前只有部分事件达到节点条件；发现独立状态所有权后再登记系统节点 |
| 内容配置、资源路径、状态通信、错误、兼容和调试 | GRP-SUPPORT | 延后登记 | 保留在系统全景；出现可定位证据和近期研究任务后登记节点 |
| 单个 NPC、车辆和地图分块实例 | OBJ-NPC、OBJ-VEHICLE、OBJ-CHUNK | 归入对象类型 | 普通实例不创建节点，实例证据留在对象或来源文档 |
| 单张图片、字段、常量和函数内部步骤 | 所属系统/对象/数据定义 | 非节点 | 没有独立设计和验证价值 |
| 最终校园业务、后台和多人在线 | [[../01-目标与范围/这次要复刻什么（目标与范围）#5. 当前不在范围]] | out-of-scope | 不属于当前原站公开前端重构范围 |

能力清单中的每个 `CAP-*` 必须映射到一个或多个节点，或进入本表说明去向；新增系统全景分支同样必须登记节点或去向。当前登记不要求提前创建详细文档。

## 当前P0调查顺序

P0表示业务优先级相同，不代表调查必须并行。当前基于证据完整度和旧实现差距提出的先后顺序维护在 [[先做什么（P0系统对照与顺序）]]；未经Human确认，不改变节点工程状态或开始源码实现。

## 状态与机器规则

```text
类型：系统 / 对象 / 事件 / 能力 / 数据 / 约定
范围处置：candidate / in-scope / out-of-scope / not-applicable / merged
原站理解状态：discovered → partial → confirmed
重构工程状态：undesign → designed → implemented → verified
证据等级：FACT / INFERRED / UNKNOWN，可用 `+` 组合
```

- 父级必须解析到节点 ID、`GRP-*` 或 `ROOT`；
- `undesign` 的唯一主定义允许为 `—`；从 `designed` 开始必须填写唯一文件或稳定章节锚点；
- 证据等级只描述原站证据，不填写 `DECISION`；重构决定通过 `decision-refs` 和决策台账追踪；
- `out-of-scope / not-applicable / merged` 必须填写理由，`merged` 还必须填写目标 ID；
- 来源引用必须解析到权威 ID、项目相对路径或固定证据定位，普通自然语言不算可定位来源；
- 当前表中的范围处置只说明研究去向，不改变阶段 6B Human Gate。

## 晋升规则

有明确证据、边界和近期研究价值的节点，才创建独立详细文档；其余继续留在本清单或候选关注点去向表。创建主定义时必须按 [[../03-具体怎么做/README]] 同步节点元数据和稳定锚点。

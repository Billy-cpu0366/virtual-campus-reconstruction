# 04-怎么验证与还差什么

> **说人话：不是说“做了”就算，要在这里看证据、测试方法，以及离原站还差哪些地方。**
>
> 想确认一个功能到底是“设计好了”“代码写了”还是“真的验证过”，看这里。

本目录回答：结论的证据在哪里，当前复刻与原站是否一致。

## 文档

- [[原站实际表现是什么（行为基准）]]：记录原站可重复观察的标准行为。
- [[旧版本实际表现是什么（行为基线）]]：记录旧 Phaser 工程在指定提交上的可重复结果，不代表原站或新工程已完成。
- [[原站和旧版本差在哪（证据与差距）]]：串联证据、系统文档、现有代码和差距。
- [[文档有没有对齐（治理检查报告）]]：分别记录治理结构检查、语义审查、基线和未解决项。
- [[地图分块：怎样验证做对了（SYS-CHUNK 验证计划）]]：地图分块的原站事实基准、设计验收和实现后验证计划。
- [[世界与地图：怎样验证做对了（SYS-WORLD 验证计划）]]：已接受世界装配设计的数据、失败和生命周期验收。
- [[图层与遮挡：怎样验证做对了（SYS-LAYER 验证计划）]]：已接受24层设计、动态遮挡和`Q-LAYER-001`最小补证计划。

## 验证原则

- 可观察行为优先于主观印象。
- 每条差异都要能追溯到操作步骤或文件证据。
- 没有证据的判断标为 `UNKNOWN`，不能强行通过。
- 自动结构检查不能替代 FACT/INFERRED/DECISION/UNKNOWN、职责边界和复用判断的语义审查。
- 正式验证必须绑定 clean Git 提交；覆盖内容变化后原验证失效。

# 03-详细设计

本目录只为已经进入实际研究的节点建立独立文档。

## 分类

- `系统/`：一组共同完成某种任务的规则和能力。
- `对象/`：玩家、NPC、火车、地图等被系统管理的对象。
- `事件/`：点击 Play、进入区域、发生碰撞等运行过程。
- `数据与约定/`：地图格式、坐标、资源命名等统一规则。

## 节点晋升条件

节点同时满足以下条件，才创建独立详细文档：

1. 至少有一条可定位证据；
2. 能描述可观察行为；
3. 能初步说明负责什么、不负责什么；
4. 当前或近期复刻需要研究；
5. 已列出关键未知项；
6. 独立文档比继续留在节点清单更清楚。

不满足条件的节点继续保留在 [[../02-概要设计/节点清单]] 或 [[../05-逆向计划/未知问题队列]]。

## 复用观察规则

复用是实践结果，不是当前目录分类：

1. 第一次出现的逻辑先正确研究和实现，不强制抽象。
2. 第二个独立实际场景出现相同行为，或同一逻辑被重复修改时，登记观察。
3. 判断相似性时比较实际输入、处理、输出和状态变化，不能只比较名称。
4. 多个真实场景显示出稳定部分和变化部分后，才能提出提取方案。
5. AI 不得自行提取；必须先报告真实场景、稳定部分、变化部分、收益、成本和风险，并取得 Human 确认。
6. Human 批准后，复用成果的完整说明只写入一个唯一主归属文档；其他文档和观察表只记录状态与链接，不复制定义。
7. 可复用成果不限于系统，也可能来自对象模型、事件流程、数据格式、算法、UI、工具、测试能力或工程约定。
8. 复刻中的重复使用只能证明项目内复用；未来校园真实使用后，才能证明跨项目复用。

## 任务检查

开始和结束详细设计或实现任务时都要检查下表：

- 当前工作是否与已有观察具有相同或相近的输入、处理、输出和状态变化？
- 是否出现第二个独立实际场景、复制逻辑或重复修改？
- 如果相似，更新实际场景和证据；如果不同，记录关键差异。
- 没有真实重复时保持“未发现”，不得为了未来设想创建通用模块。

状态只使用：`未发现 / 观察中 / 待 Human 确认 / 已批准 / 已提取 / 已拒绝 / 已跨项目验证`。进入“已批准”前必须填写主归属文档；提取后的详细接口、约束、实现和测试只在主归属文档维护。

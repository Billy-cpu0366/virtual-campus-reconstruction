# 事件详细设计

事件描述运行过程中“什么时候发生什么”，例如点击 Play、资源加载完成、进入区域和发生碰撞。

## 文件命名

```text
EVT-领域-编号-事件名称.md
```

## 统一模板

```markdown
# 事件名称

## 1. 事件目的
这个事件代表什么。

## 2. 原站证据
怎样观察到该事件。

## 3. 触发者与前置条件
谁触发，发生前必须满足什么。

## 4. 正常流程
按顺序列出参与系统和对象。

## 5. 异常与分支
失败、中断、重复触发如何处理。

## 6. 状态变化
哪些对象或系统状态发生变化。

## 7. 输入与结果
事件携带什么，最终产生什么。

## 8. 现有代码映射与差距
当前复刻是否已经支持。

## 9. 未知问题
还有什么无法确认。

## 10. 测试流程
如何重现、观察和断言。

## 11. 复用观察
是否有多个实际流程共享相同触发、状态变化或结果；没有真实证据时写“未发现”，不得把所有调用预先事件化。发现真实重复时必须同步详细设计入口的观察表；Human 批准提取后，由观察表指定唯一主归属文档。
```

事件文档描述流程；对象属性和系统内部算法分别链接到对象、系统文档。事件文档不等于必须实现事件总线：必须立即返回结果的一对一操作优先使用同步调用，已经发生的状态变化或一对多通知才优先使用事件。

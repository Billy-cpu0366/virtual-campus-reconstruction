# 原站复刻目标与范围

## 1. 项目背景

Peter Oravec 原站将作品展示网站与 Phaser 二维虚拟世界结合。本阶段通过公开发布文件、运行时行为和现有复刻代码恢复其工程知识，并用实际复刻检验理解，为后续虚拟校园正式实现积累经过实践验证的成果。

原站复刻是当前目标和第一套实践场景，不是最终产品。最终目标是在复刻、修改和重复使用过程中，逐步识别真正稳定、有价值的系统、数据、算法、UI、工具、测试能力和工程约定，为自己的虚拟校园使用。

## 2. 当前目标

1. 识别原站完整公开前端的主要能力和系统边界；
2. 优先弄清 Phaser 虚拟世界的地图、玩家、实体和交互机制；
3. 建立证据可追溯的正向工程文档；
4. 按原站实际行为完成复刻并验证理解；
5. 在实践中记录真实重复和稳定变化边界，不预设复用成果；
6. 文档确认后，再建立正式 `src/`。

## 3. 复用目标与边界

- 角色创建、事件和对话只是可能出现的例子，不代表完整复用范围。
- 可复用成果也可能来自对象模型、数据格式、算法、UI、资源工具、测试能力、调查方法和工程约定。
- 第一次出现的逻辑先正确研究和实现；第二个独立实际场景出现相同行为，或同一逻辑被重复修改时，才登记复用观察。
- 多个真实场景显示出稳定部分和变化部分后，才能提出提取方案；未经 Human 确认不得自行抽象。
- 原站复刻中的重复使用只能证明项目内复用；未来校园真实使用后，才能证明跨项目复用。
- 当前不建设适用于所有游戏的通用引擎，也不提前设计完整校园业务。

## 4. 当前范围

### 网站部分

- 页面启动和状态；
- 页面结构与导航；
- 作品、卡牌和弹窗展示；
- 游戏嵌入；
- 响应式与设备适配。

### 虚拟世界部分（当前优先）

- 游戏启动和资源加载；
- 地图、分块、图层和碰撞；
- 玩家、输入、移动和相机；
- NPC、环境实体、车辆和路线；
- 区域触发、世界交互、UI和动效。

### 公共支撑

- 内容与配置；
- 资源路径与命名；
- 状态和事件通信；
- 错误、兼容和调试。

## 5. 当前不在范围

- 未公开原始 TypeScript、私有仓库和 Git 历史；
- 服务端、数据库、密钥和私有配置；
- 未在公开文件或运行时出现的猜测资源；
- 最终虚拟校园业务、后台管理和多人在线；
- 当前阶段的正式 `src/` 实现；
- 仅根据未来设想预先划分可复用系统、原站适配或校园适配；
- 为证明复用而提前建设第二套完整校园内容。

## 6. 证据来源

- `sample/original-public-build/mirror/`；
- `sample/original-public-build/manifest.json`；
- `sample/analysis/runtime-network.json`；
- 地图 JSON、公开 Bundle 和浏览器实际表现；
- 现有 Phaser 复刻项目，只作为实现对照。

## 7. 完成标准

当前文档阶段完成需要：

- 原站主要系统、对象和事件有清晰全景；
- P0 节点均有证据、状态和未知项；
- 第一条代码闭环涉及的系统有详细设计和验收标准；
- 事实、推断和重构决定没有混淆；
- AI 能从项目入口找到当前有效原则、Human Gate 和复用观察规则；
- 没有真实重复证据时，不提前宣布或提取可复用成果。

## 8. Human 确认结果

- [x] 完整公开前端纳入系统全景；
- [x] Phaser 虚拟世界为当前优先范围；
- [x] 原站复刻优先，复用成果从实践中总结；
- [x] 正式 `src/` 只在对应系统通过文档门禁后实现。

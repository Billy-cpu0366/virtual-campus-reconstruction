# 游戏 UI（SYS-GAME-UI）—— "游戏世界的仪表盘"

> 📌 进度：📐 已定稿 —— Loading/Play/地图HUD/弹窗已清楚；精确NES.css视觉风格未与原站逐像素对齐

---

## 一句话讲清楚

**游戏UI系统 = 所有"套在游戏画面外面"的网页界面：加载动画、Play按钮、小地图、内容弹窗、导航提示。**

就像汽车上的仪表盘——它不参与发动机怎么转、轮子怎么跑，但它告诉你"还有多少油"（进度条）、"现在能不能起步"（Play按钮）、"前面是哪条路"（地图）、"这里是什么地方"（弹窗）。不管这辆车是什么牌子，仪表盘的功能——显示状态、辅助导航、展示信息——是一样的。

---

## 它管哪些事

| 管的事 | 大白话 | 不管的事 |
|---|---|---|
| 加载界面渲染 | 显示"Loading... 50%"、红色进度条、加载动画GIF | 不管具体下载什么文件、下载到多少——那是SYS-ASSET的事 |
| Play/Ready界面 | 加载完显示Logo + Play按钮，等用户点 | 不管点了Play之后怎么初始化游戏——那是SYS-APP的事 |
| 错误界面 | 显示"Unable to enter campus" + Retry按钮 | 不管为什么出错、要不要重试——那是SYS-APP的事 |
| 小地图系统 | 右下角迷你地图HUD + 点击弹出大地图对话框，显示标记点和玩家位置 | 不管玩家实际在哪——那是SYS-PLAYER提供坐标 |
| 内容弹窗 | 走到某个区域后弹出文字/图片内容（如"About Me"、"Projects"） | 不管触发什么内容、内容从哪来——那是SYS-ZONE和内容层的事 |
| 导航引导浮标 | 屏幕底部（手机端顶部）浮动文字："Explore ABOUT · head west 18 tiles, then north 5" | 不管计算需要走多少步——那是SYS-ZONE提供数据 |

**它不管的事**：网页壳的状态切换逻辑（归SYS-APP）、Canvas里的游戏画面渲染（归Phaser Scene）、资源下载（归SYS-ASSET）。

## 🎨 核心：皮与骨架拆分

> **骨架** = 换什么校园都不变的做事方式
> **皮** = 跟 Peter 这个具体项目绑定的内容
> **配置点** = 将来后端管理系统可以改的参数

---

### 一、骨架（换什么校园都不变的东西）

#### 骨架 1：状态驱动的DOM视图切换

**大白话**：游戏UI根据应用当前状态自动切换显示内容——加载中就显示进度条，准备好了就显示Play按钮，游戏中就全部隐藏。

就像红绿灯——当前是什么状态，就亮什么颜色的灯。绿车（PLAYING状态）不该看到红灯（加载界面），红灯（LOADING状态）不该看到绿灯（Play按钮）。

不管这个校园是Peter的、某学校的、还是某公司的，都需要一套"看状态→切换界面"的机制。

**为什么是骨架**：任何有多状态的应用都需要视图层能响应状态变化。状态→视图的映射模式是通用的。

**实现形态**：`DomAppUi.render(snapshot)` 接收 `AppSnapshot`，根据 `snapshot.status` 调用对应的 `renderLoading()` / `renderReady()` / `renderEntering()` / `renderPlaying()` / `renderError()`。

#### 骨架 2：内容弹窗系统

**大白话**：游戏中弹出内容卡片——有遮罩、有标题、有正文、有关闭按钮。弹窗打开时玩家不能移动。

就像你逛博物馆时走到一个展品前，墙上有一个信息牌——你停下来看，看完继续走。弹窗打开=你看信息牌，暂停走路；关弹窗=继续逛。

不管什么校园，总有些地方要展示文字和图片内容——About、Projects、Contact等等。弹窗的"打开→暂停交互→展示内容→关闭→恢复交互"这个流程是通用的。

**为什么是骨架**：任何有交互内容展示的游戏都需要弹窗系统。"遮罩+卡片+关闭按钮"的模式是通用的。

**实现形态**：`DomModalGameUi` 管理 `#content-ui-root` 中的 `#content-backdrop`、`#content-modal`、`#content-title`、`#content-body`、`#content-close`。`show()` 构建DOM内容并显示，`hide()` 清空并隐藏，`destroy()` 彻底清理。

#### 骨架 3：小地图系统

**大白话**：右下角迷你地图帮助玩家知道"我在哪"、"附近有什么"。点击放大看全景大地图。

就像商场里的"你在这里"指示牌——一个小地图告诉你当前位置和周围的店铺。迷你地图=墙上的小指示牌，大地图=展开的商场平面图。

不管什么校园，玩家都需要知道自己在哪、周围有什么。地图系统是通用的。

**为什么是骨架**：任何有空间导航需求的应用都需要地图。"缩略图+标记点+玩家位置指示"是通用模式。

**实现形态**：`#campus-map-hud`（迷你地图，z-index:6500）+ `#campus-map-root`（大地图弹窗，z-index:8000）。标记点用绝对定位按坐标放置，玩家位置实时更新。

#### 骨架 4：内容引导浮标

**大白话**：当玩家靠近一个内容区域时，屏幕边缘出现一行浮动提示文字，告诉玩家"往哪走多少步能到"。

就像GPS导航说"前方200米右转"——你不一定看到目的地，但文字告诉你方向和距离。

不管什么校园，当目的地不在屏幕上时，玩家需要文字指引。这个"文字浮标"模式是通用的。

**为什么是骨架**：任何需要给玩家空间指引的游戏都需要方向提示。浮标的位置、文字格式、显示/隐藏逻辑是通用的。

**实现形态**：`#content-guide` 元素（z-index:7000），`textContent` 动态更新。弹窗打开时自动隐藏（`guide.hidden = visible`），弹窗关闭时恢复。

#### 骨架 5：可选资源的优雅降级

**大白话**：加载动画GIF和Logo图片如果加载失败了，不崩溃，不白屏——默默地隐藏自己，换上替代文字。

就像餐厅门口的水牌——如果LED屏坏了，挂个手写小黑板也行。重要的是"这里有个入口"这个信息不丢失。

不管什么校园，图片都可能加载失败（网络不好、文件被删、CDN挂了）。"失败了不崩溃，降级到文字"这个模式是通用的。

**为什么是骨架**：任何展示外部资源的应用都需要失败降级。图片→alt文字→占位符的降级链是通用的。

**实现形态**：`DomAppUi` 的 `optionalImages` 机制——每个图片绑定 `error` 事件监听器，加载失败时设 `visibility:hidden` + 替换 `alt` 文字。

### 二、皮（跟 Peter 项目绑定的东西）

| 皮 | 当前值（Peter 项目） | 换成其他校园会怎样 |
|---|---|---|
| 加载页视觉 | 白底 + Peter Oravec GIF头像（310×310） + 红色进度条(`#ef4444`) + 黑色边框(`#111827`) + 百分比文字 | 换不同的人/学校的Logo和主题色 |
| Ready页视觉 | 透明背景露出游戏底图 + Peter Oravec Logo(441×282) + 红色Play按钮 + CSS网格动画（850ms渐隐网格） | 换不同的Logo和按钮样式 |
| 错误页视觉 | 红色面板 + 白色文字 + "Unable to enter campus" + Retry按钮（同色系） | 可以改成弹窗模式、加错误代码详情 |
| 小地图素材 | `map-holder-mini3.webp`（地图外框）、`mini-map.webp`（迷你地图图）、`big-map.webp`（大地图） | 换不同校园的地图图片和标记点坐标 |
| 地图标记点 | 11个标记点：about/cv/projects/contact/tech（5个info）+ memo1~memo6（6个memo） | 换标记点的名称、坐标、分类 |
| 内容弹窗的主题色 | 深蓝#0f172a背景 + 白色#f8fafc卡片 + 黄色#facc15标题 | 换不同品牌的配色方案 |

| 手机端适配 | ≤767px：地图缩小到209×149、引导浮标移到顶部、弹窗加宽到92vw | 调整断点值和缩放比例 |
| 导航引导文字格式 | "Explore ABOUT · head west 18 tiles, then north 5"（英文） | 可多语言、可调格式 |

## 跟谁接口（它和谁打交道）

```
                        ┌──→ [SYS-APP 应用启动]  从它：AppSnapshot（当前状态）
                        │                       给它：play/retry点击事件
[SYS-GAME-UI 游戏UI] ──┼──→ [SYS-ZONE 区域触发]  从它：触发信号 → 显示弹窗
                        ├──→ [内容层]            从它：菜单内容 → 填充弹窗
                        ├──→ [SYS-PLAYER 玩家]   从它：玩家坐标 → 更新地图上蓝点
                        └──→ [浏览器]            写入DOM / 监听点击 / 响应resize
```

游戏UI是**玩家和虚拟世界之间的翻译官**——它把游戏内部的"状态代码"翻译成人看得懂的"视觉界面"。

## 容易踩的坑

| 坑             | 为什么坑                                                                                                 |
| ------------- | ---------------------------------------------------------------------------------------------------- |
| z-index层次炸了   | DOM UI有多层（地图HUD 6500、引导浮标 7000、地图弹窗 8000、外壳 9000、诊断面板 10001）。如果哪个层的z-index不对，按钮可能被遮住点不到，或者遮罩盖不住该盖的东西 |
| 弹窗打开时忘了隐藏引导浮标 | 弹窗和引导浮标同时显示会很丑——浮标说"往西走18步"，但弹窗已经开了，用户根本不在走路。`onModalVisibility` 回调就是为了弹窗打开时隐藏引导文字                   |
| 手机端地图太小看不清    | 迷你地图在≤375px屏幕上只有169×120，标记点只有7px——手指粗的人根本点不中。当前没有做触摸扩大点击区域的处理                                        |
| 弹窗内容DOM没清干净   | 每次 `show()` 都会 `replaceChildren()` 重建内容。但如果close时忘记清，下次打开会叠加旧内容，导致标题重复、段落翻倍                          |
| 地图标记状态不对      | 标记点有三种状态：未访问（橙色）、已访问（绿色边框）、disabled（灰色）。如果visit状态没正确记录，玩家会看到"还没去过的点显示成已访问"                           |
| 像素字体FOUT      | 游戏用了monospace字体但没有web font加载策略。如果用户网慢，会先看到系统默认字体，字体加载完再跳成monospace——这就是FOUT（Flash of Unstyled Text）  |

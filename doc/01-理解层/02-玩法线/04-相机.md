# 相机（SYS-CAMERA）—— "你的眼睛"

> 📌 进度：📐 画好图纸 —— 硬跟随+边界+缩放+航拍已定稿；执行层逆向数据齐备

---

## 一句话讲清楚

**相机系统 = 决定了你在屏幕上看到什么、看多远、画面会不会抖。**

就像你看电影——导演的镜头决定你看到什么。平时镜头紧贴主角（你走到哪看到哪），开场时会先"航拍"一圈让你看看校园全貌，然后镜头落回主角身上。画面不会放大缩小（zoom=1），地图边缘就是视线的尽头（2240×2240 像素），画面做了像素取整保证不抖动。

---

## 它管哪些事

| 管的事 | 大白话 | 不管的事 |
|---|---|---|
| 跟随玩家 | 镜头贴着角色走，角色停镜头也停 | 不负责角色怎么走——那是移动系统的事 |
| 边界限制 | 镜头不能超出地图范围，不会看到地图外的黑边 | 不负责地图多大——那是世界系统的事 |
| 开场航拍 | 游戏开始前镜头自己飞一圈，带你浏览校园 | 不负责航拍中"该加载哪块地图"——那是分块系统的事 |
| 缩放控制 | 画面永远 1:1，不放大不缩小 | 不负责设备清晰度适配——nativeScale 是外部注入的 |
| 防抖稳定 | pixel取整 + 固定30帧物理步长，画面不抖 | 不负责抗锯齿——那是渲染管线的事 |

## 🎨 核心：皮与骨架拆分

> **骨架** = 换什么校园都不变的做事方式
> **皮** = 跟 Peter 这个具体项目绑定的内容
> **配置点** = 将来后端管理系统可以改的参数

---

### 一、骨架（换什么校园都不变的东西）

#### 骨架 1：跟随模式

**大白话**：镜头始终跟着角色，他去哪镜头去哪。

就像你拿手机拍一个跑步的朋友——你手机会跟着他移动。游戏的相机也一样，它一直在"看"玩家的位置，玩家走它就动。不一样的是，这把相机是"硬贴"而非"平滑追"——没有延迟、没有缓动，逐帧瞬时贴住。

**为什么是骨架**：所有有玩家的游戏都需要相机跟随，这是最基本的能力。换什么校园、换什么引擎都需要。

**实现形态**：`startFollow(player, true, 1, 1)`——第 3/4 个参数 lerpX=lerpY=1，表示瞬时硬跟随（不平滑）。每帧相机位置 = 玩家位置。

#### 骨架 2：视口约束

**大白话**：镜头不能超出地图边界，走到头就停——你不会看到地图外的东西。

就像你在房间里拍照——拍到墙了就不能再往后退，画面里不会出现隔壁房间。相机有边界 `setBounds(0,0,2240,2240)` 约束，保证玩家再往边上走镜头也不会摇出界。

**为什么是骨架**：边界约束是所有俯视角/横板游戏的标配——相机永远不能超出世界范围。

**实现形态**：`cameras.main.setBounds(0, 0, 2240, 2240)`，Physics world 同样边界。

#### 骨架 3：开场航拍序列

**大白话**：真正的游戏开始前，镜头按预设路线自己飞一圈，给观众看看校园长什么样。

就像你去电影院——正片开始前有预告片。开场航拍就是一串预设的相机位置：飞到点 A 停几秒 → 飞到点 B 停几秒 → …… → 最后落回玩家。约 111 秒的"观光"，一是展示校园，二是给地图加载争取时间。

**为什么是骨架**：开场展示、过场动画、传送过渡——这些"镜头自动化"的需求在任何校园都会出现。序列本身不同，但"按预设点飞→停→飞"这个模式是通用的。

**实现形态**：`cameraSequence` 数组（6 个点，每个点有 x/y/duration/stayDuration），由 `startCameraSequence()` 驱动。

#### 骨架 4：视口驱动加载

**大白话**：镜头看到了哪块地方，分块系统就去加载哪块地图。镜头看不到的地方就先不加载，省资源。

就像你用手电筒照亮房间——你只看到光照射的地方，暗处的东西不必细看。相机告诉分块系统"我在看这区域"，分块系统据此决定该加载、卸载哪些地图块。这是性能优化的关键。

**为什么是骨架**：按需加载是大地图游戏的通用策略，换什么校园都需要。

**实现形态**：航拍中 `preloadChunksForCameraSequence` 预载沿途 chunk；航拍结束 `loadChunksForCamera`；平时相机跟随触发分块更新（归 SYS-CHUNK）。

#### 骨架 5：像素稳定性

**大白话**：画面不会有微小的抖动或模糊——通过像素取整和固定帧步长来保证。

就像你把照片打印出来——像素必须整整齐齐，不能有半个像素的偏移。相机的搞定稳定性靠两招：`roundPixels=true`（坐标像素取整，消除子像素抖动）+ `physics.world.setFPS(30)` + `fixedDelta=true`（物理固定 30 帧步长，消除帧率波动带来的抖动）。

**为什么是骨架**：画面稳定是所有相机的刚需，换什么游戏都需要。

**实现形态**：`roundPixels=true` + `setRoundPixels(true)` + `setFPS(30)` + `fixedDelta=true`。

### 二、皮（跟 Peter 项目绑定的东西）

| 皮 | 当前值（Peter 项目） | 换成其他校园会怎样 |
|---|---|---|
| 跟随方式 | lerp=1 硬跟随（逐帧瞬时贴住，无平滑） | 可以改成 lerp=0.1 平滑跟随，镜头有"惯性" |
| 地图边界 | (0, 0, 2240, 2240)，2240 = 140格×16px | 地图变大变小，边界跟着变 |
| 缩放 | zoom=1，不放大不缩小 | 可以加缩放（zoom=2 放大看） |
| 偏移与死区 | offset(0,0)、deadzone(0,0)——角色永远正中 | 可以设 deadzone，角色走一段镜头才动 |
| 航拍点 | 6 个点，每点坐标/飞行时长/停留时长都写死 | 换成不同校园的预设飞行路线 |
| 航拍时长 | 约 111 秒（7+22+20+20+22+20） | 可缩可放 |
| 返回玩家动画 | tween 3 秒 Power2 缓动落回 | 可以 1 秒 snap 或者 5 秒平滑 |
| 物理帧率 | 30 FPS fixedDelta | 可以 60 FPS（但会影响手感） |
| nativeScale | 设备像素比（运行时注入，非相机参数） | 不同设备自动不同 |

## 跟谁接口（它和谁打交道）

```
                         出 → 玩家只读位置 (x, y)
      [SYS-CAMERA 相机] ────────────▶ [SYS-PLAYER 玩家]
              │                      （镜头跟位置走）
              │
              │  出 → 相机可见范围
              └───────────▶ [SYS-CHUNK 地图分块]
              │               （该加载哪几块？）
              │
              │  出 → 锁输入
              └───────────▶ [SYS-INPUT 输入]
              │               （航拍期间隐藏摇杆）
              │
              │  后处理管线（HeatHaze/Fire/Morph）
              └───────────▶ [SYS-LAYER / SYS-FX]
                              （归对应系统，相机只管安装）
```

相机是**玩法线最后的一环**——它消费玩家的位置、驱动分块加载、控制输入锁定。它自己只管"看"。

## 容易踩的坑

| 坑 | 为什么坑 |
|---|---|
| 把 lerp=1 写成"平滑跟随" | lerp=1 是硬跟随，逐帧瞬时贴住，没有任何平滑。如果理解层写成"平滑跟随"，代码就会做成带缓动的，跟原站不一致——手感完全不同 |
| 忘设边界 | 没调用 `setBounds`，相机可以跟着玩家看出地图外——看到黑边或图外的垃圾数据 |
| 开场航拍和正式跟随切换错误 | 航拍时用的是 `stopFollow()` + 手动设 scroll X/Y，结束航拍必须 `startFollow()` 恢复。如果切错，航拍后相机不跟玩家 |
| roundPixels 没开 | 相机会出现子像素偏移——画面在某些位置微微模糊或抖动，非常难看但不明显，容易被忽略 |
| nativeScale 当成相机参数写死 | nativeScale 是设备像素比（DPR），运行时注入的。如果写死 1 或 2，高清屏上模糊/性能差 |
| 后处理管线没 try/catch | 后处理（HeatHaze/Fire/Morph）安装可能失败。原站用了 try/catch ——如果没兜底，后处理挂了整个游戏可能崩 |

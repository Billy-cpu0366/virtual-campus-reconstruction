# 玩家（SYS-PLAYER）—— "你在游戏里的分身"

> 📌 进度：📐 画好图纸 —— 出生点+深度+状态机+换装已定稿；执行层逆向数据齐备

---

## 一句话讲清楚

**玩家系统 = 管着"你"这个角色长什么样、从哪来、会做哪些动作、什么时候能控制他。**

就像你去游乐园——你本人是站在园里的，但游戏里需要一个"虚拟的你"。这个虚拟的你有固定的出生位置，会走路、会发呆、会坐下打瞌睡、走到沙滩会换泳装、被怪物抓了会变"被拎着"的样子。玩家系统管的就是这个"虚拟的你"的一切外观和行为。

---

## 它管哪些事

| 管的事 | 大白话 | 不管的事 |
|---|---|---|
| 外观 | 角色长什么样——48×48 的小人，8 个方向每方向 8 帧动画 | 不负责画质和渲染——那是 Phaser 引擎的事 |
| 出生 | 游戏开始你在哪——固定出生在 (1088, 304) | 不负责传送——那是区域触发的事 |
| 深度 | 你走下面时被建筑挡住、走上面时挡住建筑，靠 depth 实现 | 不负责建筑的深度——那是图层系统的事 |
| 动画状态 | 走路播走路动画、发呆播小动作、坐下冒 Z、换装脱衣服 | 不负责走路被墙挡住时停动画——那是移动系统的事 |
| 控制权限 | 开场动画中不能动、换装中不能动、被怪物抓了不能动 | 不负责"能不能往这走"——那是移动系统的事 |

## 🎨 核心：皮与骨架拆分

> **骨架** = 换什么校园都不变的做事方式
> **皮** = 跟 Peter 这个具体项目绑定的内容
> **配置点** = 将来后端管理系统可以改的参数

---

### 一、骨架（换什么校园都不变的东西）

#### 骨架 1：精灵表动画映射

**大白话**：一张大的角色图片，切成 64 个小格子，每个格子是一帧动画。8 个方向 × 每个方向 8 帧 = 64 帧。

就像翻页动画书——你快速翻页，小人就动起来了。游戏里所有角色动画都是这么做的：一张大图（精灵表）切成若干帧，按顺序播放。这个"切帧→播放"的机制是通用的，不管角色是学生、老师还是保安。

**为什么是骨架**：精灵表动画是 2D 游戏的基本功，换什么校园、换什么角色都这么干。

**实现形态**：Phaser `anims.create` 从 `player` 纹理创建 8 个动画（每个方向一个），每动画 8 帧，`frameRate: 10`。

#### 骨架 2：动画状态机

**大白话**：角色在"走路""发呆""坐下""换装""被抓"这几种状态之间切换，每种状态下播不同的动画。

就像你一天的生活——上班时是"工作状态"，午休是"吃饭状态"，下班是"回家状态"。你不会同时吃饭和开会。角色也一样：走路时不会同时坐下，换装时不会同时走路。状态机就是管"什么时候可以切到什么状态"的东西。

**为什么是骨架**：状态机是所有游戏角色的标配——不管角色是谁，他都有自己的状态和切换规则。

**实现形态**：`preUpdate` 每帧检查 `lastMovementTime` 和特殊标志（`isSitting`、`isChangingClothes`、`isGrabbed`），按优先级切换状态和动画。

#### 骨架 3：动态深度

**大白话**：角色走到画面下半部分时 depth 变大（被建筑挡住），走到上半部分时 depth 变小（挡住建筑）。

就像你站在一栋楼前面——你离楼越近，楼挡住你的部分越多。在俯视角游戏里，depth 跟 y 坐标挂钩，`500 + y × 0.1`：y 越大（越往下），depth 越大，渲染顺序越靠前，就被后面的东西挡住。不是写死的固定值。

**为什么是骨架**：动态深度是俯视角游戏实现遮挡的标准方法，换什么场景都靠这个。

**实现形态**：`createPlayer` 里 `player.setDepth(500 + player.y * 0.1)`；每帧 y 变 depth 跟着变。

#### 骨架 4：空闲超时

**大白话**：你太久没操作，角色自己动起来——做小动作、坐下。让角色不呆板。

就像你等公交——站久了会换换重心、掏出手机看看、或者蹲下来。游戏角色也一样，如果一直不动会很假。"30 秒坐下、8 秒小动作"这种空闲行为是让角色"活"起来的通用手法。

**为什么是骨架**：避免角色呆如木桩是所有游戏都要解决的问题。具体动作可以换，但"不动太久要有反应"这个机制是通用的。

**实现形态**：`preUpdate` 里 `now - lastMovementTime` 比较——`≥30000ms` 触发坐下，`≥8000ms` 触发随机空闲动画（eating/scratching/tying-shoe 三选一）。

#### 骨架 5：控制门

**大白话**：有些时候你不能操作角色——开场动画中、换装中、被怪物抓了。能让你动的时候才把控制权给你。

就像你坐过山车——上车时安全杠锁住，下车时才解锁。游戏里也一样：开场动画没放完，你再怎么按键盘角色也不动；换衣服脱到一半，不能边走边脱。控制门就是一把"锁"，锁上了任何输入都不管用。

**为什么是骨架**：所有游戏都需要"有时候不让玩家操作"，比如过场动画、加载、死亡。这个锁机制是通用的。

**实现形态**：`setUseControls(bool)` 控制——初始化 `false`，开场动画/传送完成后 `true`；换装中 `isChangingClothes=true` 时 setVelocity(0,0)；被抓时 `isGrabbed=true` 停一切。

### 二、皮（跟 Peter 项目绑定的东西）

| 皮 | 当前值（Peter 项目） | 换成其他校园会怎样 |
|---|---|---|
| 出生点 | (1088, 304) | 改一个坐标，角色出现在别的地方 |
| 角色精灵表 | `player` 纹理，64 帧（8方向×8帧），48×48 | 换成学生/老师的精灵表，帧数可不同 |
| 动画帧率 | frameRate = 10 | 可调快或调慢 |
| 深度公式 | `500 + y × 0.1` | 基值 500 和系数 0.1 可以按新地图调整 |
| 空闲动作 | 吃饭 / 抓痒 / 系鞋带（三选一） | 换一套动作，比如看书、玩手机、伸懒腰 |
| 空闲时间 | 8 秒做小动作，30 秒坐下 | 可调——比如 10 秒、60 秒 |
| 换装参数 | 沙滩自动触发，脱/穿动画，48×48 ↔ 64×64 | 不同的地点、不同的换装动画和尺寸 |
| 泳装精灵表 | `player-beach`（64 帧，48×48） | 换一套泳装/便装，尺寸可不同 |
| 被怪抓贴图 | `player-holding`，64×64 | 换一个被警察抓/被老师拎走的贴图 |

## 跟谁接口（它和谁打交道）

```
                        出 → 位置 (x, y)
      [SYS-PLAYER 玩家] ───────────┬──────────▶ [SYS-CAMERA 相机]
              │                    │            （相机跟着位置走）
              │                    │
  入 ← 方向   │                    └──────────▶ [SYS-MOVE 移动]
  入 ← blocked│                                   （位置变化 + 碰撞反馈）
              │
              │  深度参与遮挡排序
              └──────────────────────────────▶ [SYS-LAYER 图层]
                                                 （500 + y × 0.1）

  控制门锁 ← [SYS-CAMERA] 航拍期间
  换装触发 ← [SYS-LAYER] 踩到 walls 层 GID 69353（沙滩块）
```

玩家系统是**玩法线的中心节点**——输入、移动、相机都围着它转。但它自己只管外观和状态，不碰碰撞、不碰相机跟随、不碰输入设备。

## 容易踩的坑

| 坑 | 为什么坑 |
|---|---|
| 深度写成固定值 | 如果 `setDepth(600)` 写死不更新，角色走到地图下方时不会被建筑挡住——看起来像在屋顶上飘。必须每帧根据 y 更新 |
| 8 方向写成 4 方向 | 原站是完整的 8 方向（含四个斜角），不是只要上下左右。如果只做 4 方向，斜着走的动画会跳变 |
| 换装动画没加载就卡住 | 换装靠 `animationcomplete` 事件切状态。如果脱/穿衣动画不存在，这个事件永远不会触发——角色永远卡在"换装中"，不能动。本 CORE 用 `skipClothingChange()` 兜底：动画不存在就跳过动画直接切贴图 |
| 空闲时间不重置 | 每次移动后 `lastMovementTime` 必须重置。如果忘了，角色走一步就坐下——因为系统以为他 30 秒没动了 |
| 控制门没堵死 | 开场动画中如果键盘还能动，玩家可能在航拍中乱跑。`setUseControls(false)` 必须关掉速度 + 屏蔽所有输入 |
| 双精灵结构 | 原站玩家是两个 sprite——物理体不可见（只撞墙）、visualSprite 负责显示（切换贴图不碰碰撞体）。如果只用一个 sprite，换装/被抓时碰撞体跟着变，可能出诡异的行为 |

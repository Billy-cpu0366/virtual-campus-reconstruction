# 动效与粒子（SYS-FX）—— "校园的气氛组"

> 📌 进度：📐 画好图纸 —— 4 类特效（工厂烟、脚印、橙雾、Stop AI 烟雾）全部落实

---

## 一句话讲清楚

**动效系统 = 让校园有"空气感"的细节。没有它，校园画面是干净的但也是死的——工厂烟囱不冒烟、走过沙地不留脚印、抗议区没有烟雾弹。它不改变任何玩法逻辑，纯粹是视觉上的"氛围感"。**

你去游乐场——过山车轨道旁有干冰烟雾、小吃摊冒着热气、地上有别人踩过的痕迹。这些东西不影响你能不能玩过山车，但没了它们，游乐场就像一个刚搭好的舞台布景，没有"运营中"的感觉。动效系统做的就是这件事。

---

## 它管哪些事

| 管的事 | 大白话 |
|---|---|
| 工厂烟雾 | 工厂烟囱往外冒烟，烟粒子走抛物线上升，飘到一定高度就消失 |
| 脚印 | 玩家走过特定地面（沙地/标记区），脚下留下一串脚印，走远了脚印花 1 秒淡出消失 |
| 橙色轨迹雾 | 某个区域（S1 区域）被橙色烟雾笼罩，玩家走到哪，周围的烟就往后退——给玩家清出一块"安全视野" |
| Stop AI 烟雾弹 | 3 个罐子各冒 3 层烟（后层/中层/前层），烟往随机方向飘（模拟风力），不同罐子延迟启动，营造层次感 |

**它不管的事**：这些特效触发什么事件（它们不参与逻辑）、玩家碰到烟会怎样（纯视觉，不阻挡移动）、性能优化（由 Phaser 粒子引擎负责）。

## 🎨 核心：皮与骨架拆分

> **骨架** = 换什么校园都不变的做事方式
> **皮** = 跟 Peter 这个具体项目绑定的内容
> **配置点** = 将来后端管理系统可以改的参数

---

### 一、骨架（换什么校园都不变的东西）

#### 骨架 1：粒子系统固定生命周期

**大白话**：每个特效都有自己的生老病死 —— 启动（start）、每帧更新粒子位置（tick）、暂停/恢复（视图裁剪）、销毁（shutdown）。就像舞台特效组——导演喊"放烟"，烟机开始工作；喊"停烟"，烟机停止；喊"收工"，烟机关机。

**为什么是骨架**：任何粒子特效都需要"开启 → 运行 → 暂停 → 关闭"这套管理。换一个校园可能有不同的烟（彩色烟、泡泡、雪花），但生命周期管理逻辑不变。

**实现形态**：每个特效是一个 Runtime 类，统一提供 `start()`、`tick()`、`shutdown()`。工厂烟雾还有 `cull()`（根据视口暂停/恢复发射）。Stop AI 烟雾有 `setActive(boolean)` 来开关。

#### 骨架 2：核心逻辑与表现分离

**大白话**：烟雾"怎么飘"的规则在 `src/fx/`（纯数学——抛物线公式、风力方向、区域多边形），"烟长什么样"在 `game/`（Phaser 粒子发射器配置——颜色、透明度、粒子数量）。

**为什么是骨架**：同 NPC/ROUTE 的分层设计。规则可测试，表现可换引擎。

**实现形态**：`src/fx/factory-smoke.ts` → `FactorySmokeRuntime`（抛物线路径计算），`game/PhaserFactorySmokeRuntime.ts` → `PhaserFactorySmokeRuntime`（Phaser 粒子发射器）。其他特效同理。

#### 骨架 3：对象池复用

**大白话**：脚印不是每踩一下就创建新对象——那样太浪费。而是预先创建 95 个脚印精灵，用的时候从池里拿，用完了还回去。就像餐厅的盘子——不是每个客人用一个新盘子，而是洗了循环用。

**为什么是骨架**：任何"高频率出现 + 消失"的东西（脚印、弹孔、火花、雨滴）都应该用对象池。换校园只换脚印的形状（沙子、雪地、泥地各有不同的印子），但池的管理逻辑通用。

**实现形态**：`game/PhaserFootstepRuntime.ts` 创建 95 个精灵组成的池，维护 `nextIndex` 游标（循环取用），每个脚印有 10 秒可见 + 1 秒淡出，到期后重置回池。

#### 骨架 4：区域触发与视口裁剪

**大白话**：特效不是全地图都在跑——工厂烟雾只在烟囱在屏幕里时才发射（省粒子开销），脚印只在特定地面上才出现，雾只在多边形区域内有效。就像舞台灯光——聚光灯只打舞台，不会照到观众席。

**为什么是骨架**：任何开放世界游戏都需要"只在需要的地方跑特效"来省性能。换校园只是换"哪些区域有烟、哪些地面有脚印、哪些地方有雾"，但"区域判断 + 视口裁剪"这套逻辑通用。

**实现形态**：工厂烟雾用 viewport + 100px padding 判断烟囱是否可见。脚印用 tile GID 判断当前地面是否该留脚印（`footstepTileIds.has(tileGid)`）。雾用 polygon 点集 + 格子分解 + `pointInPolygon` 判断。

#### 骨架 5：多层渲染 + 独立风力

**大白话**：Stop AI 烟雾不是一层——它有 3 层烟（远/中/近），每层独立的风向和粒子参数。这样做出来的烟有深度感和层次感，不是一张平面图。就像舞台上的干冰——地面雾、腰部雾、头顶雾各有自己的流动方向和浓度。

**为什么是骨架**：多层渲染是制造"体积感"的通用手法（雾、烟、云、水波都可以用）。换校园可能换层数、换颜色、换风向参数，但"多层 + 独立风力 + 延迟启动"的架构通用。

**实现形态**：`StopAiSmokeRuntime`（核心）管理 3 个 canister 各 3 层 = 9 组配置。`PhaserStopAiSmokeRuntime`（表现）为每层创建独立 Phaser 粒子发射器。每层有独立的风向（gravityX），定时随机切换。每个 canister 有随机延迟启动。

```
                        ┌──→ [世界与地图]    给它：特效实体（烟雾、脚印的位置数据）
[SYS-FX 动效系统]  ──┼──→ [玩家]           入它：玩家的位置（雾清除、脚印放置）
                        ├──→ [车辆与路线]     入它：警车位置（雾清除）

```

动效系统是**气氛组**——不参与玩法逻辑，只让世界"看起来在运转"。

## 容易踩的坑

| 坑 | 为什么坑 |
|---|---|
| 脚印池越界 | 95 个脚印用 `nextIndex` 循环取。如果所有脚印都还在显示（玩家一直在沙地上小碎步），新脚印会覆盖老脚印（主动 alpha 置 0 释放）。如果忘记检查"被覆盖的脚印是否在淡出"，脚印就会在淡出中途被突然"掐掉" |
| 沼泽陷阱 | 雾的复活时间是 500ms——但如果在 500ms 不重置 timers，一个被清除的格子可能永远不会重新冒烟。表现为：玩家扫过的地方永远不长烟了 |
| 粒子发射器泄漏 | 每个雾格子都有自己的粒子发射器。如果格子销毁时忘了 `stop()` + `remove()` 发射器，粒子继续发射但没格子接收，要么白算要么报错 |
| 视口裁剪只做了一层 | 工厂烟雾的裁剪基于烟囱是否在视野内。但烟囱在视野外 ≠ 烟也在视野外——烟可能飘得很高很远进入视野。原站选择了简单但省性能的方案：烟囱不在视野就暂停，潜在地"烟该看见时突然消失" |
| 脚印的 ground-hugging | 脚印放在 `playerY + 10` 像素处，但地面可能不平——在某些地形边缘，脚印会浮空或埋进地里。depth 检查 `playerDepth < 1000` 只能粗略过滤层内/层外 |
| 风向 UI 陷阱 | 烟雾罐的可视化渲染（canister graphics）用了 3-band 颜色编码，便于开发调试。正式发布时如果忘了关，玩家会看到"彩色罐子"而不是烟雾弹 |

> ✅ 已确认（SYS-FX）：4 类特效——工厂烟、脚印、橙轨迹雾、Stop AI 烟雾弹。各特效核心逻辑在 `src/fx/`，Phaser 适配在 `game/Phaser*Runtime.ts`。脚印用 95 精灵对象池。雾用格子分解 + 玩家/车辆清除 + 500ms 复活。烟雾弹 3 罐 × 3 层 + 独立风力。

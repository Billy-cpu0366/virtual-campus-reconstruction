# 车辆与路线（SYS-ROUTE）—— "校园里的交通工具"

> 📌 进度：📐 画好图纸 —— 车辆类型/路线参数/碰撞全部落实

---

## 一句话讲清楚

**车辆路线系统 = 让校园里的大物件（火车、直升机、警车）按各自的规律动起来。它们不是 NPC——不会跟你互动、不会寻路、不会随机乱走。它们就像游乐场的固定设施：火车定点开、警车停着闪灯、直升机在天上转螺旋桨。**

你去迪士尼——小火车沿着铁轨定点来、定点走；警车停在路边；直升机在头顶盘旋。这些东西让你感觉"这个乐园在运营"，但它们的存在感来自"规律性"而不是"随机性"。车辆系统做的就是这件事。

---

## 它管哪些事

| 管的事 | 大白话 |
|---|---|
| 火车路线 | 火车从右边开进站 → 停一会儿 → 从左边开出。精确控制进站/停靠/离站时间 |
| 碰撞区域 | 火车经过时，在它周围生成"不可通行区"，挡住路过的 NPC |
| 静态车辆 | 警车停路边、直升机在天上——位置固定，但有自己的动画（螺旋桨转、灯光闪） |
| 生命周期通知 | 火车到站了/出站了/离开视野了，告诉其他系统（比如 NPC 系统知道火车来了要避让） |

**它不管的事**：车辆怎么画（归 Phaser 适配层）、NPC 怎么避让火车（归 NPC 系统自己的 `pauseGroup`）、玩家能不能上车（不能）。

## 走一遍（火车从进站到离开）

```
你打开网页 → 火车停在右边屏幕外
    │
    ├─ 某个时机（如开场动画结束），火车触发 start
    │
    ├─ 阶段 1：进站（5 秒）
    │   火车从屏幕右边 (x=2480) 缓缓开到站台 (x=480)
    │   用了 cubicEaseOut 缓动——先快后慢，像真的刹车
    │   沿路生成 4 块碰撞区域，跟着火车移动
    │
    ├─ 阶段 2：停靠（3 秒）
    │   火车停在站台，碰撞区域维持
    │   NPC 系统收到火车站台被占用的通知
    │
    ├─ 阶段 3：离站（9 秒）
    │   火车从站台加速开走，用 quadEaseIn 缓动——先慢后快
    │   火车离开屏幕视野后，触发 onLeaveViewport 回调
    │
    └─ 阶段 4：完成
        火车消失，碰撞区域清除
        NPC 系统收到"铁轨清空了"的通知
```

**直升机**：位置写死不动，但 5 个叶片的螺旋桨一直在转（转速 8），尾桨也在转。高分辨率贴图（scale=2），depth=600。

**警车**：3 辆停在固定位置，带有碰撞体（64×48 px），玩家不能穿过去。

## 🎨 核心：皮与骨架拆分

> **骨架** = 换什么校园都不变的做事方式
> **皮** = 跟 Peter 这个具体项目绑定的内容
> **配置点** = 将来后端管理系统可以改的参数

---

### 一、骨架（换什么校园都不变的东西）

#### 骨架 1：固定路线 + 分阶段状态机

**大白话**：火车的运动是一条流水线，每个阶段做的事不同——进站（慢慢刹车）、停靠（纹丝不动）、离站（加速走人）、完成（消失）。就像电梯：按楼层 → 关门 → 运行 → 开门，流程固定，时间固定。

**为什么是骨架**：不管哪个校园，火车（或类似的沿固定路线移动的大型实体）都需要 "进 → 停 → 出" 三阶段。换一个校园可能有不同路线，但阶段概念和状态机逻辑不变。

**实现形态**：`TrainRouteRuntime` 是一个纯逻辑状态机，状态包括 `idle → arriving → holding → departing → complete`，每个阶段有精确的时刻表（起始时间 + 持续时间），位置用缓动公式插值。

#### 骨架 2：碰撞区随实体移动

**大白话**：火车不是一个点，它是一长条。当它移动时，会在地面上投射出"不可通行区域"——这些区域由格子坐标组成，其他系统（NPC、路径）查询这些格子就能知道"这里不能走"。

**为什么是骨架**：任何大型移动实体（火车、飞船、游行车队）都需要告诉其他系统"我现在占了哪些格子"。换校园只是换碰撞区的尺寸和位置，但"随实体移动 + 格子化 + 通知外部"这套机制是通用的。

**实现形态**：`TrainRouteRuntime.collisionRects` 根据当前 x 坐标实时计算 4 个碰撞矩形，把矩形覆盖的格子坐标（`tileX,tileY`）压平成字符串数组。外部通过 `setTrainBlockingZone(cells)` 接收入口，随时查询"某个格子是不是被火车占了"。

#### 骨架 3：核心逻辑与表现分离

**大白话**：火车"什么时候该到哪"的规则写在 `src/route/` 里（纯数学），"火车长什么样"写在 `game/` 里（Phaser 精灵）。警车和直升机的"位置和碰撞体"写在 `src/route/` 里，"螺旋桨转多快"写在 `game/` 里。

**为什么是骨架**：同 NPC 系统。规则不依赖引擎，可测试，可换引擎。

**实现形态**：`src/route/train.ts` 的 `TrainRouteRuntime` 纯逻辑，`game/PhaserTrainRuntime.ts` 的 `PhaserTrainRuntime` 适配层。火车表现层通过 `*Like` 接口（`PhaserTrainSceneLike`、`PhaserTrainSpriteLike` 等）接入 Phaser。

#### 骨架 4：事件驱动的外部通知

**大白话**：火车不是孤立运行的——它到站了要告诉 NPC 系统"兄弟们让一让"，它离开视野了要通知场景"可以播放下一段了"。就像火车站的广播系统——火车进站/出站/晚点，喇叭自动播报，各岗位听到后各干各的。

**为什么是骨架**：任何大型实体都需要向外部系统广播自己的状态变化。换校园只是换"谁在听广播"（不同 NPC 配置），但"火车发广播"的机制不变。

**实现形态**：`PhaserTrainRuntime` 支持多个回调：`onDeparture`（开始离站）、`onLeaveViewport`（离开当前视野）、`onComplete`（走完全程）。表现层通过 viewport 检测判断火车相对于当前视野的位置，精确触发。

#### 骨架 5：静态实体 + 动态动画

**大白话**：警车和直升机位置是死的，但它们不是死图片——螺旋桨在转、尾桨在转，有"活着"的感觉。这跟 NPC 不同：NPC 是整个对象在移动；静态车辆是对象不动，但零件在动。

**为什么是骨架**：任何校园都需要"装饰性动态实体"——停在路边的车、旋转的广告牌、晃动的旗帜。它们的位置写死，但动画独立运行。

**实现形态**：`PhaserVehicleRuntime` 管理 1 架直升机 + 3 辆警车。直升机=主螺旋桨(5 叶片)+尾桨+高分辨率机身，持续旋转。警车=精灵+碰撞体，位置写死。

### 二、皮（跟 Peter 项目绑定的东西）

| 皮 | 当前值（Peter 项目） | 换成其他校园会怎样 |
|---|---|---|
| 车辆类型和数量 | 1 辆火车 + 1 架直升机 + 3 辆警车 | 换成游船、货车、缆车等 |
| 火车进站时间 | 5,000 ms（5 秒） | 可调 |
| 火车停靠时间 | 3,000 ms（3 秒） | 可调 |
| 火车离站时间 | 9,000 ms（9 秒） | 可调 |
| 火车路线起终点 | 起点 x=2480，站台 x=480，离站终点 x=-3520 | 换站台位置 |
| 火车 y 坐标 | y=310 | 不同高度地形会变 |
| 火车碰撞区域 | 4 段矩形（left 0~365 / 360~720 / 715~1078 / 1073~1435），top=323，bottom=359 | 换火车尺寸或站台尺寸 |
| 火车缓动曲线 | 进站 cubicEaseOut（先快后慢），离站 quadEaseIn（先慢后快） | 可换其他缓动曲线 |
| 直升机螺旋桨 | 5 叶片，转速 8，scale=2，depth=600 | 不同机型不同参数 |
| 警车碰撞体 | 64×48 px，depth=560 | 换车尺寸 |

## 跟谁接口（它和谁打交道）

```
                        ┌──→ [NPC 系统]      给它：碰撞区的阻挡格子（让 NPC 避开铁轨）
[SYS-ROUTE 车辆系统] ─┼──→ [场景管理]      给它：火车生命周期事件（离站/离开视野）
                        ├──→ [世界与地图]    给它：火车/直升机/警车的实体数据
                        ├──→ [资源加载]      找它：火车/直升机/警车的精灵图
                        └──→ [图层与遮挡]    用它：车辆的深度值
```

车辆系统是**连接 NPC 系统和场景叙事的枢纽**——火车进出站不仅是画面效果，还影响 NPC 的路径行为。

## 容易踩的坑

| 坑 | 为什么坑 |
|---|---|
| 火车碰撞更新频率 | 每帧都重新计算碰撞格子，然后和上一帧比较（`lastCells`）。如果忘记比较就去通知外部，等于每帧都触发 blocking zone 刷新——外部系统被刷爆 |
| 离站视口检测 | 火车离站后要判断"它还在不在玩家视野里"来触发 `onLeaveViewport`。但玩家可能跟着火车跑——所以逻辑是"要先进过视野（departureWasInViewport=true）再出视野"，不能一离站就触发 |
| 缓动曲线混用 | 进站用 cubicEaseOut（模拟刹车），离站用 quadEaseIn（模拟加速）。如果用反了，火车到站会猛停、离站会先蹿一下——看起来像 bug |
| 直升机旋转资源 | 主螺旋桨和尾桨是两个独立精灵，各自旋转。如果它们的深度值搞混，螺旋桨会遮住机身或尾桨飞到机身前面 |
| 碰撞区域映射 | TRAIN_COLLISION_X_ZONES 是"相对于火车 sprite 左上角的偏移"，实际碰撞位置 = 火车 x + 偏移 × collisionScale。如果 collisionScale 不对，碰撞区就跑偏了 |

# 资源加载（SYS-ASSET）—— "工地的物流大队"

> 📌 进度：📐 画好图纸 —— 失败/缓存已定稿；浏览器 HTTP 缓存仍未确认

---

## 一句话讲清楚

**资源加载系统 = 把服务器上的文件运到浏览器里，让后续系统有料可用。**

你打开游戏看到的每一张图片、每一块地图、每一个走路的小人——它们都不是凭空出现的。浏览器必须先**从远处的服务器把这些文件下载回来**，才能显示给你看。谁负责这件事？就是资源加载系统。

---

## 它管哪些事

| 管的事 | 大白话 |
|---|---|
| 加载 | 负责把所有"原材料"（图片、地图数据、小人动画）从服务器拉回来 |
| 进度 | 实时告诉我"下载到百分之多少了"，让进度条有东西可画 |
| 失败 | 货拉不回来怎么办？原站的做法是：吼一嗓子（打日志），然后就不管了 |
| 缓存 | 下载完要不要存起来，下次直接用？原站不存，每次都重新下 |

**它不管的事**：下载完把数据交给下游，之后怎么把这些数据画到屏幕上、怎么让小人动起来——这些不归它管。

## 🎨 核心：皮与骨架拆分

> **骨架** = 换什么校园都不变的做事方式
> **皮** = 跟 Peter 这个具体项目绑定的内容
> **配置点** = 将来后端管理系统可以改的参数

---

### 一、骨架（换什么校园都不变的东西）

#### 骨架 1：一条固定的"流水线"

**大白话**：游戏从"还没开始"到"可以玩了"，中间要经过的步骤是固定的。

就像你去餐厅吃饭：
```
进门 → 看菜单 → 点菜 → 等上菜 → 开吃
```
不管你去川菜馆还是日料店，这个流程都是一样的。

游戏也一样：
```
启动 → 开始下载 → 下载中 → 下载完了 → 可以玩了
```

不管这个校园是 Peter 的、还是某学校的、还是某公司的，流程都是这一条。不同的只是"菜单上有什么菜"（下载什么资源）。

#### 骨架 2：实时告诉你"下载到多少了"

**大白话**：下载过程中不断告诉进度条"我现在到 50% 了""到 80% 了""到 100% 了"。

就像快递 app 告诉你"包裹已到达分拣中心 → 已出发 → 派送中 → 已签收"。每个校园都需要一个进度条，所以这个"实时汇报进度"的能力是通用的。

#### 骨架 3：图片和数据分开运输

**大白话**：地图图片和地图数据，走两条不同的路下载。

为什么？因为它们的用途不一样：
- **图片**（地图外观、小人动画）→ 要给游戏引擎用来画到屏幕上，必须走引擎自带的下载通道
- **纯数据**（地图坐标、碰撞信息）→ 不需要引擎处理，用浏览器最普通的下载方式就行，更快

就像快递：大件家具走物流公司，一份文件走顺丰。不是同一批货，没必要挤一辆车。

#### 骨架 4：不写死要下载什么，而是"读清单"

**大白话**：代码里不写"下载第1块、第2块、第3块……第16块"，而是读一份 JSON 文件，按上面的清单逐个下载。

为什么？因为如果写死了"16 块"，将来换一个校园只有 9 块怎么办？改代码很麻烦。

如果改成"读清单"，就变成了：
- 代码：去读一份清单 → 清单上写了什么就下载什么
- 换校园时：换一份清单就行，代码一个字不动

就像你去超市买东西，不是脑子里背"我要买牛奶、鸡蛋、面包"，而是照着一张购物清单拿。下次买不同的东西，换张清单就行。

#### 骨架 5：可以随时"取消"和"清理"

**大白话**：加载到一半不想玩了（比如关了网页、按了返回），系统要知道怎么"收摊"。

- **取消**：点了 Retry 按钮 → 上一次的下载就别继续了，作废
- **清理**：关了网页 → 所有下载中的请求全部停掉，占的内存全部释放
- **重试**：加载失败了 → 清理干净旧的，重新来一遍

每个校园都会遇到"用户不想等了"的情况，所以这套"取消 → 清理 → 重来"的能力是通用的。

### 二、皮（跟 Peter 项目绑定的东西）

| 皮 | 当前值（Peter 项目） | 换成其他校园会怎样 |
|---|---|---|
| 要下载哪些文件 | `exterior-final.webp`、`player.webp`、`walls-layer.json` 等 | 换一套完全不同的图片和数据文件 |
| 图片和数据各占多少进度 | 图片 72%，数据 28% | 占比会变，比如图片多的校园，图片占比更高 |
| 下载失败怎么办 | 只打一行日志，不重试、不补救 | 可以改成重试 3 次 / 弹窗提示 / 放一张灰色占位图 |
| 要不要缓存 | 不缓存，每次重新下载 | 可以改成存进浏览器，下次秒开 |
| 切块清单从哪读 | `final_map_small.json` 里的 `tilesets` 字段 | 换校园 = 换一份元数据文件 |

```
                        ┌──→ [世界与地图]  给它：地图底图、地图数据
[SYS-ASSET 资源加载] ──┼──→ [图层与遮挡]  给它：24层的渲染素材

```

资源加载是**整个地图线的起点**——它不干活，后面所有系统都等着干瞪眼。

## 容易踩的坑

| 坑 | 为什么坑 |
|---|---|
| 瓦片集不完整 | 完整的地图有 6.9 万个格子，但原站只公开了一部分，要反推缺了哪些 |
| 两条运输线混用 | 图片走引擎通道、数据走普通通道，它们的"关闭方式"不一样——引擎的自动关，普通通道要手动关。忘了手动关会内存泄漏 |
| 进度合并不对 | 图片和数据各自报进度，合并成一根进度条时比例不对，会出现"卡在 99% 不动"的诡异现象 |
| 一个文件挂了拖垮全局 | 某个资源下载失败，如果下游系统没做防护，可能整个游戏白屏 |

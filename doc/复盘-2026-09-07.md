## 4. 全周期最值得复盘的 4 个认知升级

### 4.1 整体大目标从来没换过——只分层落地（最大的一次认知纠错）

- **整体大目标**（9-7 User 明确复述）：逆向 + 后端 + 后台 + 换皮做各校园网站。
- **Phase 1（当前）**：逆向 + 复刻验证 + 骨架准备。
- **Phase 2（远期）**：在 Phase 1 骨架上补后端、后台、换皮能力。

**复盘自己的错误**：第一版复盘里我把"加后端+换皮"读成"被悄悄丢掉的目标"，还说"项目经历了一次目标重定位"——这是错的。User 立刻纠错后我才意识到：

- "Phase 1 边界"里写"最终虚拟校园业务、后台管理和多人在线不在范围"——指的是 Phase 1 不做，**不是项目不做**。
- 16 系统卡 + 写作规范 + CORE/完整系统分层 = **为 Phase 2 换皮提前准备的骨架**。

8 个 CORE 不是按"通用模块"提前设计的，是按"原站确认行为 → CORE 范围 → 真实实现 → 测试"反复走出来的。每一份 CORE 授权书都明确写"实现什么 + 不实现什么"。

### 8.3 复盘结论

这一段（Phase 1 完整周期 + 9-1 大文档重写）最值得记的有 3 件事：

1. **整体大目标从来没换过——只是分阶段执行**。整体大目标是"逆向 + 后端 + 后台 + 换皮做各校园网站"；Phase 1 只做逆向 + 复刻 + 骨架准备；Phase 2 才做后端、后台、换皮。**这是分层，不是换目标**。判断标准：去掉"Phase 1/2"前缀后，剩下的整体方向是否一致。本复盘第一版把"换皮目标"误读为"被悄悄丢掉"，是分阶段 vs 换目标混淆的典型错误——已存进 memory 防止再犯。

2. **CORE 通过 ≠ 集成通过 ≠ 完整系统通过**。3 层分层（纯逻辑 → 真实集成 → Human 视觉验收）必须保持清晰，不能用"CORE 写完"冒充"系统做完"。这一分层也是"骨架/皮可分离"的前提——CORE 是骨架的最小单元，集成是接上 Phaser/Vite/网络等"皮层"；Phase 2 换皮时只动"皮"那一层。

3. **协作模式会反复变，但协议不能绑死**。从单人 → 多人 → 多人并行 → 6 个 AI 并行写文档 → 单人 + WSL 沙箱中转——协议每次都要在 AGENTS.md 留"现在是这样"的明确痕迹，但不删除旧痕迹（旧 PR 流程规则保留，只是当前不触发）。

下一步的关键是**按整体大目标分层推进**，当前仍在 Phase 1 阶段：

**Phase 1 收尾**（按整体大目标的第一阶段）：

## 一、骨架落地

### 骨架 1：精灵表动画映射

> 理解层的人话：一张大图切成 64 个小格子，8 方向 × 8 帧循环播放。
> 在代码里，这东西就是 **Phaser anims.create + 帧范围定义**。

**它怎么工作的**：
`player` 纹理是一张精灵表，总共 64 帧。8 个方向各占连续 8 帧：
- east [0-7]、north-east [8-15]、north-west [16-23]、north [24-31]
- south-east [32-39]、south-west [40-47]、south [48-55]、west [56-63]
- idle 默认帧 = 第 48 帧（south 的首帧）

每个方向创建一个 Phaser animation：`walk-{方向名}`，循环播放，`frameRate = 10`。方向名由 SYS-INPUT 的 8 方向字符串提供（north / south / east / west 等）。

原站玩家有两个 sprite——物理体（不可见，只撞墙）和 visualSprite（负责显示外观）。显示切换在 visualSprite 上做，不影响碰撞体。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| 帧映射定义 | `src/player/appearance/` | 8 方向帧范围表 |
| 动画创建 | `game/CampusScene.ts` | `anims.create({key:"walk-...", frames:..., frameRate:10})` |
| 原站动画创建 | `sample/.../chunk-WMFY56ZM.js` | `Ue` / `xe` / `Fi` 函数 |

**怎么验证它做对了**：
- 单元测试：`tests/player/appearance/` —— 帧范围映射与方向名一一对应
- 浏览器 Smoke：各方向走动时动画正确播放、帧序不跳

### 骨架 2：动画状态机

> 理解层的人话：走路、发呆、坐下、换装、被抓——状态之间互斥。
> 在代码里，这个东西就是 **preUpdate 里的状态分支 + 互斥标志**。

**它怎么工作的**：
每帧 `preUpdate` 按优先级检查状态：

1. **被抓（最高优）**：`isGrabbed=true` → 停所有动画 + visualSprite 切 `player-holding` + `setDisplaySize(64,64)`
2. **换装中**：`isChangingClothes=true` → `setVelocity(0,0)`（不能动）+ 播脱/穿动画等 `animationcomplete`
3. **坐下中**：`isSitting=true` → sleep 粒子 Z 跟随 + 等移动时 `standUp`
4. **走路中**：有方向输入且未被挡 → `play("walk-{方向}")`
5. **空闲**：无输入 → 检查超时，触发小动作或坐下

空闲动画 3 种随机选（排除上一个）：`eating` / `scratching` / `tying-shoe`。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| 动画状态契约 | `src/player/` | `PlayerStatus` 类型 |
| 空闲状态 | `src/player/idle/` | `IDLE_ANIMATIONS`, `IDLE_TIME_FOR_EATING/SITTING` |
| 朝向状态 | `src/player/facing/` | `getFacingDirection()` → `lastRequestedDirection \|\| "south"` |
| 换装状态 | `src/player/clothing/` | 尺寸切换 `48×48 ↔ 64×64`，冷却 1000ms |
| 运行时 preUpdate | `game/CampusScene.ts` | 每帧状态分支 + 动画播放 |
| 原站证据 | `sample/.../chunk-WMFY56ZM.js` | 玩家类 `$e` 的 `preUpdate` |

**怎么验证它做对了**：
- 单元测试：`tests/player/idle/`、`tests/player/facing/`、`tests/player/clothing/` —— 各状态阈值与切换逻辑
- BASE-PLAYER-003：动画状态机可复现

### 骨架 3：动态深度

> 理解层的人话：depth 跟 y 坐标走，越往下 depth 越大。
> 在代码里，就是 **setDepth(500 + y × 0.1)，每帧更新**。

**它怎么工作的**：
`createPlayer` 里初次设置 `setDepth(500 + player.y * 0.1)`；构造里的 `setDepth(600)` 只是初始值，会被覆盖。

原站事实：`500 + y * 0.1`（`chunk-WMFY56ZM.js`）。
重构决定：采用 SYS-LAYER 已接受的 `500 + (y + 24) * 0.1`。

深度随玩家 y 坐标实时变化——走到地图下部 depth 变大（被建筑遮挡），走到上部 depth 变小。不写死固定值。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| 原站深度公式 | `sample/.../chunk-WMFY56ZM.js` | `setDepth(500 + player.y * 0.1)` |
| 重构深度公式 | `game/CampusScene.ts` | `500 + (y + 24) * 0.1`（SYS-LAYER SSOT） |
| 深度更新时机 | `game/CampusScene.ts` | `preUpdate` 每帧或 y 变化时 |

**怎么验证它做对了**：
- BASE-PLAYER-001：动态深度可复现
- 浏览器 Smoke：走到建筑下方被遮挡、走到建筑上方遮挡建筑

### 骨架 4：空闲超时

> 理解层的人话：太久没动角色自己玩起来。
> 在代码里，就是 **`now - lastMovementTime` 比较两个阈值**。

**它怎么工作的**：
`preUpdate` 里每帧读 `Date.now() - this.lastMovementTime`：
- `≥ 30000ms`（30 秒）且未坐下 → `playSittingAnimation()`：`isSitting=true`，播 sitting 动画，sleep 粒子 Z 跟随
- `≥ 8000ms`（8 秒）且未坐下 → 随机选一个空闲动画（从 `IDLE_ANIMATIONS` 里挑，排除上一个播过的）

移动后 `lastMovementTime` 重置为当前时间，站立站起时 `standUp` 清 `isSitting` 并恢复走路帧。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| 空闲阈值常量 | `src/player/idle/` | `IDLE_TIME_FOR_EATING = 8000`, `IDLE_TIME_FOR_SITTING = 30000` |
| 空闲动画池 | `src/player/idle/` | `IDLE_ANIMATIONS = ["eating","scratching","tying-shoe"]` |
| 运行时超时检测 | `game/CampusScene.ts` | `preUpdate` 里 `now - lastMovementTime` 比较 |
| sitting 实现 | `game/CampusScene.ts` | `playSittingAnimation`：Z 粒子，`standUp` 恢复 |
| 原站证据 | `sample/.../chunk-WMFY56ZM.js` | `preUpdate`、`playSittingAnimation`、`standUp` |

**怎么验证它做对了**：
- 单元测试：`tests/player/idle/` —— 阈值触发、动画排除重复、移动后重置
- BASE-PLAYER-003：动画状态机可复现

### 骨架 5：控制门

> 理解层的人话：有些时候不让玩家操作。
> 在代码里，就是 **`setUseControls(bool)` 开关 + `isChangingClothes`/`isGrabbed` 互斥标志**。

**它怎么工作的**：
初始化 `setUseControls(false)`——创建玩家后立即锁住。
- 开场火车动画完成（`isPlayerIntroComplete=true`）或传送完成 → `setUseControls(true)` 放行
- 换装中：`isChangingClothes=true` + `setVelocity(0,0)` → 不能动
- 被抓时：`setGrabbedByMonster(true)` → 停一切动画 + 锁操作
- 航拍期间：由 SYS-CAMERA 通过控制门锁住

`setUseControls` 关闭时清掉 idle 气泡等 UI 元素。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| 控制门契约 | `src/player/index.ts` | `useControls` 标志 |
| 运行时控制开关 | `game/CampusScene.ts` | `setUseControls(bool)` |
| 换装互斥 | `game/CampusScene.ts` | `isChangingClothes = true` |
| 被抓互斥 | `game/CampusScene.ts` | `setGrabbedByMonster(true)` |
| 原站证据 | `sample/.../chunk-WMFY56ZM.js` | `setUseControls`、`createPlayer` 初始 false |

**怎么验证它做对了**：
- BASE-PLAYER-004：控制启用时机可复现（开场锁、完成放）
- 浏览器 Smoke：开场动画中方向键无效

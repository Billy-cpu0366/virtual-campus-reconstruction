## 一、骨架落地

### 骨架 1：多源归一化

> 理解层的人话：不管来路是什么设备，最终都翻译成一种统一的"方向语言"。
> 在代码里，这个东西叫 **方向解析器（resolve module）**。

**它怎么工作的**：
键盘方向（cursors + wasdKeys）和摇杆方向（pointer forceX/forceY）各自先独立算出自己的 8 方向向量，然后交给 `resolveMovement` 统一选择一个输出。选择规则见骨架 3（优先级仲裁）。输出格式永远一致：`{dx, dy, direction}`——不管输入源是什么。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| 方向仲裁（选键盘还是摇杆） | `src/input/resolve/index.ts` | `resolveMovement` |
| 8 方向向量定义 | `src/input/direction/eight-direction.ts` | `EIGHT_DIRECTIONS` |
| 键盘读键→方向 | `src/input/keyboard/` | `readKeyboardDirection` |
| 摇杆 force→方向 | `src/input/joystick/` | `readJoystickDirection` |
| 输入契约（统一输出格式） | `src/input/contract/` | `DirectionInput` 类型 |
| 运行时摇杆适配器 | `game/PhaserVirtualJoystick.ts` | `PhaserVirtualJoystick` 类 |

**怎么验证它做对了**：
- 单元测试：`tests/input/resolve/` —— 键盘有输入时选键盘、摇杆激活时选摇杆、都没输入时返回 null
- 浏览器 Smoke：`scripts/browser-mobile-input-smoke.mjs` —— 桌面模拟摇杆隐藏、移动模拟摇杆显示

### 骨架 2：死区过滤

> 理解层的人话：手指轻轻蹭了一下摇杆，不算"我要走"。
> 在代码里，这个东西叫 **forceMin 阈值**。

**它怎么工作的**：
摇杆计算手指偏移距离 `force = distance(start, end)`，如果 `force < forceMin`（默认 16px），直接返回 null（表示"无输入"）。手指必须推出足够的距离才被当作有效方向。这是 rexVirtualJoystick 插件 TouchCursor 的默认行为。

在我们的原生适配器中，同样的逻辑——`forceX`/`forceY` 算出的力度（`Math.hypot` 求模）小于 `forceMin` 时，方向解析器拿到 null，输出"无输入"。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| 死区阈值 | `game/PhaserVirtualJoystick.ts` | `forceMin = 16` |
| 力度计算 | `game/PhaserVirtualJoystick.ts` | `forceX` / `forceY`（`Math.hypot` 求模）+ `params.forceMin` |
| 原站证据 | `sample/.../chunk-VANY4YOC.js` | TouchCursor `forceMin` 默认值 |

**怎么验证它做对了**：
- 移动输入 Smoke：手指微移（<16px）不产生速度，移动 20px 后产生 east 方向

### 骨架 3：优先级仲裁

> 理解层的人话：键盘和摇杆同时来信号，听谁的？摇杆说了算。
> 在代码里，这个东西叫 **joystickActive 标志 + resolveMovement**。

**它怎么工作的**：
`resolveMovement` 先检查摇杆是否激活（`joystickActive === true`）。如果激活——跳过键盘读取，直接用摇杆方向。如果摇杆回中（无输入）——`joystickActive` 置 false，恢复键盘方向。

原站的 `updateMovement` 首行就是 `if (!this.cursors || this.joystickActive) return`——摇杆激活时键盘移动整个跳过。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| 摇杆激活标志管理 | `game/PhaserVirtualJoystick.ts` | `isActive` 属性 |
| 方向仲裁 | `src/input/resolve/index.ts` | `resolveMovement(joystickActive, keyboardDir, joystickDir)` |
| 摇杆回中恢复键盘 | `game/PhaserVirtualJoystick.ts` | `onPointerUp` → setVelocity(0,0) + isActive=false |
| 原站证据 | `sample/.../chunk-WMFY56ZM.js` | `updateMovement` 首行、`joystickActive` 置位逻辑 |

**怎么验证它做对了**：
- 浏览器 Smoke：摇杆按住时键盘方向不产生速度；释放后键盘恢复 150 单轴速度
- 单元测试：`tests/input/resolve/` —— `joystickActive=true` 时键盘方向被忽略

### 骨架 4：方向量化

> 理解层的人话：摇杆推的角度是连续的，但角色只能走 8 个方向。
> 在代码里，这个东西叫 **8 方向离散化 + 速度表**。

**它怎么工作的**：
- **键盘端**：用 if/else 链逐方向判断——上 > 下 > 左 > 右（有优先级），组合出斜方向。单轴输出 150，对角输出 106（150 × 0.707）。
- **摇杆端**：用主轴判定（|forceX|/|forceY| > 1.5 判定单轴方向），阈值过滤（单轴 0.3、对角 0.5），量化成 `(dx,dy) ∈ {-1,0,1}²`，再映射到速度和方向名。
- 两端最终产出完全相同的 8 方向字符串：north / north-east / east / south-east / south / south-west / west / north-west。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| 8 方向定义 | `src/input/direction/eight-direction.ts` | `DIRECTIONS` 映射表 |
| 速度常量 | `src/input/direction/speed.ts` | `SPEED = 150`, `DIAGONAL_SPEED = 106` |
| 键盘→方向 | `src/input/keyboard/` | if/else 链 8 方向判定 |
| 摇杆→方向 | `src/input/joystick/` | 主轴判定 1.5 + 阈值 0.3/0.5 |
| 原站证据 | `sample/.../chunk-WMFY56ZM.js` | `updateMovement`（键盘）、`setJoystickControls`（摇杆） |

**怎么验证它做对了**：
- 单元测试：`tests/input/direction/`、`tests/input/keyboard/`、`tests/input/joystick/`
- 原站基准：BASE-INPUT-001（键盘映射）、BASE-INPUT-003（归一化）

### 骨架 5：失败降级

> 理解层的人话：摇杆插件没加载出来？游戏继续跑。
> 在代码里，这东西就是 **try/catch + console 日志，不抛异常**。

**它怎么工作的**：
- 摇杆插件加载失败：`console.error("⚠ rexVirtualJoystick plugin sa nepodarilo načítať...")` + return。游戏继续，只是没摇杆。桌面用户完全不受影响（本来就隐藏摇杆）。
- 摇杆纹理缺失：`console.warn` + 用 `add.circle` 画圆形占位，不影响功能。
- 输入系统本身没有独立的重试机制——摇杆没了就没了，键盘永远可用。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| 摇杆插件加载失败处理 | `sample/.../chunk-WMFY56ZM.js` | `createJoystick`（try/catch + console.error） |
| 纹理缺失占位 | `sample/.../chunk-WMFY56ZM.js` | `add.circle` 兜底 |
| 重构适配器销毁 | `game/PhaserVirtualJoystick.ts` | `shutdown()` 移除监听器 + 销毁 Graphics |

**怎么验证它做对了**：
- 运行安全 Smoke：`scripts/browser-runtime-safety-smoke.mjs` —— 验证 shutdown 清理不泄漏

## 一、骨架落地

### 骨架 1：跟随模式

> 理解层的人话：镜头始终跟着角色，他去哪镜头去哪。
> 在代码里，这东西叫 **startFollow + lerp=1 硬跟随**。

**它怎么工作的**：
调用 `cameras.main.startFollow(player, true, 1, 1)`——第 3 参数 lerpX=1、第 4 参数 lerpY=1，意味着每帧直接设置 `scrollX = player.x - 视口中央`，没有任何缓动插值。不是平滑跟随，是硬贴。

配合 `setFollowOffset(0, 0)`（玩家在画面正中央，不偏移）和 `setDeadzone(0, 0)`（无死区——玩家一动镜头就动，没缓冲区），玩家始终在画面中央。

航拍结束时、传送结束时、怪物抓人结束时，都会重新调用 `startFollow(player, true, 1, 1)` 恢复硬跟随。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| 跟随参数 | `src/camera/params/` | `LERP = 1`, `OFFSET = (0,0)`, `DEADZONE = (0,0)` |
| 主跟随调用 | `game/CampusScene.ts` | `startFollow(player, true, 1, 1)` |
| 原站证据 | `sample/.../chunk-WMFY56ZM.js` | @369624（主 gameplay）、@397275（传送）、@415935（航拍结束）、@557606（怪物抓人） |

**怎么验证它做对了**：
- 单元测试：`tests/camera/params/` —— lerp=1、offset/deadzone 均为零
- BASE-CAMERA-002：硬跟随可复现（玩家动镜头瞬移，无拖延感）

### 骨架 2：视口约束

> 理解层的人话：镜头不能超出地图边界。
> 在代码里，这东西叫 **setBounds + physics.setBounds**。

**它怎么工作的**：
`cameras.main.setBounds(0, 0, 2240, 2240)` 把相机的可滚动范围锁在 2240×2240 像素内。2240 = 140（地图格数）× 16（每格像素）。同时 `physics.world.setBounds(0, 0, 2240, 2240)` 给物理世界设同样的边界——物理体也出不去。zoom=1 意味着视口大小 = 浏览器窗口大小，不放大不缩小。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| 相机边界 | `game/CampusScene.ts`（`create`） | `setBounds(0, 0, 2240, 2240)` |
| 物理边界 | `game/CampusScene.ts` | `physics.world.setBounds(0,0,2240,2240)` |
| 缩放 | `game/CampusScene.ts` | `setZoom(1)` |
| 原站证据 | `sample/.../chunk-WMFY56ZM.js` | @364238 创建块、@364398 开场、@415992 航拍结束 |

**怎么验证它做对了**：
- BASE-CAMERA-001：边界 2240×2240 + zoom=1 可复现
- 浏览器 Smoke：走到地图边缘不出现黑边

### 骨架 3：开场航拍序列

> 理解层的人话：游戏开始前镜头按预设路线自己飞一圈。
> 在代码里，这东西叫 **cameraSequence 数组 + startCameraSequence**。

**它怎么工作的**：
```js
cameraSequence = [
  {x:16*59,  y:16*58,  duration:0,     stayDuration:7000},   // 点0：立即
  {x:16*97,  y:16*76,  duration:15000, stayDuration:7000},    // 点1：飞15s→停7s
  {x:16*57,  y:16*71,  duration:15000, stayDuration:5000},    // 点2：飞15s→停5s
  {x:16*76,  y:16*41,  duration:15000, stayDuration:5000},    // 点3：飞15s→停5s
  {x:16*128, y:16*128, duration:15000, stayDuration:7000},    // 点4：飞15s→停7s
  {x:16*59,  y:16*58,  duration:15000, stayDuration:5000}     // 点5：飞15s→停5s
]
```
总时长 ≈ 111 秒（7+22+20+20+22+20）。坐标 = `16 × 格坐标`。

`startCameraSequence()` 做的事：`stopFollow()`（停跟随）+ `toggleJoystick(false)`（隐藏摇杆）+ `time.delayedCall(100, preloadChunksForCameraSequence)`（延迟 100ms 预载沿途 chunk）。

最后一点结束后：`tweens.add({targets: cameras.main, scrollX, scrollY, duration:3000, ease:"Power2", onUpdate: loadChunksForCamera, onComplete: ...})`——镜头 3 秒 Power2 缓动落回玩家，onComplete 里 `startFollow(player,true,1,1)` 恢复硬跟随。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| 航拍序列定义 | `src/camera/sequence/` | 6 点数据 + 总时长 |
| 运行时航拍启动 | `game/CampusScene.ts` | `startCameraSequence()` |
| 返回玩家 tween | `game/CampusScene.ts` | `tweens.add({duration:3000, ease:"Power2"})` |
| 原站证据 | `sample/.../chunk-WMFY56ZM.js` | `cameraSequence` @333500、`startCameraSequence` @409312、结束 tween @415700 |

**怎么验证它做对了**：
- 单元测试：`tests/camera/sequence/` —— 6 点坐标×时长×停留无遗漏
- BASE-CAMERA-004：航拍序列可复现

### 骨架 4：视口驱动加载

> 理解层的人话：镜头看到哪就加载哪块地图。
> 在代码里，这东西是 **通过 SYS-CHUNK 间接完成的——相机只提供视口范围**。

**它怎么工作的**：
相机本卡不直接操作 chunk 加载逻辑。它只提供两个回调给 SYS-CHUNK：
- `preloadChunksForCameraSequence`——航拍启动后 100ms 延迟调用，汇总相机位置、视口与 +2 块边距后空闲预载，当前坐标覆 5×5 分块。
- `loadChunksForCamera`——航拍中 onUpdate 调用，相机视口变化时触发分块按需加载/卸载。

分块系统的加载/卸载、网络请求、缓存策略一概归 SYS-CHUNK，本卡只提视口。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| 航拍预载调度 | `game/CampusScene.ts` | `time.delayedCall(100, preloadChunksForCameraSequence)` |
| 视口更新通知 | 间接，走 SYS-CHUNK 接口 | `loadChunksForCamera` 回调 |
| SYS-CHUNK 接口 | `src/chunk/` + `02-接口层/API契约表.md` | 相机可见范围 +1 块边距公式 |
| 原站证据 | `sample/.../chunk-WMFY56ZM.js` | @409312、runtime-network.json |

**怎么验证它做对了**：
- Q-MAP-003 已关闭：航拍预载机制已确证
- 浏览器 chunk Smoke：`scripts/browser-chunk-smoke.mjs` —— 跨块视口变化时 chunk 正确加载/卸载

### 骨架 5：像素稳定性

> 理解层的人话：画面不抖、不模糊。
> 在代码里，这是 **roundPixels + 30fps fixedDelta 两件套**。

**它怎么工作的**：
1. `roundPixels=true` + `setRoundPixels(true)`——相机坐标取整到最近像素，消灭子像素偏移导致的抖动/模糊。
2. `physics.world.setFPS(30)` + `fixedDelta=true`——物理模拟固定 30 帧步长。硬跟随（lerp=1）在固定步长下，画面"逐帧贴住"而非平滑，手感靠像素取整兜底。

这两条配合保证画面稳定：像素取整消子像素抖动，固定帧率消帧率波动。不是靠某种高级算法，就是两个最简单的设置。

**代码在哪**：

| 做什么 | 文件路径 | 关键常量/函数名 |
|---|---|---|
| roundPixels | `game/CampusScene.ts`（`create`） | `roundPixels=true` + `setRoundPixels(true)` |
| 物理帧率 | `game/CampusScene.ts` | `physics.world.setFPS(30)`, `fixedDelta=true` |
| 原站证据 | `sample/.../chunk-WMFY56ZM.js` | @364230（roundPixels）、@364276（setFPS） |

**怎么验证它做对了**：
- BASE-CAMERA-003：roundPixels + 30FPS fixedDelta 可复现
- 浏览器 Smoke：画面移动无抖动/撕裂

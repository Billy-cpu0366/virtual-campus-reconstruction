## 一、骨架落地 —— 每根骨头对应哪块代码

### 骨架 1：状态驱动的 DOM 视图切换

> 理解层说的是"游戏UI根据应用当前状态自动切换显示内容——加载中就显示进度条，Ready了就显示Play按钮，游戏中就全部隐藏"。
> 在代码里，这叫 **DomAppUi**。

**它怎么工作的**：

`DomAppUi` 接收来自 `AppRuntime` 的 `AppSnapshot`（包含 `status`、`progress`、`generation`），然后根据 `status` 选择渲染哪个视图。一共 6 种视图：

```
snapshot.status       →   renderLoading(progress)
  "BOOT"              →   renderLoading(0)
  "LOADING"           →   renderLoading(progress)
  "RETRYING"          →   renderLoading(progress)
  "READY"             →   renderReady()
  "ENTERING_GAME"     →   renderEntering()
  "PLAYING"           →   renderPlaying()
  "MODAL_OPEN"        →   renderPlaying()
  "ERROR"             →   renderError(message)
  "SHUTDOWN"          →   destroy()
```

每个 render 方法做的事很简单：把需要的元素设 `hidden=false`，不需要的设 `hidden=true`。比如 `renderReady()` 就是隐藏 loading 相关元素、显示 ready 元素、自动 focus Play 按钮。

**关键保护**：`render()` 在每次调用时检查 `snapshot.generation !== this.generation`，如果是新一代就重置进度计数器。进度值必须单调递增——比之前小的值被直接忽略。

### 骨架 2：内容弹窗系统

> 理解层说的是"游戏中弹出内容卡片——有遮罩、有标题、有正文、有关闭按钮。弹窗打开时玩家不能移动"。
> 在代码里，这叫 **DomModalGameUi** + **AppGameUiBridge**。

**它怎么工作的**：

`DomModalGameUi` 管理 `#content-ui-root` 中的一组 DOM 元素：`#content-backdrop`（半透明遮罩）、`#content-modal`（白色卡片）、`#content-title`（标题）、`#content-body`（正文区）、`#content-close`（关闭按钮）。

弹窗流程：
1. 玩家走进内容区域 → `show(request)` 被调用 → 构建 DOM 内容（用 `DomModalContentPort` 的 `createElement` / `appendChildren`）→ 显示遮罩 + 卡片 → 聚焦关闭按钮
2. 玩家点关闭按钮 / 点击遮罩 → `hide(request)` 被调用 → 隐藏所有元素
3. 场景销毁 → `destroy()` 被调用 → 移除所有 DOM 节点

`AppGameUiBridge` 在 `DomModalGameUi` 和 Main 之间做了一层桥接：每次 show/hide 时会通知 Main 当前弹窗可见性，Main 再根据这个隐藏/恢复引导浮标。

**关键保护**：`destroy()` 被设计成幂等的——多次调用不会出错。`subscribeUserClose` 在 destroy 后返回空函数，防止内存泄漏。

| 弹窗 DOM 结构 | [index.html](../../index.html):724-731 | `#content-ui-root` > `#content-backdrop` + `#content-modal` > `#content-title` + `#content-body` + `#content-close` |

### 骨架 3：小地图系统

> 理解层说的是"右下角迷你地图帮助玩家知道在哪，点击放大看全景大地图"。
> 在代码里，地图系统由 `index.html` 的 DOM 结构 + `PhaserCampusMapRuntime` 驱动。

**它怎么工作的**：

HTML 中预置了地图的两层 DOM：
- **迷你地图**（`#campus-map-hud`，z-index:6500）：固定在右下角，包含地图底图（`mini-map.webp`）、11 个标记点（绝对定位）、玩家蓝点
- **大地图**（`#campus-map-root`，z-index:8000）：全屏弹窗，包含半透明遮罩 + 地图对话框（`big-map.webp`）+ 可点击标记按钮 + 玩家蓝点 + 图例 + 关闭按钮

`PhaserCampusMapRuntime` 负责：
- 监听地图打开/关闭按钮的点击事件
- 根据玩家坐标更新迷你地图和大地图上蓝点的位置
- 管理标记点的 visited/disabled 状态（CSS class 切换）
- 弹出地图时接管焦点管理（Esc 键关闭、焦点循环）

### 骨架 4：内容引导浮标

> 理解层说的是"当玩家靠近一个内容区域时，屏幕边缘出现一行浮动提示文字，告诉玩家方向和步数"。
> 在代码里，引导浮标是 `#content-guide` 元素，由 `publishGuide()` 和 `publishAmbientGuide()` 更新。

**它怎么工作的**：

`#content-guide` 是一个 `position:fixed` 的元素，位于桌面端左下角（手机端移到顶部）。`textContent` 动态更新为类似 "Explore ABOUT · head west 18 tiles, then north 5" 的导航文字。

弹窗打开时自动隐藏：`onModalVisibility(visible)` 回调中设 `guide.hidden = visible || guide.textContent === ""`。弹窗关闭、引导文字非空时自动恢复显示。

### 骨架 5：可选资源的优雅降级

> 理解层说的是"加载动画GIF和Logo如果加载失败，不崩溃，不白屏——隐藏自己，换替代文字"。
> 在代码里，这靠 `DomAppUi` 的 `optionalImages` 机制。

**它怎么工作的**：

`DomAppUi` 构造时接收一个 `optionalImages` 数组。每个图片注册 `error` 事件监听器。图片加载失败时：
1. 设 `image.alt = fallbackAlt`（如 "Peter Oravec portfolio loader unavailable"）
2. 设 `image.style.visibility = "hidden"`（隐藏损坏的图片但不改布局）
3. 如果有 `fallback` 元素，显示它（如显示纯文字代替图片）

**关键保护**：整个降级逻辑被 `try/catch` 包裹——可选资源永远不能打断核心流程。图片挂了不影响游戏启动。

| 图片错误绑定 | [src/game-ui/app-shell.ts](../../src/game-ui/app-shell.ts):296-305 | `bindImages()`：每个图片注册 error 监听器 |

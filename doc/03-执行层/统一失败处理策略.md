# 统一失败处理策略

> **目的**：各系统 §4 "失败怎么办" 目前各自为政。本文档建立三级分类、异步操作统一要求、并给出各系统当前策略对照表，让后续系统实现时有统一参考。
> **维护原则**：新增系统或修改失败策略后，同步更新本文档对应系统的策略行。

---

## 一、三级分类

每条错误都应分类到以下三级之一，不能跳过分类直接选处理方式。

| 级别 | 定义 | 示例 | 处理原则 |
|---|---|---|---|
| **可恢复** | 故障是暂时性的，重试有意义 | 网络请求超时、chunk 下载失败、tileset 偶发加载失败 | 重试 N 次（N 可配）+ 指数退避或等间隔 + 最后一次失败后才降级 |
| **可降级** | 功能不能完整提供，但有替代方案 | 摇杆插件加载失败 → 键盘操作可用；粒子纹理缺失 → 圆形占位；换装动画缺失 → 跳过换装、保持当前状态 | 降级后保证核心功能可用 + console.warn 记录降级原因 |
| **致命** | 系统核心能力不可用，继续运行没有意义 | tileset 未加载完就尝试创建世界；ANGULAR 入口未命中；Phaser 框架未初始化 | 上报（console.error / 错误页）+ 停服（进入 Error 状态、显示 Retry）+ 销毁已建资源 |

### 降级后的恢复

可降级的错误在降级后**不自动重试**（因为降级 = 已经判断重试无意义）。如果后续条件变化（例如用户重新进入场景、重新创建世界），可以**重新尝试完整路径**。

---

## 二、异步操作统一要求

所有异步操作（网络请求、tween 动画、定时器、事件监听器、Phaser Loader）必须遵循以下四条：

1. **必须有超时**：不得依赖浏览器默认。chunk 请求超时**实际是 `15s`**（`game/fetchJson.ts:1` `JSON_REQUEST_TIMEOUT_MS = 15_000`，`ChunkDataStore` 以 `fetchJson` 作为取数器，故 master 与全部 chunk 请求都走它）；tileset 加载超时建议 `30s`（ASSET 仍未设超时，标记为待补）。
2. **必须有 AbortController 或等价的取消机制**：场景销毁/世界销毁/chunk 离开目标集合时，必须取消在途请求并清理回调。CHUNK 的 `AbortController` 机制是已验证的参考实现（见 `src/chunk/data-store.ts`）。
3. **必须有清理**：success/error/timeout/abort 四个分支全处理；tween 用 `onComplete` + 额外的安全 `destroy` 钩子；Phaser 事件用 `once` 或显式 `off`。
4. **取消和销毁不抛错**：取消（`AbortError`）是正常行为不是失败，不应触发错误状态或 `console.error`。

### 当前异步清理合规情况

| 要求 | 已合规 | 未合规 / 待补 |
|---|---|---|
| 超时 | CHUNK（master/chunk 请求） | ASSET（依赖浏览器默认超时） |
| AbortController | CHUNK（coordinator/datastore） | ASSET（无取消机制）、INTERACT（lease 异步未设取消） |
| 四分支处理 | CHUNK, WORLD | INPUT（摇杆失败仅 console.error + return）、PLAYER（换装动画缺失无超时） |
| 取消不抛错 | CHUNK | 大部分系统未做系统性验证 |

## 三、各系统 §4 策略对照表

以下信息来自各执行层系统卡的 §4 + 代码实际表现。**缺口**列标明该系统和统一策略之间的差距。

| 系统 | 失败分类 | 当前做法 | 缺口（与统一规则比） |
|---|---|---|---|
| **SYS-ASSET** | 致命 | 资源加载失败 → `requiredLoadError` → ERROR 状态 → 错误页+Retry 按钮。无自动重试，依赖用户手动 Retry。`fail()` 做 synchronous cleanup。 | ① 没有超时（依赖浏览器默认）；② 没有 AbortController 取消；③ 没有自动重试（可恢复型错误如网络波动会直接致命） |
| **SYS-WORLD** | 致命 / 可恢复 | `createWorld` 校验失败返回 `{ kind:"failure", reason }`；`applyChunk` 失败回滚（逐层清除已写内容）；`removeChunk` 失败回滚（重新写入已清除的层）；任何一次失败都整体回滚该 chunk、不登记已渲染 | 回滚逻辑已验证，和统一规则一致 |
| **SYS-LAYER** | 可降级 | roof/bridge 层不存在 → 忽略；未知层名 → 返回 null（调用方按"未知层默认失败"处理）；GID 判定未知 GID → false（不碰撞） | 无（纯查询/策略层，无异步操作） |
| **SYS-CHUNK** | 可恢复 | chunk 请求：**每次 3 次尝试**（`data-store.ts:186` 默认值；`game/CampusScene.ts:1346` 同值 3，2026-09-17 前传的是 2）；AbortController 取消；master 解析失败可重试；过期响应检测和丢弃；销毁时清空 pending 请求+失败记录+缓存；**失败目标有指数退避**（`coordinator.ts:233`，2 500 ms 起、翻倍、封顶 30 000 ms） | 最合规的系统。残留一处：同一块内的连续尝试之间没有间隔（退避只在**目标级调度**上） |
| **SYS-INPUT** | 可降级 | 摇杆插件加载失败 → `console.error` + return（游戏继续，仅键盘可用）；非法方向 → (0,0)；未知设备类型 → 默认 tablet 参数；方向不可能组合 → if/else 优先级 | 无超时/AbortController（摇杆是同步回调，不需要） |
| **SYS-MOVE** | 可降级 | `blocked` 为空 → 不卡；越界坐标 → false（不可走）；非法方向 → false | 无（纯同步逻辑） |
| **SYS-PLAYER** | 可降级 | 换装动画缺失 → 卡住（原站未兜底，这是已知缺口）；空闲判定负数 → none | ① 换装动画缺失无降级方案；② 换装异步没有超时保护 |
| **SYS-CAMERA** | 可降级 | 玩家不存在 → 忽略 startFollow；相机未初始化 → 全零返回；航拍是常量数据、无异常 | 无（纯查询/常量） |
| **SYS-ZONE** | 可降级 | 无效 bbox → 跳过并告警；越界坐标 → 无匹配区域；重复 id → 覆盖旧注册 | 无异步操作 |
| **SYS-INTERACT** | 可恢复 | lease 失败重试 + pendingReleaseTokens 队列；未知 interactionId → 忽略；弹窗已在显示 → 排队或忽略 | ① 弹窗异步关闭无超时（如果用户永远不点关闭按钮）；② lease 重试次数未文档化 |
| **SYS-GAME-UI** | 可降级 | 可选图片加载失败 → 隐藏自己 + 替代文字（不崩溃、不白屏）；调试面板不存在 → 忽略 HUD 更新；插件缺失 → 圆形占位 | 图片加载失败的降级是参考实现 |
| **SYS-APP** | 致命 | `fail()` → 错误页+Retry；`retry()` → cleanup 旧代 → 重新 beginLoading；页面隐藏 → 暂停游戏；页面可见 → 恢复 | 无 AbortController（页面 unload 时未取消在途加载） |
| **SYS-ENTITY** | — | undesign，无实现 | 不在 Phase 1 范围 |
| **SYS-NPC** | 可降级 | 贴图未加载 → 跳过并告警；越界 → false（不可走）；路径失败 → batchedPathFailures++ | 缺少 AbortController（NPC 寻路是异步的吗？待确认）；路径失败重试/降级策略未定 |
| **SYS-ROUTE** | 可降级 | 贴图未加载 → 跳过；路线结束 → 循环或移除 | 和统一规则一致（无异步操作需要特殊处理） |
| **SYS-FX** | 可降级 | 纹理缺失 → 圆形占位或跳过；管线不可用 → `console.warn` + strength 置 0 | 和统一规则一致 |

## 四、Phase 1 优先修复建议

按严重程度排序：

| 优先级 | 系统 | 问题 | 建议 |
|---|---|---|---|
| **P0** | SYS-ASSET | 无超时+无取消 | 给 tileset/world 加载加 30s 超时 + AbortController |
| **P0** | SYS-APP | 页面 unload 未取消加载 | `beforeunload` 事件中 abort 所有在途 ASSET 请求 |
| **P1** | SYS-PLAYER | 换装动画缺失无降级 | 加超时（10s），超时后跳过动画直接切换贴图（或保持当前着装） |
| **P1** | SYS-INTERACT | 弹窗关闭无超时 | 确认是否需要"用户 N 秒未关闭 → 自动关闭"——Phase 1 的弹窗内容展示场景可能不需要 |
| **P2** | SYS-NPC | 路径失败处理未定 | Phase 2 正式实现 NPC 时再定 |
| ~~P2~~ | ~~SYS-CHUNK~~ | ~~重试退避~~ | **已结项（2026-09-17）**：核实后确认**退避已存在**——`src/chunk/coordinator.ts:233` 的 `#retryBackoff` 是**指数退避**：初始 2 500 ms、每次翻倍、封顶 30 000 ms，由 `game/CampusScene.ts:2189` 在每次目标集合更新时驱动。**原建议「加 1s/2s/4s 退避」作废**——现值更完善（有封顶），没有理由改。残留的只是「同一块内连续尝试之间无间隔」（见 §三 SYS-CHUNK 行） |
| ~~P2~~ | ~~SYS-CHUNK~~ | ~~`maxAttempts` 两个值~~ | **已结项（2026-09-17）**：Human 定「调用点改，和代码一致」，`game/CampusScene.ts:1346` 由 `maxAttempts: 2` 改为 **3**（与 `data-store.ts:186` 默认值同值）。此后**只留一个定义处**（`data-store.ts`），调用点不再单独调低 |

## 五、新增系统时的检查清单

如果一个新系统有异步操作，必须在下笔实现前回答以下 6 问，并写入该系统的 §4：

1. 哪些操作会失败？失败后属于哪一级（可恢复/可降级/致命）？
2. 如果是可恢复：重试几次、间隔多久、最后一次失败后降级还是致命？
3. 如果是可降级：降级方案是什么？降级后用户的核心功能还可用吗？
4. 所有异步操作有没有超时？超时时间是多少？
5. 所有异步操作有没有取消机制（AbortController 或等价手段）？
6. 场景/世界/系统销毁时，能否安全取消所有在途操作并清理所有回调？

## 六、修订记录

### 2026-09-17：SYS-CHUNK 重试退避与超时数值订正

由 [网络协议层](../06-网络协议层/README.md) 按代码逐条复盘时发现，本文件有三处与代码不符。Human 授权后订正。

| 位置 | 原文 | 订正为 | 依据 |
|---|---|---|---|
| §二 第 1 条 | chunk 请求超时建议 `10s`（CHUNK 已实现） | **实际是 `15s`** | `game/fetchJson.ts:1` `JSON_REQUEST_TIMEOUT_MS = 15_000`；`ChunkDataStore` 以 `fetchJson` 作取数器（`game/CampusScene.ts:1345`），master 与全部 chunk 请求都走它 |
| §三 SYS-CHUNK 行 | 「3 次重试」；缺口「重试间隔是否有退避**待确认**」 | 当时的实际值是 **2 次尝试**（`CampusScene.ts:1346` 传 2，store 默认 3）；缺口改为「`maxAttempts` 两个值未统一」+「同一块内连续尝试无间隔」。**其中「两个值」已于同日稍后结项**，统一为 3（见 §四 P2 行） | `src/chunk/data-store.ts:186,404` |
| §四 P2 SYS-CHUNK | 「确认 3 次重试之间是否有间隔——如果没有，建议加 1s/2s/4s 退避」 | **已结项**：退避**已存在**，且比原建议更完善 | `src/chunk/coordinator.ts:55,233` |

**错因**：本文件当时只核实了 `src/chunk/data-store.ts` 的重试循环，**没有看 `src/chunk/coordinator.ts` 的目标级重试调度**。本项目实际有**两套重试机制**：

| | 单次取数的重试循环 | 失败目标的重试调度 |
|---|---|---|
| 位置 | `data-store.ts` `#loadChunk()` | `coordinator.ts` `#retryBackoff` + `retryFailedTargets()` |
| 管什么 | 同一块连发几次 | 失败过的目标什么时候才准再试 |
| 退避 | **无**（`await` 完立即重发） | **有**：2 500 ms 起、翻倍、封顶 30 000 ms |
| 驱动 | 循环自己 | `game/CampusScene.ts:2189`，每次目标集合更新时检查一遍（**不是定时器**） |

只找到其中一套，就会把「有退避」误判成「无退避」。详见 [网络协议层 §一 契约 5](../06-网络协议层/README.md)。

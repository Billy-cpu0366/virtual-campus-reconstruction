## 一、骨架落地 —— 每根骨头对应哪块代码

### 骨架 1：分阶段状态机

> 理解层说的是"火车进站、停靠、离站，分阶段运行"。
> 在代码里，这叫 **TrainRouteRuntime**，一个纯数学状态机。

**它怎么工作的**：

```
idle（空闲，等触发）
  │  start(nowMs) → arriving
  ▼
arriving（进站中）
  │  根据 elapsed / TRAIN_ENTRY_DURATION 算进度
  │  用 cubicEaseOut 缓动插值 x 坐标
  │  x = 2480 + (480 - 2480) × cubicEaseOut(progress)
  │  时间到 → x=480, state=holding
  ▼
holding（停靠）
  │  x=480 不动
  │  holdUntil = arrivalAt + TRAIN_HOLD_DURATION
  │  时间到 → departing
  ▼
departing（离站）
  │  根据 elapsed / TRAIN_DEPARTURE_DURATION 算进度
  │  用 quadEaseIn 缓动插值 x 坐标
  │  x = 480 - 4000 × quadEaseIn(progress)
  │  时间到 → x=-3520, state=complete
  ▼
complete（走完了）
```

**缓动公式**：
- cubicEaseOut(进站刹车)：`1 - (1-t)³ ` —— 减缓
- quadEaseIn(离站加速)：`t²` —— 渐快

### 骨架 2：碰撞区随实体移动

> 理解层说的是"火车经过的地方，其他 NPC 不能走"。
> 在代码里，这通过 **碰撞矩形 → 格子坐标 → blocking zone 通知** 实现。

**它怎么工作的**：

```
TRAIN_COLLISION_X_ZONES（4 段，相对于火车 sprite 左上角）：
  [0,   365]   ← 第 1 段（车头区域）
  [360, 720]   ← 第 2 段
  [715, 1078]  ← 第 3 段
  [1073, 1435] ← 第 4 段（车尾区域）
  （区间有重叠，防止碰撞缝隙）

每帧计算：
  实际碰撞左 = 火车当前 x + 区间左 × collisionScale
  实际碰撞右 = 火车当前 x + 区间右 × collisionScale

格子化（tileSize=16）：
  左边界格子 = floor(碰撞左 / 16)
  右边界格子 = floor(碰撞右 - ε / 16)
  上边界格子 = floor(TRAIN_COLLISION_TOP / 16)   = floor(323/16) = 20
  下边界格子 = floor(TRAIN_COLLISION_BOTTOM / 16) = floor(359/16) = 22
  每个格子坐标压成 "tileX,tileY" 字符串

去重 + 排序 → 拼成 "t1|t2|t3" → 和 lastCells 比较
  变了 → setTrainBlockingZone(newCells)
  没变 → 跳过（避免每帧刷外部系统）
```

**代码在哪**：

| 做什么 | 文件路径 + 行号 | 关键常量 |

| 碰撞区间定义 | [src/route/train.ts:13-18](src/route/train.ts#L13-L18) | `TRAIN_COLLISION_X_ZONES` (4 段) |
| 碰撞上下界 | [src/route/train.ts:10-11](src/route/train.ts#L10-L11) | `TRAIN_COLLISION_TOP=323`, `TRAIN_COLLISION_BOTTOM=359` |
| 格子大小 | [src/route/train.ts:8](src/route/train.ts#L8) | `TRAIN_TILE_SIZE=16` |

### 骨架 4：事件驱动的外部通知

> 理解层说的是"火车到站了要通知其他系统"。
> 在代码里，通过回调 `onDeparture` / `onLeaveViewport` / `onComplete` 实现。

**它怎么工作的**：

```
PhaserTrainRuntime 内部维护三个标志位：
  departureNotified       ← 是否已通知 onDeparture（防止重复触发）
  departureWasInViewport  ← 离站期间火车是否曾在视野内
  leaveViewportNotified   ← 是否已通知 onLeaveViewport

触发逻辑：
  ① onDeparture:
     snapshot.state === "departing" && !departureNotified
     → 立即触发（离站瞬间，不管视野）

  ② onLeaveViewport:
     前提：departureWasInViewport = true（火车确曾出现在玩家视野里）
     条件：(isOutsideViewport && !leaveViewportNotified)
          || (complete && !leaveViewportNotified)
     → 离开视野时触发（或直接走到 complete 时也触发一次）

  ③ onComplete:
     snapshot.state === "complete"
     → 走完全程时触发
```

**视野检测**：`isInsideViewport()` 判断火车 sprite 的左右边界跟 viewport 有无交集。

| 视野检测 | [game/PhaserTrainRuntime.ts:365-376](game/PhaserTrainRuntime.ts#L365-L376) | `isInsideViewport()` / `isOutsideViewport()` |
| 离开视野通知 | [game/PhaserTrainRuntime.ts:215-223](game/PhaserTrainRuntime.ts#L215-L223) | `onLeaveViewport` 触发 |

结构：3 层精灵
  机身 (vehicle-helicopter-high-res) → scale=2, depth=600
  主螺旋桨 (vehicle-helicopter-main-rotor-thingy) → 持续旋转, rotationSpeed=8
                                                 → 5 个叶片

  helicopterRotor.angle += rotationSpeed
  helicopterTailRotor.angle += rotationSpeed

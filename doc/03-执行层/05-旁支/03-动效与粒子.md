# 动效与粒子（SYS-FX）—— 执行层细化

> 对照理解层的 5 个骨架 + 10 张皮 + 10 个配置点，逐一落到代码位置。

---

## 👀 先看这里（给 Human 的人话总结）

**当前状态**：4 类特效全部实现。核心逻辑在 `src/fx/`（3 个 Runtime 类），表现层在 `game/`（4 个 PhaserRuntime）。工厂烟用自定义 `emitCallback` 实现抛物线轨迹。脚印用 95 精灵对象池。雾用按格子的多发射器 + 定时复活。Stop AI 烟用 3 层独立发射器 + 随机风力。

**还没做的**：所有特效的位置、颜色、参数硬编码，将来从后端配置下发。

## 一、骨架落地 —— 每根骨头对应哪块代码

### 骨架 1：粒子系统固定生命周期

> 理解层说的是"每个特效都有 start → tick → shutdown"。
> 在代码里，每个特效 Runtime 都有统一的生命周期管理。

**它怎么工作的**：

```
FactorySmokeRuntime:
  start(now, visible) → 设置 emitting/paused 状态
  tick(now, visible)  → 根据 viewport 可见性切换 emitting/paused
  shutdown()          → state='idle'

FogRuntime:
  start(now)          → 初始化格子网格 + 每个格子的粒子状态
  tick(now, player, cars) → 检查玩家/车辆是否进入了某个格子 → 清除/复活
  shutdown()          → 清除所有状态

StopAiSmokeRuntime:
  start(now)          → 初始化 3 个 canister，各自设随机延迟
  tick(now)           → 每个 canister 到了延迟时间 → 激活
                      → 每个 canister 独立管理自己的 active 状态
  shutdown()          → 全部 deactivate
```

**代码在哪**：

| 做什么 | 文件路径 | 关键类/方法 |
|---|---|---|
| 工厂烟雾核心 | [src/fx/factory-smoke.ts](../../../src/fx/factory-smoke.ts) | `FactorySmokeRuntime` — `start()`, `tick()`, `shutdown()` |
| 橙色雾核心 | [src/fx/fog.ts](../../../src/fx/fog.ts) | `FogRuntime` — `start()`, `tick()`, `updateInteractions()`, `shutdown()` |
| Stop AI 烟雾核心 | [src/fx/stop-ai-smoke.ts](../../../src/fx/stop-ai-smoke.ts) | `StopAiSmokeRuntime` — `start()`, `tick()`, `setActive()`, `shutdown()` |
| 工厂烟雾表现 | [game/PhaserFactorySmokeRuntime.ts](../../../game/PhaserFactorySmokeRuntime.ts) | `PhaserFactorySmokeRuntime` — 包裹 FactorySmokeRuntime |
| 脚印表现 | [game/PhaserFootstepRuntime.ts](../../../game/PhaserFootstepRuntime.ts) | `PhaserFootstepRuntime` — 自包含对象池 |

### 骨架 2：核心逻辑与表现分离

> 理解层说的是"smoke 怎么飘在 src/，长什么样在 game/"。
> 在代码里，每个特效都遵循 Runtime + Adapter 分层。

**它怎么工作的**：

**工厂烟雾**分层示例：

```
src/fx/factory-smoke.ts → FactorySmokeRuntime
  职责：管理 emitting/paused/idle 状态
  常量：FACTORY_SMOKE_POSITION = { x: 50.5*16, y: 33.7*16 }
        FACTORY_SMOKE_DELAY = 1500 (ms)
        FACTORY_SMOKE_VIEWPORT_PADDING = 100 (px)
  函数：particlePosition(offsetX, startY, elapsed)
        计算抛物线轨迹：x = startX + offsetX * 0.1
                        y = -0.03 * (x-startX)² + startY

game/PhaserFactorySmokeRuntime.ts → PhaserFactorySmokeRuntime
  职责：创建 Phaser 粒子发射器，用 emitCallback 给每个粒子算位置
        forEachAlive 更新粒子 → 根据 FactorySmokeRuntime 状态切换发射
```

**橙色雾**分层示例：

```
src/fx/fog.ts → FogRuntime
  职责：管理多边形区域 → 格子分解
        管理每个格子的 clearedAt 时间戳
        管理 activeCells（哪些格子在冒烟）
        updateInteractions(player, cars) → 检查清除触发

game/PhaserFogRuntime.ts → PhaserFogRuntime
  职责：每个 active cell 一个 Phaser 粒子发射器
        管理 cleared cell 的 500ms respawn timer
        根据 playerDepth 调整粒子大小
```

**Stop AI 烟雾**分层示例：

```
src/fx/stop-ai-smoke.ts → StopAiSmokeRuntime
  职责：3 个 canister 的配置和延迟管理
        每层独立的 active 标志
        windTimer 管理风向切换

game/PhaserStopAiSmokeRuntime.ts → PhaserStopAiSmokeRuntime
  职责：每个 canister 的 3 层各一个 Phaser 粒子发射器
        每个 canister 的独立 wind 循环（随机 delay → 随机 gravityX）
        canister graphic 渲染（调试用的彩色罐子）
```

### 骨架 3：对象池复用

> 理解层说的是"脚印不重复创建，从池里取用"。
> 在代码里，`PhaserFootstepRuntime` 维护 95 个精灵的池，循环使用。

**它怎么工作的**：

```
初始化阶段：
  创建 95 个精灵（用 Canvas 生成 8×12px 椭圆贴图 → texture）
  每个精灵初始 alpha=0

每帧仅写入路径：
  检查当前玩家的 tile → 是否在 footstepTileIds 集合里（GID 69345）
  检查 playerDepth < 1000（只在特定深度层）
  检查距上次脚印 ≥ 14px

生成脚印：
  nextIndex 循环取下一个精灵（0→1→2...→94→0→1...）
  精灵 position = (player.x, player.y+10)
  精灵 alpha = 0.5
  精灵 aliveAt = now（记录生成时间）

每帧 update：
  遍历所有脚印：
    aged = now - aliveAt
    aged < 10000ms → alpha=0.5（正常显示）
    10000 < aged < 11000 → alpha 线性衰减到 0（1 秒淡出）
    aged > 11000 → alpha=0（回收，但精灵对象不销毁）
```

**代码在哪**：

| 做什么 | 文件路径 + 行号 | 关键常量 |
|---|---|---|
| 脚印 Runtime | [game/PhaserFootstepRuntime.ts](../../../game/PhaserFootstepRuntime.ts) | `PhaserFootstepRuntime` (254 行) |
| 池大小 | [game/PhaserFootstepRuntime.ts](../../../game/PhaserFootstepRuntime.ts) | `FOOTSTEP_COUNT = 95` |
| 脚印贴图生成 | [game/PhaserFootstepRuntime.ts](../../../game/PhaserFootstepRuntime.ts) | Canvas 8×12px 椭圆 → `generateTexture` |
| 脚印间距 | [game/PhaserFootstepRuntime.ts](../../../game/PhaserFootstepRuntime.ts) | `FOOTSTEP_MIN_DISTANCE = 14` (px) |
| 可见时长 | [game/PhaserFootstepRuntime.ts](../../../game/PhaserFootstepRuntime.ts) | 10s 可见 + 1s fade |
| 脚印触发 tile | [game/PhaserFootstepRuntime.ts](../../../game/PhaserFootstepRuntime.ts) | `footstepTileIds` (包含 GID 69345) |
| 深度限制 | [game/PhaserFootstepRuntime.ts](../../../game/PhaserFootstepRuntime.ts) | `playerDepth < 1000` |

### 骨架 4：区域触发与视口裁剪

> 理解层说的是"特效只在需要的地方跑"。
> 在代码里，这表现为三种不同的触发机制。

**① 工厂烟雾：视口裁剪**（[game/PhaserFactorySmokeRuntime.ts](../../../game/PhaserFactorySmokeRuntime.ts)）

```
视口检测：
  factoryPosition (808, 539.2) 是否在 viewport + 100px padding 内？
    ↓ 是 → emitting（发射粒子）
    ↓ 否 → paused（停止发射，但不销毁已有粒子）

每帧 tick：
  FactorySmokeRuntime.tick(now, visible)
    visible=true  → emitting（active=true, idle=false, paused=false）
    visible=false → paused（active=false, idle=false, paused=true）
    shutdown     → idle（active=false, idle=true, paused=false）
```

**② 脚印：tile 触发**（[game/PhaserFootstepRuntime.ts](../../../game/PhaserFootstepRuntime.ts)）

```
触发条件（全部满足才留脚印）：
  ① 当前 tile 的 GID ∈ footstepTileIds（仅 69345）
  ② playerDepth < 1000
  ③ 距上次脚印 ≥ 14px
  ④ 玩家正在移动
```

**③ 橙色雾：多边形区域 + 格子分解**（[src/fx/fog.ts](../../../src/fx/fog.ts)）

```
初始化：
  S1 多边形 49 个顶点 → 算 bounding box → 遍历每个格子
  → pointInPolygon → 在区域内 → 加入 activeCells

运行时：
  玩家位置 → 计算 clearsArea（35×85 椭圆）
  警车位置 → 计算 clearsArea（半径 40 圆）
  遍历 activeCells → 格子中心是否在 clearsArea 内？
    ↓ 是 → cleared=true，记录 clearedAt=now
    ↓ 否 → 跳过

复活：
  每个 cleared cell → now - clearedAt > 500ms？
    ↓ 是 → cleared=false，重新冒烟
    ↓ 否 → 继续保持清除状态
```

**代码在哪**：

| 做什么 | 文件路径 + 行号 | 关键常量/方法 |

| 工厂烟视口边距 | [src/fx/factory-smoke.ts](../../../src/fx/factory-smoke.ts) | `FACTORY_SMOKE_VIEWPORT_PADDING = 100` |
| 工厂烟延迟发射 | [src/fx/factory-smoke.ts](../../../src/fx/factory-smoke.ts) | `FACTORY_SMOKE_DELAY = 1500` (ms) |
| Phaser 工厂烟视口检查 | [game/PhaserFactorySmokeRuntime.ts](../../../game/PhaserFactorySmokeRuntime.ts) | `tick()` 中 viewport 碰撞检查 |

### 骨架 5：多层渲染 + 独立风力

> 理解层说的是"Stop AI 烟雾不是一层，有 3 层，各层独立的风"。
> 在代码里，`StopAiSmokeRuntime` 管理 3×3=9 组参数，`PhaserStopAiSmokeRuntime` 为每组创建独立发射器。

**它怎么工作的**：

```
结构（核心层，[src/fx/stop-ai-smoke.ts](../../../src/fx/stop-ai-smoke.ts)）：
  3 个 canister (canister-1/2/3)
    ├─ 各有自己的坐标
    ├─ 各有随机延迟启动时间（0~10s）
    └─ 3 层(layer)：
         ├─ back  (depth=350)  — 后层，最远
         ├─ main  (depth=1160) — 中层
         └─ front (depth=1550) — 前层，最近

每层独立风力（Phaser 表现层）：
  gravityX = random([-40, -15] 或 [15, 40])  ← 向左或向右
  定时器：
    windTimer = random(2~5s 或 3~8s) → 到期后随机换 gravityX 和 timer 时长

延迟启动：
  每个 canister 有独立的 delay 计时
  canister-1: delay=random(0~3s)
  canister-2: delay=random(0~5s)
  canister-3: delay=random(0~10s)

渲染顺序（由 depth 控制）：
  back layer (350)  → 画在最底下
  main layer (1160) → 中间
  front layer (1550) → 画在最顶上（离玩家最近）
```

**烟雾罐可视化**（[game/PhaserStopAiSmokeRuntime.ts](../../../game/PhaserStopAiSmokeRuntime.ts)）：
- 每个 canister 绘制一个 3-band 颜色罐子图（调试用）
- 颜色编码：0xFF4D4D(红) / 0xFFA64D(橙) / 0xFFFF4D(黄)

**代码在哪**：

| 风力参数范围 | [src/fx/stop-ai-smoke.ts](../../../src/fx/stop-ai-smoke.ts) | `GRAVITY_MIN/MAX` (15~40) |
| 延迟范围 | [src/fx/stop-ai-smoke.ts](../../../src/fx/stop-ai-smoke.ts) | `START_DELAY_MIN/MAX` (0~10s) |

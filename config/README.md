# 配置

**这个文件夹，是把游戏里「能改的值」从代码里拎出来之后的落脚点。** 以后换校园，改这里，不动 `src/`。

**现在已经生效的部分**：NPC 那个板块的 **22 份配置全部接上了**——数据层 15 份（谁去哪、去几个人）和呈现层 7 份（用哪几张图、每帧切多大）都是游戏运行时去读的。改一个数、刷新页面就生效，**不用重新构建**。其余板块还没接，见下面的[已知缺口](#已知缺口)。

**这套东西在真浏览器里跑通过**（2026-09-21）：开发服务器和生产构建产物各跑一次，都能进到可玩状态、没有报错；并且实测了「改一个数、不重新构建、刷新即生效」——改 `maxCreatePerSync` 和一张图的 `frameCount`，刷新后页面读到的就是新值。

## 目录长什么样

```
config/
├── 文档/                    方案、格式规范、换皮总表
├── 工具/                    测试用：从磁盘直接读配置（游戏里不用它）
├── 骨架/                    ← 所有校园共用，换校园时不动
│   ├── 公共/                读配置的零件（读哪一套、去哪儿取、怎么校验、冻结）
│   └── 05-旁支/SYS-NPC/逻辑/  NPC 板块的逻辑
└── default/                 ← 一个校园一套，只放「数据」
    └── 05-旁支/SYS-NPC/数据/ 22 份 JSON
```

**为什么要分成「骨架」和「一套一套」**：一个校园换一套的，只有**数字**（谁站哪、走哪条路、贴图几帧）。**读配置的代码和板块逻辑，到哪个校园都是同一份。** 要是每套各存一份代码，五套配置就有五份一模一样的逻辑，改一处 bug 要改五处，漏一处那一套的行为就跟别人不一样。

## 怎么加一套校园配置

三步，**不用改任何代码**：

1. **复制** `default/` 整个目录，改个名（比如 `set1/`）。
2. **改里面的数字**。照着 [总表](文档/换皮配置总表.md) 找哪个数管哪件事；每份 JSON 顶上的 `meta` 写着它是从哪儿抽出来的。
3. **在网址上指明读它**：`http://localhost:4175/?config=set1`。不带参数就读 `default/`。

**集名只用小写英文字母、数字、`-` 和 `_`**（`set1`、`school-a` 都行）。这条是硬规矩：集名要拼进网址再拿去取文件，放任 `../` 之类就能读到 `config/` 外面去。顺带白捡一条——`骨架`、`文档`、`工具` 是中文名，天然不合格，不会被当成一套配置。

名字拼错、或者用了中文和斜杠，游戏**退回读 `default/` 并在控制台喊一声**（按 F12 打开控制台就能看见那句）。不喊的话，拼错的人看到游戏照常跑起来，会以为自己指定的那套生效了——**看着正常、其实错了**。

## 已经定下来的事

### 贴图规格算配置，归 SYS-NPC

抽呈现层时撞上一处**两份文档自己打架**：

- [配置格式规范](文档/配置格式规范.md) §八原先把「用哪张图、几帧」整句划成**素材**，说「不当配置」——理由是换校园就是换图片文件，改配置改不了图。
- [总表](文档/换皮配置总表.md) §14 却把**同样的贴图规格**列成了配置项，还算进了那句「这是后台到底要做几个输入框的答案」。

**定了：按总表办，留在 SYS-NPC 板块。** 规范那句话划粗了，已划细（下表只列跟这次争议有关的三行，另两类是「数值」和「逻辑」，没动）：

| 算什么 | 例子 | 为什么 |
|---|---|---|
| **图片的规格** | 每帧切多大、一共几帧、锚点对齐到哪、四个方向的帧怎么排 | **算配置**——新校园美术给的排布多半不一样 |
| **用到哪几张图** | 静态人群从哪十几张里挑、哪一组专用哪几张 | **算配置**——这是「每校园」的选择 |
| **图片文件本身** | 哪个 `.webp`、放在哪个目录 | **不算**，归 §1 的资源清单——盖掉文件名就完事了 |

分这条线的道理，用一个例子就清楚：新学校美术给了张 **48×48、20 帧**的图，配置里还写着 64，游戏就按 64 去切——**人照样出现，但一帧一帧地花**。这种值必须有个地方让人改。

> 副产物：**4 份**呈现层表里现在带着图片路径——`static-npc-presentation.json` 和 `sprayer-presentation.json` 的 `url`、`venue-crowd-presentation.json` 里抗议者那张的 `url`、`dancing-crowd-presentation.json` 的 `textureUrlPrefix`。按新规矩这些**将来要挪到 §1 的资源清单**。眼下先留在原地，因为那份清单还没做——是临时落脚，不是破例。
>
> 另一半是反过来的：`static-crowd-presentation.json` 和 `route-crowd-presentation.json` 只给**名字**，地址由 `game/` 按 `/sprites/<名字>.webp` 拼出来；虫子那张连名字都写死在 `game/PhaserBugCrowdRuntime.ts` 里。**这三处改配置换不了图。** 明细见[总表 §14 末尾那张三档表](文档/换皮配置总表.md#改哪儿--呈现层那-7-份表)。

### 取图地址写「现成地址」，不许拿字符串拼

**这条是踩了坑之后定的。** 喷水器的两张贴图原先写成 `new URL(\`../${asset.sourceFile}\`, import.meta.url)`——路径由配置里的字符串拼出来。看着挺聪明，实际跑不起来：

打包器只认**写得死的路径**。拼出来的它分析不了，就换成一堆「项目根目录下有哪些文件」的名单去查——名单里只有 README、`package.json` 这些，没有贴图。于是地址取到空值，浏览器实际请求的是 `/game/undefined`，**图片一次都没下载**，Phaser 登记不到贴图，整个动态世界起不来，游戏停在错误提示上。

更糟的是它**顺带把工程文件打进了发布产物**：那份名单把 `package.json`、`package-lock.json`、`tsconfig.json` 一起带上了。

**定了：配置里存的是运行期地址（`url`，形如 `/sprites/npc-sprayer.webp`），代码原样拿来用，不做任何拼接。** 图片文件放 `public/sprites/` 下，由 `scripts/prepare-runtime-assets.mjs` 从原站镜像拷过去——和其它所有 NPC 贴图同一条路。

### 最后 4 个藏在代码里的值也挖出来了

数据层原先还剩 4 个值，是**光秃秃的数字直接写在函数里**（没起名字，所以当初搜「有名字的常量」时漏掉了）。现在都成了配置字段，改完刷新就生效：

| 值 | 现在写在哪个配置里 | 写死的值 |
|---|---|---|
| 每支足球队站几个人 | `static-crowd-tuning.json` 的 `footballCount` | 10 |
| 哪几片算咖啡座 | `static-crowd-tuning.json` 的 `coffeeRegionIndexes` | [38, 61] |
| 已经出现过的区域，往外多留多少像素才算离开 | `static-crowd-tuning.json` 的 `activeRegionExtraMargin` | 100 |
| 给抗议者找位置最多试几次 | `venue-crowd-tuning.json` 的 `maxPlacementAttempts` | 20 |

**一处还没定**：那两片咖啡座（38、61）正好就是 `static-crowd-disabled-regions.json` 里被关掉的那两片。关掉的区域压根不放人，所以「咖啡座之间要隔 56 像素」这条规矩**现在怎么跑都跑不到**。要么这两片本来就不该关，要么这条规矩该删——得定一个。

### 「咖啡座」这套东西，原版里查不到

上面那个「还没定」查过一轮，结果比预想的干脆。

**搜的地方**：`sample/original-public-build/mirror/` 整棵镜像树，293 个文件全搜。

**搜到什么**：

| 搜什么 | 结果 |
|---|---|
| `coffee` / `kaviar` / `káva` / `咖啡` | **一个都没有** |
| 同一轮搜 `football_team_blue`（对照组） | 2 个文件搜到——说明这些文件确实被搜到了，不是漏搜 |
| 原版人群代码里的间距值 | 只有**一个** 20，没有第二档 |
| 原版代码里出现的 `56` | 21 处，全是坐标或帧号，没有一处是间距 |
| 原版区域数据里的 `spacing` / `disabled` 字段 | 都没有 |
| 原版的人群循环 | 只跳过「类型不是人群」和「轮廓点少于 3 个」的，**没有「按序号跳过某一片」这回事** |

**结论**：原版没有「咖啡座」这个概念，也没有第二档间距。**`[38, 61]` 那个「关掉哪两片」的名单同样不在原版里**——原版 88 片区域全都会站人。这套东西是我们这版自己带的，不是从原版抄来的。

（之所以重查一遍：我第一次只搜了两个文件就宣布「原版没有」，被指出「有时候只是你没看全」。那条规矩现在定在 skill `verify-before-claiming` 里。）

### 还有三处「原版有、我们这版没有」，先记着

同一轮搜索顺出来的，都不是这次要改的，但值得记一笔：

1. **原版按「区域中点的格子坐标」认两片音乐会人群**（不按名字，也不按序号），给它们两套不同朝向，还自动起名 `crowd_left_concert` / `crowd_right_concert`。我们这版没有这段。
2. **原版给一片区域找位置，整片共享「20 × 人数」次尝试**；我们这版是每个人各 20 次。
3. **原版的贴图是「洗牌发牌」**（发完一轮再洗一次），我们这版每次独立随机抽——同一张贴图可能连着出现。

## 已知缺口

**三条缺口现在全都关掉了**（下面留着没删，它们记的是「换校园时会踩到的坑」，那部分永远有效）。

**但「改了不生效」这件事还没有绝迹**——有 4 个字段在配置里长得像能改，实际改了画面不动（喷水器的 `depth` 和 `frameRate`、虫子的 `sprite`、静态人群的 `coffeeMinSpacing`）。原因是代码根本没读它们，不是配置写错了。**别去删这些字段**（那要动 `src/` 的字段定义），照着[总表 §14 的「改了没反应」清单](文档/换皮配置总表.md#14-sys-npc)绕开就行。


### 缺口 1（已关闭）：呈现层的 7 份表已经接线

> 关闭时间：2026-09-20。下面这条以前算缺口，现在已经不是了——**换校园想改贴图规格，改这 7 份 JSON 就行**。

SYS-NPC 的呈现层配置原先写死在 `game/` 下 7 个 `Phaser*Runtime.ts` 里，现在抽成 7 份表，游戏运行时去读：

| 表 | 管什么 |
|---|---|
| `static-npc-presentation.json` | 三张特殊贴图的帧规格 |
| `static-crowd-presentation.json` | 兜底贴图、要单下的 6 张图、帧规格、半宽、转头间隔 |
| `route-crowd-presentation.json` | 17 张贴图、逐组特殊贴图、逐组显示偏移、铁轨带 |
| `venue-crowd-presentation.json` | 贴图、半宽、抗议口号、喊话节奏、创建上限、气泡样式 |
| `bug-crowd-presentation.json` | 虫子帧规格、锚点、四方向起始帧 |
| `dancing-crowd-presentation.json` | 跳舞贴图的拼接规则与帧规格 |
| `sprayer-presentation.json` | 喷水器两张贴图的帧规格 |

（SYS-NPC 一共 22 份表：这 7 份归呈现层，其余 15 份归数据层。第 8 份呈现层表 `static-crowd-disabled-regions.json` 划进了数据层，因为它管的是「哪几块地方不站人」，不是「长什么样」。）

**为什么配置非得在游戏启动前读完**：贴图的帧规格（每帧多大、一共几帧）必须在 Phaser 的 `preload` 阶段就报上去，而那一阶段是同步的、等不了网络。所以顺序只能是「先读配置 → 再造 Phaser 游戏对象 → 场景按配置登记贴图」。这也是 `game/main.ts` 里那句 `loadNpcConfigs` 的位置来由。

**「那我现在想改这些值，去哪儿改？」** —— [总表 §14 末尾那张「改哪儿」表](文档/换皮配置总表.md#改哪儿--呈现层那-7-份表) 一列到底：想改什么 → 改哪份 JSON → 出问题去哪儿查。另外，**图片文件本身**（哪个 `.webp`、放哪个目录）不在这 7 份里，归 §1 的资源清单。

这 7 份表的 `meta.verified` 大多标成 `mixed` 或 `manual`：值是照着源码抄下来的，没有机检证据可比，换校园前建议人工核对一遍。另外有几项原先在总表里根本没登记过（场馆人群的气泡样式、同时做动作的人数上限、每帧最多新出现几人、每几个抗议者挑一个会动，以及静态人群的兜底贴图与半宽），现在都补在 §14 里了。

2026-09-21 又补进去三项同类的东西（也都登记在 §14 了）：静态 NPC 每张图**一共几帧**（`static-npc-presentation.json` 的 `frameCount`）、静态人群**每帧最多新建几个人**（`static-crowd-presentation.json` 的 `maxCreatePerSync`）、以及喷水器两张图的**取图地址**（`sprayer-presentation.json` 的 `url`）。前两项原先写死在 `game/` 里，坏起来都不报错——换一张帧数不同的图，人照样出现，只是动画播不全。

### 缺口 2（已关闭）：三处特殊区域原先按名字认，现在按序号认

> 关闭时间：2026-09-20。下面这条以前算缺口，现在已经不是了，但留着有用——**换校园时这三份名单得跟着重填**。

静态人群里有三片地方要特殊处理：足球队那两片站固定人数，沙滩那片换一组贴图，车站那片的朝向不朝北。**原先代码认的是它们的名字**（`football_team_blue` / `football_team_red` / `beach_crowd` / `station_static_crowd`）——新校园不一定还叫这些名字，所以改成了按序号认：

| 想改哪件事 | 改哪个配置项 | 现在填的序号 |
|---|---|---|
| 哪几片是足球队 | `static-crowd-tuning.json` 的 `footballRegionIndexes` | [51, 53] |
| 哪几片是沙滩人群 | 同上的 `beachRegionIndexes` | [52, 74] |
| 哪几片在车站 | 同上的 `stationRegionIndexes` | [29] |

**序号就是 `static-crowd-regions.json` 里每片地方的那个 `regionIndex`。** 换校园如果区域有增删，序号会跟着挪，照着那份区域表重填就行。

两个容易踩的点：

- **沙滩是两片，不是一处**（52 和 74）。原版这两片挂着同一个名字，都按沙滩处理。
- **改名字不再是问题，改序号才是。** 名字现在只是给人看的注释，代码不看它。

### 缺口 3（已关闭）：两个漏网的值也抽出来了

> 关闭时间：2026-09-20。下面这条以前算缺口，现在已经不是了——**人群躲铁轨的范围和喷水器的动画快慢都改得动了**。

呈现层接线做完之后还剩下**两个值没被圈进来**——一个藏在 `game/` 的呈现层里，一个是动画参数，既不算「有名字的常量」也不算「裸数字」，所以 22 份表里哪一份都没有它们。现在都补上了：

| 值 | 原先写死在哪 | 现在改哪 |
|---|---|---|
| 人群躲火车轨道那条带子 | `game/PhaserStaticCrowdRuntime.ts` 里的 `CROWD_TRACK_BAND` | `route-crowd-presentation.json` 的 `trackBand`（见下） |
| 喷水器动画每秒放几帧 | `game/PhaserSprayerRuntime.ts` 的 `createAnimations()` 里两处字面量 `6` | `sprayer-presentation.json` 里每张图的 `frameRate` |

**铁轨带这一处要单说**，因为它不是简单挪个位置。查下来当初是**两个适配器各写了一遍一模一样的常量**（不是共用同一个，是各写各的），值都是 400 / 1471 / 304 / 319。换校园挪了铁轨，只改一处配置就只会改一半——**静态人群照样杵在旧位置上**，而且这种错不会报错、只会看起来"有点不对"。

所以没有给它再抄一份，而是**合成一处**：两份表共读 `route-crowd-presentation.json` 的那个 `trackBand`。理由是铁轨在哪儿属于**世界事实**，不是某一类 NPC 的属性，两边本来就该同步。

> 想改人群躲铁轨的范围，去 `route-crowd-presentation.json` 找 `trackBand`——**别去 `static-crowd-presentation.json` 找，那儿没有，脚本里也不会报错**。

**喷水器那一处**是「画面快慢」：`frameRate: 6` 意思是每秒放 6 帧。两张图各有一份，因为站着喷水和跑动是两套动画。顺带一提，**6 比人物走路那套的 10 慢**——这是原版就有的差别，不是笔误，照抄没动。

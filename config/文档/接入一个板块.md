# 接入一个板块

**这份指南管一件事：把总表上还写着「没接」的板块，一个一个接上，让游戏真的去读配置。**

已经接完的：**SYS-NPC**（22 份配置）、**SYS-ROUTE**（4 份配置）。还有哪些没接、下一块挑谁，看[总表](换皮配置总表.md)卷首那张「板块索引」底下的**接线进度**。

板块之间互不干扰，这是刻意的设计——所以可以一个一个来，接完一个就是一个，不用等全部接完才能验收。

---

## 一句话说清「接线」是什么

现在这些值**住在代码里**。接线就是让它们**搬到 JSON 里**，并且让游戏**改从 JSON 读**。

举个最小例子。火车的「开出去多远」原来是这样：

```
// src/route/train.ts 里写死
const TRAIN_EXIT_DISTANCE = 4000;
```

接完之后变成：

```
// config/default/05-旁支/SYS-ROUTE/数据/train-config.json 里写着
"exitDistance": 4000
```

游戏不再认代码里那个常量，改认文件里那个数。**改文件、刷新页面，就生效，不用重新构建。**

---

## 三步

| 步 | 干什么 | 做完的标志 |
|---|---|---|
| **第一步 抽值** | 决定哪些数搬走、哪些留着，把它们抄成 JSON | 磁盘上有一份数据文件，`meta.verified` 写着 `exact` |
| **第二步 定目录** | 决定文件放哪、类型和校验写在哪 | 能用一个函数把这几份文件读成一个对象 |
| **第三步 换读取方式** | 改代码，让它从「读常量」变成「从配置读」 | 四关验收全过 |

**顺序不能颠倒。** 先抽值再接线，中间任何一步停下来，项目都是能跑的：第一步做完，代码还是读常量，只是旁边多了一份抄本；第二步做完，多了一个没被调用的读取函数。**只有第三步会改变游戏行为**，所以它放最后，而且做完立刻验。

---

## 第一步：抽值

### 先翻总表

[换皮配置总表](换皮配置总表.md) 里，每个板块一节，每个配置点一行，写着「来源」和「落点」。**照抄，不要重新发明。**

总表是**复制**不是**抽取**——原来系统卡上有的配置点，这里一个都不能少。照着总表做，就不会漏。

### 抽什么

| 该抽 | 例子（SYS-ROUTE） |
|---|---|
| 具体数值 | 火车进场 5 秒（`entryDurationMs`）、直升机停在 (504,1288) |
| 缩放、尺寸、个数 | 直升机 2 倍大（`scale`）、警车 3 辆 |
| 贴图规格 | 用哪张图、每帧切多大、一共几帧 |
| 一段区间的边界 | 火车碰撞带的 4 个横向区间（`collisionXZones`） |

### 不抽什么

这几类是 SYS-NPC 那轮定下来的，照着办：

| 不抽 | 例子 | 为什么 |
|---|---|---|
| **只有一个取值的类型标记** | `mode` 恒为 `"wander"`、`isHelicopter` 恒为 `true`、`wheels` 恒为 `false` | 这是**类型**不是数。留一个永远改不出效果的输入框，只会让人以为改了会有用 |
| **占位符** | `"UNKNOWN"` | 它表示「这块没查到」，不是个可选的值 |
| **算法** | 火车的缓动曲线（`cubicEaseOut`）、刀片角度的排布方式 | 换校园改的是数，不是公式。要改公式那是改代码 |
| **算得出来的值** | 直升机画在哪一层（`depth`）由它站的高度算出来；刀片数就是角度数组的长度 | **一个值只能有一个家**。算出来的不算家，存下来就是给同一个事实造第二份真相 |
| **联合类型** | `state: "arriving" \| "holding" \| ...` | 同「类型标记」 |

**「算得出来的值」有个例外**：如果一个值**原本就是个选项字段**（构造函数里当参数传进去的），那它本来就是配置，照抽不误。火车的 `tileSize` 就是这样——它一直是 `TrainRouteOptions` 上的一个字段，所以进了 `train-config.json`；而车辆那边 tileSize 是模块内部的一把尺子，就跟着格坐标一起**折算掉了**，没进配置。

### 单位怎么标

每份 JSON 的 `meta.units` 给字段标单位。校验器按单位查区间：`tile` 只允许 0..140，`pixel` 只允许 0..2240，`ratio` 和纯文本不查。

**三个坑，SYS-ROUTE 上全踩过：**

1. **`meta.units` 的键只能是顶层字段名。** 嵌套字段声明不了。所以 `vehicle-config.json` 干脆没写 `meta.units`——它的值都嵌在 `helicopter` / `police` 底下，单位改由 `shapes.ts` 逐字段落实（那才是真正管事的校验契约）。
2. **偏移量绝不能标 `pixel`。** 偏移可以是负数（`tailRotorOffsetEast.y` 是 `-11`），而 `pixel` 的范围是 0..2240，标上去等于自己把合法的负值拦下来。
3. **超出世界范围的像素值也不标。** 火车的 `startX` 是 2480、`exitDistance` 是 4000，都在地图外面（世界只有 2240 像素宽），标 `pixel` 会被误拦。

数字本身要**原样照抄**。代码里写 `5_000` 那是给人看的写法，JSON 里写 `5000`，值一样。这类差异记在 `meta.notes` 里。

### 每份 JSON 顶上的 meta

| 字段 | 写什么 |
|---|---|
| `system` | 板块名，比如 `"route"` |
| `source` | 从哪个代码文件抽的 |
| `sourceConstant` | 抽的是哪些常量，一个不许漏 |
| `units` | 顶层字段的单位（可以不写，见上面的坑 1） |
| `verified` | 抄得准不准。逐一对得上写 `exact` |
| `notes` | 抄的时候做的判断：哪些值没抽、为什么、哪些数字改了写法 |

`notes` 别省。半年后有人问「这个 2480 怎么没标单位」，答案得在文件里，不能只在谁的脑子里。

## 第二步：定目录

### 文件放哪

```
config/
├── 骨架/<分区>/SYS-XXX/逻辑/     ← 读法和校验，所有校园共用
│   ├── types.ts                  这个板块有哪些数据形状
│   ├── shapes.ts                 每个字段怎么校验
│   └── index.ts                  一个函数读完全部
└── default/<分区>/SYS-XXX/数据/   ← 数字，一个校园一套
    └── *.json
```

`<分区>` 就是总表的分区号，比如 `05-旁支`。

### 三个文件各管什么

**`types.ts` 只转发，不自己定义。** 这条是硬规矩：**一个类型只有一个出处，就是 `src/`**。

```ts
export type { TrainConfig, TrainRouteOptions } from "../../../../../src/route/index.js";
```

只有一种情况例外：这个类型**本来就只活在呈现层**，`src/` 里根本没有对应的东西（比如「用车图哪几帧」）。那种就定在 `types.ts` 里，但仍然**只有这一份**。

**`shapes.ts` 是真正管事的校验契约。** JSON 是死的，改错一个字（少个字段、多个字段、单位超范围）得当场拦住。`meta.units` 只是文件里的备注，**拦截力度以 `shapes.ts` 为准**。

**`index.ts` 是加载入口。** 两样东西：

```ts
// 一个文件：来源取生数据 → 整理成可信文件 → 按形状校验
readXConfig<T>(key, source)
// 这个板块的全部文件，一次并发读完
loadXConfigs(source): Promise<XConfigs>
```

`source` 必须**由调用方递进来**，这里不自备默认值。理由和「公共不许 import 板块」是同一条：读法会变（现在是 fetch，将来后台可能带鉴权），这一层只管「读哪些、怎么拼」。

### 目录还有一条规矩

### 依赖方向是单向的

三条，别绕回去：

- **`骨架/公共/` 不许 import 任何一个板块。** 方向只能是「板块 → 公共」。反过来就会缠成一团，改一个系统牵动所有系统。
- **`src/` 不许 import `config/`。** 配置是外面喂给 `src/` 的，不是 `src/` 自己去拿的。
- **`game/` → `config/` 是允许的**，这是已确立的方向（`game/` 是适配器层，它负责「去读配置，再喂给 `src/`」）。

## 第三步：换读取方式

### `src/` 的红线

**`src/` 是复刻基准，默认一个字不许改。** 接线时只许按三类动：

| 类 | 干什么 |
|---|---|
| **① 把值搬走** | `export const XXX_CONFIG = {...}` 这类具体数值常量，整个删掉 |
| **② 把藏着的值挖出来** | 写在函数体里、或者模块私有的值，加 `export` 或提到顶层。**只搬位置，不改数值、不改算法** |
| **③ 改「去哪儿取数」** | 从「import 那个常量」改成「从加载器拿配置」 |

**绝对不许动**：所有 `interface` / `type`（字段定义）、所有算法、Phaser 的一切、资产文件、`doc/` 全部。

**关于 `doc/` 那句「不许动」**：值搬走以后，逆向文档里那些「`TRAIN_START_X` 在 `src/route/train.ts:1`」的指路牌就过期了——常量已经不在那儿了。**这是已知的、故意的**，SYS-NPC 那轮也一样（`doc/03-执行层/05-旁支/01-NPC.md` 到现在还写着 `STATIC_CROWD_FACTOR`）。

原因是**两份文档分工不同**：`doc/` 是逆向成果，记的是「原版这个系统是什么样」；值的**新住址**记在[换皮配置总表](换皮配置总表.md)里。所以接线这一轮只改总表，不碰 `doc/`。要统一收拾，那是另一件事。

**连带结果**（这三条是上面三类做完必然会撞上的）：

- 值改成外面递进来之后，`XXX?: number` 这种**可选**字段必须变成**必填**——外面一定会递，写成可选就是骗人。
- `constructor(options = {})` 那个 `= {}` 去掉。**留了默认值就等于「没配置也能跑」**，场景悄悄变稀疏比硬报错更难查。
- **字段名和类型一个都不变**，只是"从哪来"变了。

**怎么验证没越界**：把改动 diff 出来逐条对照，每条都必须能归进三类；归不进去就是越界了。

### `game/` 里的适配器

每个适配器多一个必填的 `route`（换成自己板块的名字）选项，构造函数里存下来：

```ts
this.config = options.route;
this.presentationScale = this.config.presentation.train.presentationScale;
this.presentationDepth = playerDepth(this.config.train.y);
```

**注意后面两行在干什么**：它们是**算出来的**，不是从配置里读的。配置里存的是「火车停在世界坐标 y=310」，深度是拿 y 现算的——因为深度不属于火车，属于整个世界。这就是第一步「算得出来的值不抽」在代码里的样子。

另外，原来导出的常量（`TRAIN_SCALE`、`TRAIN_PRESENTATION_DEPTH`）**整个删掉**，别留着当二手来源。

### `game/main.ts`：加进那个 `Promise.all`

```ts
void Promise.all([
  loadNpcConfigs(configSource),
  loadRouteConfigs(configSource),   // ← 新板块加一行
]).then(([npcConfigs, routeConfigs]) => { ... });
```

**是并发，不是排队**：板块之间互不依赖，排队只会让首屏多等一趟网络。板块多了也一样，谁慢等谁。

场景构造函数跟着多收一组配置，一个板块一个参数：

```ts
new CampusScene(npcConfigs, routeConfigs, callbacks)
```

**为什么只在启动前读这几个板块**：Phaser 有一条硬规矩——贴图规格（每帧多大、几帧）必须在上场之前报上去，而那个阶段是**同步**的，等不了网络。所以会碰到贴图的板块必须在「读配置 → 造游戏 → 登记贴图」这条链子上。不会碰贴图的板块，起来之后再读。

### 测试跟着改

测试里那些「从 `src/` 拿常量」的地方，换成**从磁盘读配置**：

```ts
const ROUTE_CONFIGS = await loadRouteConfigs(createDiskConfigSource());
const TRAIN_CONFIG = ROUTE_CONFIGS.train;
const TRAIN_START_X = TRAIN_CONFIG.startX;
```

**这么写不是偷懒，是更严**：它验的是「游戏实际读的就是这份文件」。真按旧常量再抄一遍，配置改坏了测试也照样绿。

还有一处**容易漏**：凡是 mock 掉配置加载的测试（`tests/app/main-cleanup.test.ts` 那种），**新板块要补一行 mock**。漏了的话真实现会去发网络请求，测试就红了。

### 新板块要写一份自己的配置测试

照着 `tests/config/route-config-extraction.test.ts` 写，六类内容：

1. **值对不对**：逐个字段和原代码核对，连 `1.025 === (1/3)*0.75*4.1` 这种算式也验
2. **冻结了没有**：读出来的对象每一层都不能被改
3. **meta 齐不齐**：key 列表、`notes` 在不在、`source` 指的文件真的存在
4. **清单对得上磁盘**：磁盘上有什么文件，`KEYS` 就得有什么
5. **单位标注对得上形状**：`meta.units` 里标的字段，`shapes.ts` 里也得有
6. **改坏了会被拦住**：喂几个错值进去（超范围、缺字段、多字段、NaN），确认抛错

## 四关验收

改完代码，**四关都要过**，一关都不能省：

| 关 | 命令 | 过不了说明什么 |
|---|---|---|
| 类型 | `npx tsc --noEmit` | 有地方还在用已经删掉的旧常量 |
| 测试 | `npx vitest run` | 行为变了 |
| 构建 | `npm run build` | 打包时才发现的问题（比如资产路径） |
| **真浏览器** | `npm run browser:config-live-smoke` | **配置到底接上了没有** |

**第四关是最后一关，也是唯一能证明「改一个值刷新就看得见」的一关。** 前三关全绿，配置也可能只是躺在 JSON 里没人读。

### 第四关怎么加自己板块的用例

打开 `scripts/browser-config-live-smoke.mjs`，两处要动：

**一、往 `TESTS` 表里加几条。** 每条写清：改哪个文件、改哪个值、从哪个镜头看。

**二、往 `MEASURE` 里加这个板块要量的数。** 这是关键——**得能量出来**，不能只是「跑完没报错」。SYS-ROUTE 量的是运行时快照里的 `x` / `y` / `scale`，这些数直接取自画面上那个对象，所以「快照变了」等价于「画面上那个东西变了」，截图也一并存着可以对着看。

**两条硬要求：**

- **要量的数当场就得是稳定的。** 火车那条一开始就是反面教材：进场流程结束时火车**还在开出去**，这时候量到的是「这一刻开到哪儿了」，两次跑差几百像素可能只是加载快慢——看着变了，其实跟改的那个值没关系。**量到没稳定的数，比没量到更坏**：报告是绿的，结论却是错的。给用例加个 `settle`，等它真停下再量。改完那条量出来的是 `-3520` 和 `-520`，正好是 `480-4000` 和 `480-1000`，这才叫对得上。
- **人群撒点是随机的**，`staticCrowdTotal` 两次加载会差 ±5。报告里看到这类数字变了，那多半不是你的配置起了作用，**认准你要验的那个键**。
- **火车也一样**：不是火车那几条用例时，`train` 会出现在「变了什么」里——那只是两次跑拍到的时刻不同，火车还在半路上。**只有用例 14 那一条的 `train` 是算数的**，因为它专门等了火车停下来。

### 顺手别忘了「套」

**加完一个板块，每一套 set 都要补齐这个板块的数据文件。**

```
config/default/05-旁支/SYS-ROUTE/数据/   4 份
config/set1/05-旁支/SYS-ROUTE/数据/      4 份  ← 少一份这套就是坏的
```

**一套 set 必须齐全。** 缺文件不是「用原版的」，是**开不了游戏**：所有板块的配置是一起并发读的，谁 404 谁把整批拖下水。这是故意的——照着 [README](../README.md) 的三步走（复制 `default/` 整个目录），正常路径下不会缺；真缺了就该当场报错，而不是「看着正常、其实一半读的是原版」。

**这一步最容易忘**，因为做的时候一直在 `default/` 上测。加完记得回头把每一套 set 都补上，并且顺手在 set 里改一个**看得见的值**，让 `?config=<set>` 真能演示这个板块。

## 名词解释

| 词 | 什么意思 |
|---|---|
| **板块** | 一个系统，比如「NPC」「路线」。总表按板块分节 |
| **接线** | 让游戏改从配置读，而不是从代码里的常量读 |
| **骨架** | `config/骨架/`，读配置的代码和校验规矩，所有校园共用 |
| **集 / set** | 一个校园的一套数字，比如 `default/`、`set1/` |
| **复刻基准** | `default/`。它那套值必须和原版逐一对得上，所以别改它 |
| **形状 / spec** | 一个字段「是什么类型、什么范围」的说明书，写在 `shapes.ts` |
| **契约** | 同上。真正管拦截的是它，不是 JSON 里的 `meta.units` |
| **呈现层** | 管「长什么样」的那一层：用哪张图、多大、画在哪一层 |
| **派生值** | 能由别的值算出来的值。**不算家**，不抽 |
| **冻结** | 把读出来的对象锁死，防止有人半路改它 |
| **套（这里的用法）** | 同「集」 |

# 后台平台文档

> 这里只放后台管理系统（校园内容与配置运营平台）的文档。游戏逆向的文档在仓库根 `doc/`，两边不混。
> 代码在 `admin/`；怎么启动看 [`admin/README.md`](../README.md)；本目录管需求、设计、测试和约定。

## 一、为什么单独开一块

游戏那套文档（`doc/01-理解层` ～ `doc/06-网络协议层`）是"同一件事讲三遍、一遍比一遍细"的逆向尺子。后台是另一条产品线，有自己的页面、接口、数据库和运营规则，套游戏那套尺子会打架。所以后台从需求到测试全部放在这里，一个板块一个板块往下走。

## 二、按流程分文件夹，板块写进每个流程

```text
admin/doc/
  README.md                 本文件：总纲、板块清单、进度
  00-已定决策.md              Human 已拍板的决定（D-001 起）；改设计先看这里
  00-技术约定与日志.md        横向：技术栈、日志、错误处理、配置标准
  00-平台契约.md             横向：返回格式、错误码、权限位、审计动作、发布状态机
  01-需求收集/
    README.md               本阶段怎么收、收到什么算完
    00-平台总需求.md         平台级需求 RQ-PLAT-001～020
    BG-01-平台底座.md
  02-需求分析/
    README.md
    00-平台总PRD.md          平台级方案、板块拆分、交付轮次
    BG-01-平台底座.md
  03-概要设计/
    README.md
    BG-01-平台底座.md       A0 版，待重写
  04-详细设计/
    README.md
    BG-01-平台底座.md       A0 版，待重写
  05-测试设计/
    README.md
    BG-01-平台底座.md       A0 版，待重写
  99-原始件/
    README.md               录音、合同、外部文档、脑图放哪、怎么命名
```

规则只有三条：

1. **同一个板块 ID 贯穿五个阶段。** 想看完一个板块的全貌，按 ID 在五个文件夹里找同名文件。
2. **每个阶段文件夹先看 `README.md`。** 那里写本阶段的入口、检查项和板块索引。
3. **跨板块共用的东西放 `00-` 开头两份文件里。** 每个板块不各写一套返回格式、错误码和审计动作。

## 五、这一版怎么推进

1. **需求收集 + 需求分析先评审。** 平台级两份和 BG-01 两份先给 Human 看，确认"重做"口径、范围和验收标准。
2. **BG-01 继续走概要设计、详细设计、测试设计。** 三份旧文件要按重做口径重写，不能直接改 A0 版。
3. **实施第一步做归档。** A0 代码归档、A0 审计导出、新库新表（D-001）。
4. **BG-01 全部跑通后再开 BG-02。** 一个板块走完再开下一个，不并行铺开（D-010）。
5. 每走完一个阶段，回本文件更新进度表。

## 六、文档状态怎么看

- 每份板块文件头部有 `阶段`、`状态`、`更新` 三行；状态和本文件进度表冲突时，以文件头部为准，并回来修正进度表。
- 标注"A0 版，待重写"的文件，只能用来查"A0 当时怎么想"，不能当实施依据。
- 已定决策只认 [`00-已定决策.md`](00-已定决策.md)；别处写的"建议""默认"都不算定。

> 现在这一版是 AI 起草的草稿，不是已确认结论。原始材料只当来源，Human 确认后才算项目指令。

# 02-需求分析

> 本阶段回答两句话："客户到底想要什么"和"我们打算怎么做"。

## 一、输入

上一阶段的需求清单（`01-需求收集/BG-xx-名称.md`）。

## 二、做法

1. 先给结论：这个板块本轮做到什么程度，一句话说清。
2. 写清用户和场景：谁用、什么时候用、用完得到什么。
3. 划范围：本轮做什么、不做什么、为什么不做。
4. **一条需求对一个方案**：编号沿用需求编号，写清怎么实现、依赖什么、边界在哪。
5. 每条方案配**能执行的验收标准**：不是"体验流畅"，而是"未登录访问 `/admin` 跳到 `/login`"。
6. 方案有取舍的，写清选了什么、放弃了什么、风险是什么。
7. 还没定的决策单列，不假装已经定了。

## 三、交付物

每个板块一份 `BG-xx-名称.md`（PRD 或技术需求分析报告），包含：

- 结论与目标
- 用户与场景
- 范围（做 / 不做）
- 需求到方案的映射表
- 关键方案说明
- 验收标准
- 风险与待确认

## 四、算完成的标志

- 每条需求都有方案，或明确写"本轮不做"；
- 每条验收标准都能实际验证；
- 范围外写清了，没有含糊的"以后再说"；
- 待确认的决策没有混进已确认方案。

# BG-01 平台底座 — 需求分析（重做版）

> 阶段：需求分析 | 状态：草稿，待 Human 评审 | 更新：2026-10-25
> 上游：[`01-需求收集/BG-01-平台底座.md`](../01-需求收集/BG-01-平台底座.md)；决策见 [`00-已定决策.md`](../00-已定决策.md)

## 一、结论

平台底座第一圈重做成三件事：**一扇可信的门、一本可查的账、一份不泄密的设置页**。

- 门：登录、登出、12 小时会话、登录限流、停用即失效。
- 账：登录成功/失败、登出、关键写操作都记审计；审计能分页查、按校园和动作筛、能导出 CSV。
- 兜底：忘记密码走命令行重置，不先做页面。
- 设置页只读，密钥只显示"已设置"。

账号管理、多角色、按校园分权一律放 BG-07。第一圈不碰，避免和权限板块打架。

**重做口径**：新代码从零写，A0 代码只作参考；A0 审计先导出，A0 代码归档；数据库新建，不迁移旧表结构（D-001）。

## 二、用户与场景

| 用户 | 场景 | 期望 |
|---|---|---|
| 平台管理员 | 每天登录后台，改配置、看审计 | 登录快、会话稳、操作有记录 |
| 平台管理员 | 换了电脑或忘了退出 | 12 小时后自动失效，不用手动记 |
| 平台管理员 | 忘了密码 | 能在服务器上命令行重置，不用重装 |
| 运维 / 接手人 | 查"谁在什么时候改了什么" | 审计字段齐、能筛选、能导出 |
| 未来的编辑者 / 查看者 | 只看或只改 | 角色位预留，BG-07 启用 |

## 三、范围

### 本轮做

- 邮箱 + 密码登录；停用账号不能登录；停用后旧会话立刻失效。
- 登出，并写审计。
- 12 小时会话，不做"记住我"。
- 登录失败限流：单实例内存计数。
- 登录成功/失败、登出、关键写操作写审计。
- 审计列表：分页、按校园和动作筛选、仅登录用户可见。
- 审计 CSV 导出；保留至少 180 天；自动清理后置。
- 设置页只读展示环境信息，密钥隐藏。
- 统一接口返回格式、错误码、CSRF 同源校验。
- 角色字段预留，不做权限判断。
- 命令行密码重置脚本。
- 重做前的 A0 审计导出和代码归档。
- 本板块的自动化测试。

### 本轮不做

| 不做 | 原因 | 去向 |
|---|---|---|
| 账号新建、停用、改密页面 | 先保证门能进、账能查 | BG-07 |
| 多角色权限矩阵、按校园分权 | 需要先有账号管理 | BG-07 |
| 审批流、编辑/发布分离 | 同上 | BG-07 |
| 找回密码邮件 / 页面 | 先用命令行兜底 | 后置 |
| 多实例共享限流、分布式锁 | 第一版单实例 | 多实例前单独立项 |
| 审计自动清理任务 | 先做导出和保留策略 | 下一圈 |
| SSO、LDAP、微信登录 | 没有来源 | 不做 |

## 五、关键方案说明

### 5.1 登录与会话

沿用 Auth.js Credentials + JWT，不引入新服务。理由：后台访问量小，单实例部署，SQLite 足够；换数据库会话或外部认证服务没有收益。

```text
输入邮箱/密码
→ 去空格、邮箱转小写
→ 检查限流（邮箱+IP）
  ├── 已锁定 → 统一错误
  └── 未锁定 → 查 AdminUser
        ├── 不存在 → 记失败 + 统一错误
        ├── active=false → 记失败 + 统一错误
        └── bcrypt.compare
              ├── 不匹配 → 记失败 + 统一错误
              └── 匹配 → 清限流 + 记成功 + 签发 12 小时 JWT
```

### 5.2 登录限流

- 键：`email|ip`，邮箱已转小写，IP 取 `x-forwarded-for` 第一段。
- 窗口：15 分钟；窗口内失败 5 次，锁 15 分钟。
- 成功一次清零。
- 锁定期间对外仍返回统一错误，不告诉攻击者"你被锁了"。
- 内存 Map 定期清理过期条目，避免无限增长。
- **只在单实例有效**；重启清零；多实例时每个实例各算各的。上线多实例前必须换成共享存储（RQ-BG01-026）。

### 5.3 停用账号与已登录会话

现状只检查"登录那一刻"的 `active`。账号停用后，已经签发的 JWT 在过期前仍然有效。重做后：

- `session` 回调里按 `token.sub` 查一次 `AdminUser.active`。
- 查不到或 `active=false`，返回空会话，页面跳登录页，接口 401。
- 代价：每个需要登录的请求多一次 SQLite 查询。后台用户少，可以接受。
- 会话本身仍保持 12 小时；停用是"立刻失效"的唯一手段。

### 5.4 密码重置

- 脚本：`npm run admin:reset-password -- --email <邮箱>`。
- 交互式输入新密码两次；至少 12 位；输入不回显。
- 直接写 bcrypt 哈希，不经过 Web 接口。
- 要求：能登录服务器、能执行 npm 脚本。没有这个权限的人不能重置。
- 页面和邮件找回后置，不在本轮。

### 5.5 审计

- 登录成功/失败：不阻断登录，写失败打服务端错误日志。
- 登出：写一条 `logout`，写失败不阻断退出。
- 业务写操作：审计失败就让操作失败，避免"改了但没记录"。
- 日志里绝不写密码、令牌、密钥、完整配置正文。
- `detail` 用短字符串或 JSON 摘要；大内容只记哈希。
- 保留至少 180 天；CSV 导出由服务端生成，仅登录用户可用。
- 自动清理任务下一圈再做；本轮只在文档里写明保留策略。

### 5.6 权限位

`role` 只存不用。本板块不写权限判断，页面和接口只判断"有没有登录"。BG-07 再启用角色。

### 5.7 错误与 CSRF

- 统一返回格式见 [`00-平台契约.md`](../00-平台契约.md)。
- 写接口校验 `Origin` 与 `Host` 同源。反向代理部署时必须正确转发 `Host` / `X-Forwarded-Host`。
- 错误响应不返回堆栈、SQL、绝对路径。

### 5.8 设置页

只读，不提供修改入口。显示配置根、发布根、数据根、数据库、游戏地址；`AUTH_SECRET`、`ADMIN_PASSWORD` 一类只显示是否设置。以后要改配置走部署流程。

## 六、验收标准

### 功能

- [ ] 正确邮箱密码能登录并进入 `/admin`。
- [ ] 错误密码、不存在账号、停用账号都看到同一句错误提示。
- [ ] 未登录访问 `/admin/*` 跳 `/login`；调 `/api/admin/*` 返回 401。
- [ ] 登录成功、登录失败、登出各有一条审计记录。
- [ ] 连续输错 5 次后，正确密码也被暂时拒绝；15 分钟后恢复。
- [ ] 登录 12 小时后会话失效，需要重新登录。
- [ ] 停用账号后，已登录浏览器下一次请求被踢回登录页。
- [ ] 审计列表能分页、按校园筛选、按动作筛选。
- [ ] 审计能导出 CSV，Excel 打开不乱码，字段齐全。
- [ ] 设置页显示根路径，密钥只显示"已设置（内容隐藏）"。
- [ ] 带错误 `Origin` 的写请求返回 403；同源写请求正常。
- [ ] 命令行能重置密码，旧密码随即失效。
- [ ] 数据库里没有明文密码；日志里没有密码和令牌。

### 重做与数据

- [ ] A0 审计已导出成 JSON + CSV，存在 `bak/admin-a0-20261025/`。
- [ ] A0 代码已归档，新代码从零写，不直接改 A0 文件。

### 约束

- [ ] 不修改游戏运行时，不新增游戏对后台的依赖。

- [ ] `npm run typecheck`、`npm run test`、`npm run build` 全部退出码 0。

## 七、风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 内存限流重启清零 | 重启后暴力破解窗口重新打开 | 可接受；多实例前换共享存储 |
| 内存限流只对一个实例有效 | 多实例时限流失效 | 第一版明确单实例；多实例前立项 |
| JWT 无法主动吊销 | 停用后旧会话仍有效 | 方案 5.3：每次读会话查 `active` |
| 只有一个管理员 | 忘记密码会锁死 | 命令行重置脚本 |
| 登录审计写失败被吞 | 审计缺失且没人知道 | 本轮补服务端错误日志 |
| 审计 CSV 含 IP / User-Agent | 导出文件泄露个人信息 | 仅登录用户可导出；文件不外发 |
| 审计表持续增长 | 查询变慢、备份变大 | 180 天保留；下一圈做清理任务 |
| SQLite 并发写 | 多人同时写审计可能锁等待 | 单实例；后续量上来再换库 |
| 反向代理下 IP 不准 | 审计 IP 是代理地址 | 明确信任的代理层数；本轮只取 `x-forwarded-for` 第一段 |
| 重写丢掉 A0 已修的坑 | 新代码重新踩坑 | 把 A0 测试当检查清单，逐条重写测试 |

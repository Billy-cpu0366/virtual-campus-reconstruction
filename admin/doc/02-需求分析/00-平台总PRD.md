# 后台平台总 PRD（重做版）

> 阶段：需求分析 | 状态：草稿，待 Human 评审 | 更新：2026-10-25
> 上游：[`01-需求收集/00-平台总需求.md`](../01-需求收集/00-平台总需求.md)；决策见 [`00-已定决策.md`](../00-已定决策.md)

## 一、结论

重做一套**校园内容与配置运营平台**：一个后台管多个校园，配置和内容走"草稿 → 预览 → 发布 → 回滚"，所有写操作可审计。

重做不是把 A0 推倒后凭记忆再写一遍，而是：

1. **保留 A0 已验证的模型**：配置是唯一真相、校验只有一份、发布整批原子替换、审计落表。
2. **重写代码和界面**：不背 A0 的结构债，不复制 A0 的页面和组件。
3. **补 A0 没做的安全项**：登录限流、停用即失效、会话收紧、密码重置脚本、审计导出。
4. **按板块推进**：BG-01 先走完五阶段，Human 确认后再开 BG-02。

第一轮只做 **BG-01 平台底座**。它是所有板块的门和账本；它不稳，后面的板块都白做。

## 二、用户与场景

| 场景 | 用户 | 结果 |
|---|---|---|
| 每天登录后台改配置 | 平台管理员 | 登录快、会话稳、改动有记录 |
| 新开一个学校 | 平台管理员 | 从 `default` 复制一套配置，独立编辑、独立发布 |
| 改错一个值 | 管理员 | 预览能看到效果；发布后可回滚 |
| 查"谁把玩家改大了" | 运维 / 接手人 | 审计里有操作人、时间、文件、前后哈希 |
| 以后只看不写 | 查看者 | 权限位已预留，BG-07 启用 |

## 三、平台范围

### 做

- 多校园管理，校园为最高一层。
- 配置文档的读取、编辑、校验、草稿。
- 预览、发布、回滚、历史版本。
- 账号、登录、会话、审计。
- 素材和内容模块（后续轮次）。
- 后台骨架统一，新模块只加页面、接口和数据，不改底层。

### 不做

- 完整游戏编辑器（地图编辑、剧情编排、任务编辑）。
- 游戏运行时依赖后台。
- 多人在线协同编辑、实时在线状态。
- 账号自助注册。
- 照搬 WorkAdventure 的宇宙/世界/房间/成员/封禁模型。
- Redis、对象存储、消息队列、GraphQL、tRPC。

## 四、总体方案

### 4.1 架构

```text
浏览器
├── 游戏静态站
│     └── 只读 /config/<集名>/*.json
│
└── 管理后台（admin/，Next.js）
      ├── 复用 config/骨架 的 Spec、validate、各系统 loader
      ├── 草稿目录 → 预览集 → 发布到 config/<校园>
      └── SQLite：账号、校园元数据、版本索引、审计
```

### 4.2 三条硬原则

1. **配置文件是配置值的唯一真相。** 数据库不存配置正文。
2. **校验只有一份。** 后台 import `config/骨架`，不复制规则。
3. **发布是整批原子替换。** 全量校验 + 快照 + 整批替换；缺一份游戏就起不来。

### 4.3 数据归属

| 数据 | 存哪 | 说明 |
|---|---|---|
| 配置正文 | 磁盘 `config/<校园>/`、草稿、快照 | 已发布内容本来就是公开静态文件 |
| 账号、密码哈希 | SQLite | 只存 bcrypt 哈希 |
| 校园元数据 | SQLite | 显示名、状态、来源 |
| 版本索引 | SQLite | 快照目录和文件数 |
| 审计 | SQLite | 操作人、动作、文件、前后哈希、IP |

### 4.4 权限演进

- 第一轮：只区分"已登录 / 未登录"。
- `role` 字段先留 `admin` / `editor` / `viewer`，不用来拦。
- BG-07 再做按校园分权、编辑与发布分离。

### 4.5 审计

- 所有写操作落 `AuditLog`；登录成功/失败、登出也落。
- 审计只记摘要和哈希，不记密码、令牌、完整配置正文。
- 保留至少 180 天；先做 CSV 导出，自动清理后置（D-007）。

### 4.6 模块化

每个板块自己声明：

1. 自己的数据结构与校验；
2. 自己的编辑界面；
3. 发布后导出成什么；
4. 挂在同一套"校园 → 草稿 → 预览 → 发布 → 回滚 → 审计"骨架上。

### 4.7 重做策略

1. 开工前把 A0 代码归档到 `bak/admin-a0-20261025/`，只读参考。
2. 把 A0 审计导出成 JSON + CSV，存同一备份目录（Q-PLAT-01）。
3. 新建数据库，不迁移 A0 表结构；表结构按重做后的设计重建。
4. 复用 `config/骨架` 的校验和 loader，不复制。
5. A0 的测试当检查清单，不直接复制；重做后的测试按事件重新写。

## 五、平台级需求到方案

| 需求ID | 方案 | 验收标准 |
|---|---|---|
| RQ-PLAT-001 | 校园是最高层；配置根按 `config/<校园>/` 组织；草稿和快照按校园分目录。 | 能列出多个校园；每个校园的配置、草稿、发布历史互不影响。 |
| RQ-PLAT-002 | 单值配置点用表单，多实例配置用表格；两种形态最终都写同一份 JSON。 | 两种编辑方式保存后都能通过整套校验。 |
| RQ-PLAT-003 | 素材建索引表，记录文件路径和引用关系；素材配置点能反查引用。 | 能查"这张图被哪些配置用了"和"这个配置点用了哪张图"。 |
| RQ-PLAT-004 | 内容模块用独立表或独立文件，配独立编辑器；不塞进 40 份配置 JSON。 | 公告/剧情能独立增删改查，不影响游戏配置。 |
| RQ-PLAT-005 | 统一状态机：草稿 → 预览 → 已发布 → 历史/回滚。 | 保存草稿不影响线上；预览不改变线上；发布后能回滚。 |
| RQ-PLAT-006 | 后台提供统一外壳、导航、权限、审计；板块只注册自己的页面和接口。 | 加一个新模块不需要复制布局和登录逻辑。 |
| RQ-PLAT-007 | 配置正文只落磁盘；数据库只存元数据、索引和审计。 | 数据库里搜不到配置正文。 |
| RQ-PLAT-008 | 后台直接 import `config/骨架` 的 `Spec`、`validate()`、`load*Configs()`。 | 同一份配置在后台和游戏侧校验结果一致。 |
| RQ-PLAT-009 | 发布：全量校验 → 快照当前 → 临时目录 → 原子替换；持有校园锁。 | 发布中途失败不会留下半套配置；失败能回退。 |
| RQ-PLAT-010 | 游戏只读静态 JSON；后台接口不进入游戏运行时。 | 停掉后台，游戏仍能正常启动和运行。 |
| RQ-PLAT-011 | 每浏览器独立 JWT；同一文件保存带 `baseHash`，不一致返回 409。 | 两个账号改不同文件互不影响；改同一文件后保存的人收到冲突提示。 |
| RQ-PLAT-012 | 统一 `AuditLog`；写操作调用同一个审计函数；动作名走白名单。 | 每个写操作都能在审计里查到，字段齐全。 |
| RQ-PLAT-013 | 集名白名单；路径 `resolve` 后检查根前缀；拒绝符号链接。 | `../`、绝对路径、越界路径、符号链接全部被拒。 |
| RQ-PLAT-014 | 重写 `admin/`；A0 代码归档；A0 审计导出；新库新表。 | 新代码能独立启动；旧数据有备份；旧代码可查。 |
| RQ-PLAT-015 | 技术栈按 D-001 和 A0 规格：Next.js、TypeScript、Tailwind、SQLite+Prisma、Auth.js、bcryptjs、Vitest。 | 不新增未批准依赖；`package.json` 可核对。 |
| RQ-PLAT-016 | 第一版单实例；限流用内存计数；发布锁用文件锁。 | 单实例下限流和锁有效；文档写明多实例限制。 |
| RQ-PLAT-017 | 中文界面；每个异步区块有加载/空/错/成功四态；错误文案可操作。 | 不出现白屏和静默失败。 |
| RQ-PLAT-018 | 每板块五阶段文档 + 事件驱动测试；测试可一键重跑。 | 阶段文档齐全；`npm run test` 覆盖主要事件。 |
| RQ-PLAT-019 | 第一轮只判断登录状态；角色随会话传递但不拦。 | 未登录被拦；登录后都能用。 |
| RQ-PLAT-020 | 账号管理放 BG-07；BG-01 只做初始化账号和命令行重置。 | BG-01 没有账号增删改页面。 |

## 六、板块方案摘要

| 板块 | 目标 | 第一轮必须 | 暂不做 | 验收 |
|---|---|---|---|---|
| BG-01 平台底座 | 一扇门 + 一本账 | 登录、登出、12 小时会话、限流、停用即失效、审计记录/查询/CSV、设置页、命令行重置 | 账号管理、找回密码页面、多角色 | 未登录被拦；登录/登出/失败都有审计；停用即失效 |
| BG-02 校园管理 | 校园是第一层对象 | 列表、从 `default` 新建、只读基准、元数据 | 删除校园、批量导入 | 能新建校园；`default` 不能改；各校园独立 |
| BG-03 配置编辑 | 把配置值管住 | 文档树、JSON 编辑、格式校验、草稿保存、冲突提示 | 自动表单、全站搜索、结构化 diff | 改一个值能保存；非法值被拦并给字段路径 |
| BG-04 发布与版本 | 让改动安全上线 | 预览、发布、回滚、锁、历史列表、发布目标同步 | 定时发布、审批流 | 预览不影响线上；发布原子；回滚能恢复 |
| BG-05 素材管理 | 管文件和引用 | 上传、规格登记、引用关系查询 | 对象存储、图片编辑 | 能查"谁在用谁"；删文件前有引用提示 |
| BG-06 内容管理 | 管公告/剧情等内容 | 公告的增删改查、上下线时间、按校园/区域投放 | 剧情树、任务系统 | 公告能定时上下线；不影响配置 |
| BG-07 权限与运营 | 多人分权 | 账号管理、角色、按校园分权、审批、监控 | 单点登录、外部账号同步 | 不同角色只能做允许的事；操作有审计 |

## 九、风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 重写丢掉 A0 已修的坑（路径安全、原子写、部分发布） | 新代码重新踩坑 | 把 A0 测试当检查清单；逐条重写测试 |
| 后台 import 根目录外的 `config/骨架` | Next.js 可能报错 | 先试 `externalDir` / tsconfig include；不行写薄再导出；绝不复制 Spec |
| Windows 目录 rename 失败 | 发布/回滚中断 | 捕获错误、回退旧目录、返回明确错误；测试覆盖 |
| Auth.js beta 版本接口变化 | 登录不可用 | 锁版本；升级前先跑登录测试 |
| 内存限流重启清零 / 多实例失效 | 暴力破解窗口 | 第一版单实例；多实例前换共享存储 |
| 只有一个管理员 | 忘记密码锁死 | 命令行重置脚本；文档写清用法 |
| 审计表越来越大 | 查询变慢、备份变大 | 180 天保留；CSV 导出；后续加清理任务 |
| 多人改同一文件 | 后保存覆盖前保存 | `baseHash` 乐观锁，冲突返回 409 |
| 配置目录含中文 | 路径编码错误 | URL 逐段编码/解码；测试用中文路径 |
| SQLite 并发写 | 锁等待或写失败 | 单实例；写操作串行；量上来再换库 |

## 十一、完成定义

一个板块算完成，必须同时满足：

1. 五阶段文档齐全，Human 已确认；
2. 代码按详细设计实现；
3. 测试设计里的每个事件都有自动化用例，或有明确的不做理由；
4. `npm run typecheck`、`npm run test`、`npm run build` 全部退出码 0；
5. 验收路径实际走通，报告写实际结果，不写"应该可以"；
6. 进度回写到 [`admin/doc/README.md`](../README.md) 和 [`00-已定决策.md`](../00-已定决策.md)（如有新决定）。

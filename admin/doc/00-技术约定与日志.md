# 技术约定与日志

> 这份文件管后台所有板块共用的技术标准。板块自己的设计不重复写这里的内容，只写"本板块用到了哪几条"。

## 一、技术栈

| 项 | 约定 | 现状出处 |
|---|---|---|
| 运行时 | Node.js 22（`>=22 <23`） | `admin/package.json` |
| 框架 | Next.js App Router（当前 16.x） | `admin/package.json` |
| 语言 | TypeScript，`strict: true` | `admin/tsconfig.json` |
| 样式 | Tailwind CSS 4；不强制引入组件库 | `admin/package.json` |
| 数据库 | SQLite + Prisma | `admin/prisma/schema.prisma` |
| 登录 | Auth.js（NextAuth）Credentials Provider，JWT 会话 | `admin/auth.ts` |
| 密码哈希 | `bcryptjs`，成本 12 | `admin/prisma/seed-admin.ts` |
| 测试 | Vitest | `admin/package.json` |
| 包管理 | npm | `admin/package-lock.json` |

**不引入**：Redis、对象存储、消息队列、GraphQL、tRPC。等到真需要时再单独立项，不在板块里顺手加。

## 二、日志与审计

### 2.1 原则

- 用户操作和系统状态变化要落**数据库专用表**，不能只打控制台。
- 日志用于审计和事后追查：谁、什么时候、从哪来、做了什么、结果如何。
- 密码、会话令牌、密钥、完整配置正文**不进日志**。
- 日志写失败不能静默：至少写服务端错误日志；业务写操作是否因此失败，按板块单独定。

### 2.2 审计表 `AuditLog`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | String | 是 | 主键，cuid |
| `userId` | String? | 否 | 操作人；登录失败或未登录时为空 |
| `action` | String | 是 | 动作名，见 2.3 |
| `campusSlug` | String? | 否 | 所属校园 |
| `path` | String? | 否 | 相关文件相对路径 |
| `beforeHash` | String? | 否 | 改前内容哈希 |
| `afterHash` | String? | 否 | 改后内容哈希 |
| `detail` | String? | 否 | 补充说明；不写敏感内容 |
| `ip` | String? | 否 | 取 `x-forwarded-for` 第一段 |
| `userAgent` | String? | 否 | 浏览器标识 |
| `createdAt` | DateTime | 是 | 操作时间，默认当前 |

索引：`campusSlug + createdAt`、`action + createdAt`。

### 2.3 动作名

固定用下面这些，不临时造新词：

`login`、`logout`、`create-campus`、`save-draft`、`validate`、`preview`、`publish`、`rollback`。

`logout` 由 BG-01 实现（D-008）；其余动作随对应板块落地。

后续板块新增动作时，先在这张表里登记，再写代码。

### 2.4 现状与重做口径

- 现状（A0，只作参考）：登录成功/失败都写 `login`，`detail` 为 `success` / `failed`；登录日志写失败被吞掉（`admin/auth.ts` 的 `.catch(() => undefined)`）。
- 现状（A0）：其他写操作调用 `audit()`，失败会让请求报错。
- 重做口径（已定）：登出写 `logout`（D-008）；登录/登出审计失败不阻断，但必须打服务端错误日志；业务写操作审计失败则操作失败；保留至少 180 天，支持 CSV 导出（D-007）；自动清理后置。

## 三、错误处理

所有后台接口统一返回：

```json
{ "ok": true, "data": {} }
{ "ok": false, "error": { "code": "VALIDATION_FAILED", "message": "...", "details": [] } }
```

规矩：

- 客户端只看 `ok` 和 `error.code`；`message` 是给人看的中文说明。
- 不把堆栈、SQL、文件绝对路径返回给浏览器。
- `details` 只放定位信息，例如字段路径、冲突文件的哈希。
- 未登录一律 `401 UNAUTHORIZED`；跨站写请求一律 `403 CSRF_REJECTED`。

错误码全集和含义见 [`00-平台契约.md`](00-平台契约.md)。

## 四、配置与环境变量

| 变量 | 必填 | 用途 |
|---|---|---|
| `AUTH_SECRET` | 是 | Auth.js 会话签名，至少 32 位随机字符串 |
| `CONFIG_ROOT` | 是 | 已发布配置根，游戏线上读这里 |
| `ADMIN_DATA_ROOT` | 是 | 草稿、快照、锁、数据库所在根 |
| `GAME_ORIGIN` | 是 | 预览链接指向的游戏地址 |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | 首次初始化 | 首个管理员；密码至少 12 位 |
| `ADMIN_DB` | 否 | 数据库文件路径 |
| `DATABASE_URL` | 是 | Prisma 连接串 |
| `PUBLISH_ROOT` | 否 | 发布目标目录，配置后发布时同步一份 |
| `MAX_JSON_BYTES` | 否 | 单份 JSON 大小上限，默认 2 MB |
| `LOCK_STALE_MS` | 否 | 锁超过多久算陈旧，默认 10 分钟 |
| `KEEP_REVISIONS` | 否 | 历史版本保留数量 |

规矩：

- `.env*` 不进仓库，只提交 `.env.example`。
- 相对路径以 `admin/` 为基准。
- 生产必须 HTTPS；会话 Cookie 设 `httpOnly`、`sameSite=lax`、`secure`。

## 五、代码与测试约定

- 类型检查：`npm run typecheck`（`tsc --noEmit`）。
- 测试：`npm run test`（Vitest）。
- 构建：`npm run build`（先 `prisma generate`）。
- 测试必须用临时目录和临时数据库，不得读写真实的 `config/` 或 `admin-data/`。
- 一个板块开工前，先在本文件登记它用到的技术标准；不临时改技术栈。

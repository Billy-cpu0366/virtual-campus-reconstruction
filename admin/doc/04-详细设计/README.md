# 04-详细设计

> 本阶段把每个页面拆到"照着就能写代码"：元素、字段、状态、事件、样式、异常。

## 一、输入

上一阶段确认过的页面清单、API 清单和数据模型。

## 二、做法

1. **一个页面一节**，写清：
   - 布局和元素（每个元素叫什么、放哪、干什么）；
   - 调用的 API；
   - 显示的字段和格式；
   - 状态：加载中、空、出错、无权限、成功；
   - 交互事件：点击、提交、刷新、离开页面；
   - 样式约定：用哪套间距、颜色、按钮、表格。
2. **事件单独列表**：事件 ID、触发条件、前置状态、后续动作、失败怎么处理。
3. **数据库字段明细**：类型、必填、默认值、长度/范围、索引。
4. **同类元素抽模板**：基础组件是模板，页面里的具体呈现是实例；写清模板管什么、实例能改什么。不在每个页面重复定义。
5. **异常和边界**：网络失败、会话过期、并发修改、数据为空、权限不足。
6. 不写实现代码，但写清到"变量叫什么、字段从哪来"的程度。

## 三、交付物

每个板块一份 `BG-xx-名称.md`，包含：

- 页面逐页设计
- 事件总表
- 数据库字段明细
- 组件模板与实例
- 状态与异常处理
- 样式约定

## 四、算完成的标志

- 每个页面都有元素、状态、事件、API、字段；
- 每个事件都有触发、动作、失败处理；
- 字段类型、必填、默认值写全；
- 同类元素没有在页面里重复定义；
- 异常路径有明确文案和去向。

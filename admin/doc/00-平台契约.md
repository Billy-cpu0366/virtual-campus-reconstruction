# 平台契约

> 跨板块共用的约定。板块设计只引用这里，不复制一份；要改先改这里，再改所有引用方。

## 一、系统边界

```text
浏览器
├── 游戏静态站
│     └── 只读 /config/<集名>/*.json，运行时 fetch
│
└── 管理后台（admin/，独立 Next.js 应用）
      ├── 读 config/骨架 的 Spec / loader，校验规则只有一份
      ├── 草稿目录 → 预览集 → 发布到 config/<校园>
      └── SQLite：账号、校园元数据、版本索引、审计
```

三条硬原则：

1. **配置文件是配置值的唯一真相。** 数据库不存配置正文。
2. **校验只有一份。** 复用 `config/骨架` 里的 `Spec`、`validate()`、各系统 loader，不另写规则。
3. **发布是整批原子替换。** 40 份文件同时加载，缺一份游戏起不来；发布必须全量校验 + 快照 + 整批替换。

**游戏运行时不依赖后台。** 游戏只读静态 JSON，后台停掉不影响线上。

## 二、接口返回格式

```json
{ "ok": true, "data": {} }
{ "ok": false, "error": { "code": "VALIDATION_FAILED", "message": "给人看的中文说明", "details": [] } }
```

- HTTP 状态码按语义用：成功 200/201，客户端错误 400/401/403/404/409/422，服务端错误 500。
- `details` 可选；只放定位信息，不放堆栈和绝对路径。

## 三、错误码

| 错误码 | HTTP | 含义 |
|---|---|---|
| `UNAUTHORIZED` | 401 | 未登录或会话失效（含账号已停用） |
| `INVALID_CREDENTIALS` | 401 | 登录失败；账号不存在、密码错、停用、限流锁定统一用它，不暴露具体原因 |
| `CSRF_REJECTED` | 403 | 写请求来源不同源 |
| `READ_ONLY` | 403 | 试图修改只读对象（如 `default`） |
| `INVALID_BODY` | 400 | 请求正文不是合法 JSON 对象或缺少必填字段 |
| `INVALID_PATH` | 400 | 路径不合法（非法集名、非 JSON、越界、符号链接） |
| `INVALID_CAMPUS` | 400 | 校园集名或显示名无效 |
| `NOT_FOUND` | 404 | 资源或接口不存在 |
| `REVISION_NOT_FOUND` | 404 | 找不到指定历史版本 |
| `ALREADY_EXISTS` | 409 | 同名校园或草稿已存在 |
| `STALE_WRITE` | 409 | 保存时文件已被别人改过（**规格要求，当前代码未实现**） |
| `PARTIAL_PUBLISH` | 409 | 源目录已更新、发布目标未更新（建议值；当前代码按 400 返回，待统一） |
| `VALIDATION_FAILED` | 422 | 信封、字段或语义校验失败 |
| `REQUEST_FAILED` | 400/500 | 其余未分类错误 |

新增错误码先登记到这张表，再写代码。

## 四、认证、会话与 CSRF

- 登录：邮箱 + 密码，Auth.js Credentials Provider；账号不存在、密码错误、账号停用对外表现一致。
- 会话：JWT，有效期 12 小时，不做"记住我"（D-004）；Cookie 设 `httpOnly`、`sameSite=lax`，生产加 `secure`。
- 停用：每次读会话查一次 `AdminUser.active`，为 false 立即失效（D-005）。
- 限流：同一邮箱 + IP，15 分钟内失败 5 次锁 15 分钟；单实例内存计数（D-003）。
- 页面保护：`/admin/:path*` 未登录跳 `/login`。
- 接口保护：所有 `/api/admin/*` 先查会话，未登录返回 401。
- 写接口（POST/PUT/PATCH/DELETE）必须校验 `Origin` 与 `Host` 同源，不一致返回 403。
- 密码重置：命令行脚本，至少 12 位；页面找回后置（D-006）。

## 五、权限位

- `AdminUser.role` 是字符串，现在预留三个值：`admin`、`editor`、`viewer`。
- 当前所有账号都是 `admin`，只区分"已登录 / 未登录"。
- 按校园分权、编辑与发布分离、审批流，统一放到 BG-07 权限与运营，其他板块不自己造权限判断。

## 六、审计动作

统一动作名：`login`、`logout`、`create-campus`、`save-draft`、`validate`、`preview`、`publish`、`rollback`。

规矩：

- 登录成功和失败都要记。
- 登出也要记（D-008）。
- 每个写操作都要记；只读查询不记。
- 记录操作人、动作、校园、文件、前后哈希、IP、User-Agent、时间。
- 密码、令牌、密钥、完整配置正文不进日志。
- 审计保留至少 180 天，支持 CSV 导出（D-007）；自动清理后置。
- 登录/登出审计写失败不阻断登录退出，但必须打服务端错误日志；业务写操作审计失败则操作失败。

字段明细见 [`00-技术约定与日志.md`](00-技术约定与日志.md)。

## 七、发布状态机

```text
草稿（draft）
  ├── 整套校验通过 → 预览（_preview-<校园>，游戏可打开）
  ├── 预览不改变线上
  └── 发布（publish）
        ├── 快照当前已发布内容
        ├── 整批原子替换
        └── 写 Revision + AuditLog
              └── 回滚（rollback）→ 再走一遍"快照 + 替换"
```

规矩：

- 发布前必须整套校验通过。
- `default` 永远只读，可以看、可以复制成新校园，不能保存、不能发布覆盖。
- 同一校园发布/回滚时持有校园锁；锁超过 10 分钟视为陈旧，可清理并记录。
- 发布目标同步失败要返回 `PARTIAL_PUBLISH`，不能报告"发布成功"。

## 八、路径与集名

- 集名白名单：`^[a-z0-9_-]{1,64}$`，直接复用 `config/骨架/公共/config-location.ts`。
- 所有路径先 `path.resolve()`，再确认结果在目标根目录内；拒绝 `..`、绝对路径、空段。
- 写入前 `lstat` 目标；符号链接一律拒绝。
- URL 里的中文目录名逐段 `encodeURIComponent` / `decodeURIComponent`，不要整条路径一次性编码。

## 九、数据归属

| 数据 | 存哪 | 谁能看 |
|---|---|---|
| 配置正文 | 磁盘 `config/<校园>/`、草稿目录、快照目录 | 已发布内容公开；草稿和快照要登录 |
| 账号、密码哈希 | SQLite | 登录用户；密码明文任何人看不到 |
| 校园元数据 | SQLite | 登录用户 |
| 版本索引 | SQLite | 登录用户 |
| 审计记录 | SQLite | 登录用户 |

已发布的配置 JSON 本来就是公开静态文件，**不要在里面写密钥、内部备注或未公开内容**。

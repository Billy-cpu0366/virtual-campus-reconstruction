# 05-测试设计

> 本阶段把每个"事件"变成能自动重跑的用例。测试不是写完代码再补，而是设计阶段就定好。

## 一、输入

上一阶段的事件总表、页面设计和 API 清单。

## 二、什么是事件

事件 = 用户做了一个动作，或系统状态发生了变化。例如：

- 用户提交登录、点登出、打开某个页面；
- 用户保存草稿、点发布、点回滚；
- 系统校验失败、发现文件冲突、会话过期；
- 后台任务完成、外部同步失败。

每个事件都要写清：**谁触发 → 前置状态 → 发生什么 → 系统做什么 → 失败怎么办**。

## 三、做法

1. 从详细设计的事件总表抄事件，一条不漏。
2. 每个事件至少一条自动化用例；重要事件补正常、失败、边界三条。
3. 用例写清前置条件、操作步骤、预期结果、测试级别（单元 / 接口 / 页面）。
4. 标出脚本放哪、现在有没有覆盖；没覆盖的写"待补"，不假装测过。
5. 关键流程配一张流程图，看清分支和失败去向。
6. 测试数据用临时目录、临时数据库；不读写真实 `config/` 和 `admin-data/`。
7. 命令必须能一键重跑。

## 四、交付物

每个板块一份 `BG-xx-名称.md`，包含：

- 测试范围和级别
- 事件 → 用例对照表
- 现有测试盘点（已有 / 缺口）
- 测试数据准备方式
- 关键流程图
- 脚本位置
- 一键命令和通过标准

## 五、算完成的标志

- 详细设计里的每个事件都有对应用例；
- 正常、失败、边界都有覆盖，或写清为什么不做；
- 每条用例能独立重跑；
- 现有测试和缺口分开写，不用"应该没问题"代替结果。

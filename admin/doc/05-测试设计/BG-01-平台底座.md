## 一、测试范围与级别

| 级别 | 测什么 | 工具 | 现状 |
|---|---|---|---|
| 单元 | 邮箱归一化、密码比对、同源判断、审计写入分支 | Vitest | 只有同源判断有测试 |
| 接口 | 审计查询、401、CSRF、分页筛选 | Vitest + 临时 SQLite | 只有 401 和 CSRF 有测试 |
| 页面 | 登录表单状态、审计表格空态/错误态、设置页脱敏 | 人工验收（第一圈） | 没有浏览器自动化 |
| 端到端 | 登录 → 查审计 → 退出 | 人工验收 | 没有 |

第一圈不引入 Playwright。页面级先用人工验收清单，接口和逻辑必须有自动化。

## 四、测试数据

- 每个测试文件用临时目录 + 临时 SQLite 文件，不碰真实 `admin/admin-data/`。
- 推荐做法：Vitest `globalSetup` 建一个带表结构的模板库；每个用例复制一份，用完删除。
- 种子数据：
  - `active@example.com`，`active=true`，密码 `correct-password-123`；
  - `inactive@example.com`，`active=false`，同样密码；
  - 3 条不同动作、不同校园的审计记录，用于筛选和分页。
- 密码哈希在测试里用 `bcryptjs.hash` 现场生成，不写死哈希。
- 审计时间用固定时间写入，避免翻页断言受当前时间影响。

## 五、流程图

### 5.1 登录

```text
打开 /login
  → 填邮箱/密码
  → 提交
      ├── 空字段 → 浏览器拦住
      └── 有值 → 邮箱转小写
            → 查 AdminUser
                ├── 不存在 → failed 审计 → 统一错误
                ├── active=false → failed 审计 → 统一错误
                └── 存在 → bcrypt.compare
                      ├── 不匹配 → failed 审计 → 统一错误
                      └── 匹配 → success 审计 → 签发 JWT → /admin
```

### 5.2 会话检查

```text
请求 /admin/* 或 /api/admin/*
  ├── 页面 → proxy.ts
  │     ├── 有会话 → 继续
  │     └── 无会话 → 302 /login
  └── 接口 → requireSession()
        ├── 有会话 → 写操作再做同源校验
        └── 无会话 → 401 UNAUTHORIZED
```

### 5.3 审计查询

```text
打开 /admin/audit
  → 读 page=1, limit=25, campus=空, action=空
  → GET /api/admin/audit
      ├── 401 → 跳登录
      ├── 失败 → 错误态 + 重试
      └── 成功 → 渲染表格
            ├── 改校园 → page=1，重新请求
            ├── 改动作 → page=1，重新请求
            └── 翻页 → page±1，重新请求
```

## 六、脚本组织

```text
admin/__tests__/
  api-auth.test.ts              现有：401、CSRF；本轮扩展错误 Origin
  auth/
    credentials.test.ts         邮箱归一化、密码比对、停用账号、审计成功/失败
    session.test.ts             会话回调、停用后失效（Q5 后）
  audit/
    query.test.ts               分页、校园筛选、动作筛选、空结果、401
    write.test.ts               审计字段、失败分支
  helpers/
    db.ts                       临时库、迁移、种子、清理
    request.ts                  构造带 Origin/Host 的请求
```

配套：

- `admin/auth.ts` 把 `authorize` 里的凭据校验抽成 `verifyCredentials(email, password)`，放 `admin/lib/credentials.ts`，方便单元测试；`authorize` 只负责调它和写会话。
- 审计写入也抽成可注入 prisma 的函数，测试里传假实现模拟失败。
- 第一圈不引入新测试框架，继续用 Vitest。

## 八、人工验收清单

自动化跑完后，人工走一遍：

- [ ] 正确账号密码登录，能看到 `/admin`。
- [ ] 错误密码、停用账号看到同一句提示。
- [ ] 清 Cookie 后访问 `/admin/audit` 跳登录页。
- [ ] 退出登录后回 `/login`，审计里有一条 `logout`。
- [ ] 审计页能按校园、动作筛选，能翻页。
- [ ] 审计页断网或接口失败时有错误提示和重试。
- [ ] 设置页看不到 `AUTH_SECRET` 和 `ADMIN_PASSWORD` 的值。
- [ ] 登录审计里能看到 IP 和 User-Agent。

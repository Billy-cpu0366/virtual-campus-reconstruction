# 03-概要设计

> 本阶段搭主体框架：有哪些页面、前后端怎么分、接口长什么样、数据存哪。**不碰页面里的按钮和字段细节。**

## 一、输入

上一阶段确认过的需求分析。

## 二、做法

1. 画系统边界：浏览器、后台应用、数据库、配置文件各在哪，谁读谁。
2. 列**全部页面**：名称、用途、路径。页面清单不全，后面一定漏。
3. 划前后端边界：哪些由服务端渲染、哪些由接口提供数据、哪些是纯前端交互。
4. 列 **API 清单**：方法、路径、入参、出参、权限、是否写审计。
5. 设计数据模型：表、字段、主键、索引、唯一约束；对象属性和字段一一对应。
6. 说明和其他板块的接口：共用什么、依赖什么、谁调用谁。
7. 前后端解耦：前端依赖后端的每个功能都必须有接口定义，不靠口头约定。

## 三、交付物

每个板块一份 `BG-xx-名称.md`，包含：

- 系统边界图
- 页面清单（名称 / 用途 / 路径）
- 前后端边界
- API 清单
- 数据模型（表、字段、主键、索引）
- 与其他板块的接口
- 非功能要求（安全、性能、可运维）

## 四、算完成的标志

- 每个页面有明确路径和用途；
- 每个前端依赖的后端功能都有 API 定义；
- 每个写接口都写了权限和审计；
- 数据模型能对上需求里的每个名词；
- 没有把页面元素、样式、状态细节混进来（那是下一阶段）。

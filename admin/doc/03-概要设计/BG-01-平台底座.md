## 一、系统边界

```text
浏览器
  │
  ├── /login ──────────────► Auth.js ──► AdminUser（SQLite）
  │                              │
  │                              └──────► AuditLog（登录成功/失败）
  │
  ├── /admin/* ──► proxy.ts 检查会话 ──► 后台页面（共用侧边栏）
  │                     │
  │                     └── 未登录 → 302 /login
  │
  └── /api/admin/* ──► requireSession() ──► 业务处理
                            │
                            ├── 未登录 → 401
                            ├── 写操作 → 同源校验 → 403 或继续
                            └── 写操作 → AuditLog

配置文件（磁盘）
  ├── CONFIG_ROOT/<校园>/        已发布，游戏读
  ├── ADMIN_DATA_ROOT/drafts/    草稿，游戏不读
  └── ADMIN_DATA_ROOT/revisions/ 历史快照
```

平台底座不直接读写配置文件；它只提供登录、会话、审计和设置页。配置读写由 BG-02～BG-04 负责。

## 二、页面清单

| 页面 | 路径 | 用途 | 属于 |
|---|---|---|---|
| 登录页 | `/login` | 邮箱密码登录，失败统一提示 | BG-01 |
| 总览 | `/admin` | 校园数、草稿数、发布记录数、最近操作 | BG-01（数据来自其他板块） |
| 操作审计 | `/admin/audit` | 审计列表、分页、按校园/动作筛选 | BG-01 |
| 系统设置 | `/admin/settings` | 只读展示环境配置，密钥隐藏 | BG-01 |
| 后台外壳 | `/admin` 布局 | 左侧导航、当前用户、退出登录 | BG-01 |
| 校园配置 | `/admin/campuses` 及子页 | 校园列表、文档树、编辑 | BG-02～BG-04 |

后台外壳从 BG-01 起提供；BG-02 以后往里加导航项，不另起一套布局。

## 三、前后端边界

| 功能 | 谁做 | 说明 |
|---|---|---|
| 登录表单 | 客户端组件 | 调 Auth.js 的 `signIn("credentials")`，不自己写登录接口 |
| 会话读取 | 服务端 | `auth()` 在页面、布局、接口里调用 |
| 页面保护 | 中间件 `proxy.ts` | 只匹配 `/admin/:path*`；接口自己在 handler 里查 |
| 登出 | 服务端 Action | 布局里的表单调 `signOut`，回 `/login` |
| 审计查询 | 服务端接口 + 客户端表格 | `GET /api/admin/audit` 返回 JSON，表格负责筛选和翻页 |
| 设置展示 | 服务端组件 | 直接读 `process.env`，不经过接口，避免把密钥送到浏览器 |

## 四、API 清单

| 方法 | 路径 | 作用 | 权限 | 审计 |
|---|---|---|---|---|
| GET/POST | `/api/auth/[...nextauth]` | Auth.js：会话、CSRF、登录、登出 | 公开（内部校验） | 登录成功/失败、登出 |
| GET | `/api/admin/audit` | 审计列表 | 已登录 | 不记（只读） |
| GET | `/api/admin/*`（其他板块） | 校园、配置、发布等 | 已登录 | 按板块定 |
| POST/PUT/PATCH/DELETE | `/api/admin/*`（其他板块） | 写操作 | 已登录 + 同源 | 必须记 |

`GET /api/admin/audit` 参数：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `page` | 整数 | 1 | 第几页，最小 1 |
| `limit` | 整数 | 25 | 每页条数，1～100 |
| `campus` | 字符串 | 空 | 按校园集名精确匹配 |
| `action` | 字符串 | 空 | 按动作名精确匹配 |

返回：

```json
{
  "ok": true,
  "data": {
    "items": [],
    "page": 1,
    "limit": 25,
    "total": 0
  }
}
```

## 五、数据模型

### 5.1 `AdminUser`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | String | 主键，cuid | 用户 ID |
| `email` | String | 唯一，必填 | 登录名，存小写 |
| `passwordHash` | String | 必填 | bcrypt 哈希，成本 12 |
| `role` | String | 默认 `admin` | 预留 `admin` / `editor` / `viewer` |
| `active` | Boolean | 默认 `true` | 停用后不能登录 |
| `createdAt` | DateTime | 默认当前 | 创建时间 |
| `updatedAt` | DateTime | 自动更新 | 更新时间 |

主键：`id`。唯一索引：`email`（登录查询用）。

### 5.2 `AuditLog`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | String | 主键，cuid | 记录 ID |
| `userId` | String? | 可空 | 操作人；未登录/失败登录为空 |
| `action` | String | 必填 | 动作名 |
| `campusSlug` | String? | 可空 | 校园 |
| `path` | String? | 可空 | 文件相对路径 |
| `beforeHash` | String? | 可空 | 改前哈希 |
| `afterHash` | String? | 可空 | 改后哈希 |
| `detail` | String? | 可空 | 摘要，不放敏感内容 |
| `ip` | String? | 可空 | `x-forwarded-for` 第一段 |
| `userAgent` | String? | 可空 | 浏览器标识 |
| `createdAt` | DateTime | 默认当前 | 时间 |

索引：`campusSlug + createdAt`、`action + createdAt`。

### 5.3 是否要加字段

如果 Q5 选"每次读会话查 `active`"，不需要改表。如果以后要"一键踢掉某账号所有会话"，再加 `tokenVersion`；本轮不加。

## 六、状态机

### 6.1 登录状态

```text
未登录
  ├── 打开 /admin/* → 跳到 /login
  └── 提交登录
        ├── 成功 → 已登录（JWT）
        └── 失败 → 未登录 + 错误提示
已登录
  ├── 点退出 → 未登录
  ├── JWT 过期 → 未登录
  └── 账号被停用（Q5 确认后）→ 未登录
```

### 6.2 审计列表状态

```text
进入页面 → 加载中
  ├── 有数据 → 显示表格 + 分页
  ├── 无数据 → "暂无记录"
  └── 请求失败 → 错误提示 + 重试
```

### 6.3 审计写入状态

```text
业务动作
  ├── 审计写成功 → 继续
  └── 审计写失败
        ├── 登录：不阻断登录，写服务端错误日志
        └── 业务写：操作失败，返回错误
```

## 七、权限与审计

- 本板块只判断"已登录 / 未登录"。
- `role` 随 JWT 和 session 传递，但不用来拦页面和接口；BG-07 再启用。
- 页面保护由 `proxy.ts` 统一做，避免每个页面自己写。
- 接口保护由 `requireSession()` 统一做，避免漏掉某个 handler。
- 写接口必须同时做同源校验和审计；两个都缺一不可。
- 动作名统一走 [`00-平台契约.md`](../00-平台契约.md) 的清单。

## 八、和其他板块的接口

| 板块 | 从平台底座拿什么 | 要给平台底座什么 |
|---|---|---|
| BG-02 校园管理 | 登录会话、统一返回格式、审计函数 | 校园相关动作的审计记录 |
| BG-03 配置编辑 | 同上 | 保存草稿的审计（含前后哈希） |
| BG-04 发布与版本 | 同上 | 发布、回滚的审计 |
| BG-05 素材管理 | 同上 | 上传、删除的审计 |
| BG-06 内容管理 | 同上 | 内容发布的审计 |

所有板块共用 `admin/app/admin/layout.tsx` 的侧边栏，只加导航项，不复制布局。

## 九、非功能要求

| 项 | 要求 |
|---|---|
| 安全 | 生产 HTTPS；Cookie `httpOnly`、`sameSite=lax`、`secure`；写操作同源校验；密码只存哈希 |
| 隐私 | 审计不含密码、令牌、密钥、完整配置正文；IP 和 User-Agent 只在登录用户可见 |
| 性能 | 审计查询分页，单页最多 100 条；按索引字段过滤 |
| 可用性 | 审计查询失败不能白屏；登录失败有明确提示；设置页只读 |
| 可运维 | 环境变量集中在 `.env`；设置页能看到当前根路径；初始化和管理员重置有脚本 |
| 兼容 | Node.js 22；Next.js App Router；SQLite 单实例 |

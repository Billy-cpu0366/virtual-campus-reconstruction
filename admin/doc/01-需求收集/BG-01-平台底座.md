## 一、这个板块管什么

后台所有板块共用的一层：

- 谁能进后台（登录、登出、会话保护）
- 进来的是谁、还能不能用（账号、停用、角色位）
- 进来以后干了什么（审计记录、审计查询、导出）
- 所有接口统一的返回格式和错误处理
- 只读的系统设置页
- 单实例下的登录限流和密码重置兜底

## 二、不管什么

- 校园列表、新建校园 → BG-02 校园管理
- 配置文档树、编辑、校验 → BG-03 配置编辑
- 预览、发布、回滚 → BG-04 发布与版本
- 账号新建、停用、改密页面 → BG-07 权限与运营（D-002）
- 多角色权限矩阵、审批流 → BG-07
- 游戏运行时的任何逻辑 → 不属于后台

## 七、A0 参考事实（只记录，不作为结论）

- 登录用 Auth.js Credentials Provider，JWT 会话；密码用 `bcryptjs` 比对。
- `authorize` 里检查 `user.active`，登录成功和失败都尝试写 `AuditLog`；写失败被 `.catch(() => undefined)` 吞掉。
- 页面保护在 `admin/proxy.ts`，只匹配 `/admin/:path*`；接口保护在每个 handler 里调 `requireSession()`。
- 写接口校验 `Origin` 与 `Host` 同源，不一致返回 `CSRF_REJECTED`。
- 审计查询接口是 `GET /api/admin/audit`，分页 25 条，可按校园和动作过滤。
- 设置页读取环境变量，`AUTH_SECRET` 和 `ADMIN_PASSWORD` 只显示"已设置（内容隐藏）"。
- 现有自动化测试只有 `admin/__tests__/api-auth.test.ts` 三条：未登录 401、跨站写被拒、同源写通过。

这些事实在重做时**可以推翻**，只用来对照"哪些坑踩过"。

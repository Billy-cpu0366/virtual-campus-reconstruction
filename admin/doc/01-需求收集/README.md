# 01-需求收集

> 本阶段只回答"谁、在什么场合、说了什么"，不写方案。

## 一、输入

- 会议录音和转写稿
- 合同、需求确认单、报价单
- 外部系统接入文档
- 定制需求版本（1.0 / 2.0 / 3.0）
- 思维导图、任务计划表
- 已有规格、已有代码的实际行为

原始件统一放 [`99-原始件/`](../99-原始件/README.md)。

## 二、做法

1. 每条需求给一个编号：`RQ-<板块ID>-<三位序号>`，例如 `RQ-BG01-001`。
2. 写清来源编号（`S01`、`S02`……）、提出人、日期。
3. **原话和我们的理解分开**：原话加引号；理解另起一行。
4. 每条需求标状态：
   - `已确认`：Human 明确说过；
   - `已实现待确认`：代码里已经有，但这次重做是否保留还没定；
   - `待确认`：还没问清楚；
   - `已否决`：明确不做，写清原因。
5. 没搞清的需求**不要猜**，单列到"待确认"。
6. 本阶段不写页面、不写接口、不写数据库——那是后面阶段的事。

## 三、交付物

每个板块一份 `BG-xx-名称.md`，包含：

- 这个板块管什么、不管什么
- 来源清单（编号、来源、位置、日期）
- 需求清单（编号、原话/需求、来源、状态）
- 本轮不做清单
- 待确认清单

## 四、算完成的标志

- 每条需求都有编号、来源、日期、状态；
- 原话和我们的理解没有混在一起；
- 待确认项单独列出，没有藏进正文；
- 没有把"怎么做"写进需求。

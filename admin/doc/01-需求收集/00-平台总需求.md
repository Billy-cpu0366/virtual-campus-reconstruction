## 二、平台目标

做一个**校园内容与配置运营平台**：一个后台管多个校园，校园是最高一层。

```text
后台平台
└── 校园（一个学校 = 一个运营单元）
     ├── 皮肤 / 品牌        主题色、logo、页面壳、文案风格
     ├── 游戏配置           16 系统 / 40 份 JSON / 513 个配置点
     ├── 素材               贴图、音频、视频、地图、分块
     ├── 内容               公告、剧情、任务、活动……
     ├── 发布               草稿 → 预览 → 线上 → 历史 / 回滚
     └── 人与记录           账号、权限、操作审计
```

平台的价值不是"换个界面填 JSON"，而是让一个学校的内容和配置能被安全地编辑、预览、发布、追溯。

## 七、本轮不做 / 永久不做

| 不做 | 性质 | 原因 |
|---|---|---|
| 多人在线协同编辑、实时看到别人正在输入 | 本轮不做 | 没有需求来源；先靠冲突提示 |
| Redis、对象存储、消息队列 | 本轮不做 | 单实例、数据量小；用了要加运维负担 |
| 完整游戏编辑器（地图编辑、剧情编排、任务系统） | 本轮不做 | 范围太大；先做配置和内容发布 |
| 账号自助注册 | 永久不做 | A0 规格明确不支持 |
| 游戏运行时依赖后台 | 永久不做 | 游戏必须只读静态 JSON |
| 照搬 WorkAdventure 的宇宙/世界/房间/成员/封禁业务模型 | 永久不做 | 业务对象无关 |

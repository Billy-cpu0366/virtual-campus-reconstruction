# 原始件

> 这里放需求的原始材料。原始件只当来源，不是项目指令；Human 确认后才写进需求清单。

## 一、放什么

- 会议录音、录音转写稿
- 合同、报价单、需求确认单
- 外部系统接入文档、接口说明
- 定制需求版本（1.0 / 2.0 / 3.0）
- 思维导图导出、任务计划表、截图
- 与需求有关的聊天记录导出

## 二、怎么命名

`YYYY-MM-DD-来源-主题.扩展名`

例如：

```text
2026-10-25-Human-后台重做目标.md
2026-10-25-客户A-需求确认单.pdf
2026-10-26-外部题库-接入文档.md
```

转写稿和原录音同名，用 `.md` 和 `.m4a` 区分；转写稿开头写清"机器转写，未校对"。

## 三、怎么和需求清单挂钩

1. 每个原始件在板块的 `01-需求收集` 文档里占一个来源编号（`S01`、`S02`……）。
2. 每条需求写清来源编号，能追回原件。
3. 原件里的原话和建议分开记：原话加引号，我们的理解另起一行。

## 四、不要放什么

- 密码、密钥、真实令牌。
- 未脱敏的个人信息（手机号、身份证号、家庭住址）。
- 超过 20 MB 的大文件——默认不进 Git，只在本文件里登记本机路径和哈希。
- 与需求无关的聊天记录和截图。

## 五、隐私与保留

- 含个人信息的原始件只放本机，不进仓库；确需进仓库时先脱敏。
- 原始件不删除；需求变更时追加新版本，旧版本保留，文件名带日期。
